# 契約とスクリプト方策

[04-model-design.md](04-model-design.md) で、全層をスクリプトで先に書き、その間の受け渡しをそのまま契約の定義とすると決めた。この文書がその定義である。

**ここに書かれた方策は実装済みである。** 実物は `rwintel/control/policy/` にあり、六層が層ごとのモジュール(`strategy.py` `operations.py` `tactics.py` `economy.py` `organisation.py` `logistics.py`)に分かれ、層の間の契約は `contracts.py` にある。種別を領域と機能で分類するのは `catalogue.py`、地形からどの領域へ何が行けるか、輸送がどこで積みどこで降ろすかを求めるのは `reach.py` である。戦略層と内政層が同じ尺度で拡張先を並べるための土地の読み方は `ground.py`、規則の切り替えは `options.py` にある。各層は自分の周期が来たときに走り、上位が置いた契約を読み、下位へ契約を置く。**互いを呼ばない。** これが四層を凍結して一層だけを差し替えられる条件であり、人間が指揮を引き取る継ぎ目そのものでもある。[乱入への頑健性](#乱入への頑健性)のスクリプト乱入者も実装済みで、`rwintel/control/intruder.py` が下表の頻度でそのまま干渉する。

数値には二種類ある。**構造として決まっているもの**(契約の項目、部隊管理の規則、行動の集合)と、**初期値にすぎないもの**(閾値、比率、周期)である。後者は表の中で初期値と明記した。前者を変えるには設計の見直しが要るが、後者は計測で調整する対象である。契約の粒度が議論ではなく計測で決まるようにするのが、スクリプトを先に書く目的の一つである。

## 契約の一覧

層の構成は [04-model-design.md](04-model-design.md) にある。ここでは受け渡しの中身を型と値域まで書き下す。

| 経路 | 周期 | 渡すもの |
| --- | --- | --- |
| 戦略から内政へ | 0.1Hz | 姿勢、資源配分比、技術投資の上限、軍備の目標構成、拡張の計画 |
| 戦略から作戦へ | 0.1Hz | 領域ごとの優先度、攻勢か守勢か、許容する総損害、拡張の計画 |
| 内政から編成へ | 事象 | 完成したユニットの引き渡し |
| 編成から作戦へ | 事象 | 部隊の一覧 |
| 作戦から戦術へ | 0.5Hz | タスク契約 |
| 戦術から作戦へ | 0.5Hz | 任務状況、接触した敵編成(役割ごとの価値と、そのうち飛ぶものの価値)、実損害、撃破した価値 |
| 作戦から編成へ | 0.5Hz | 戦力の過不足、消耗して任務に耐えない部隊 |
| 編成から内政へ | 事象 | 必要な補充の種別と量 |
| 作戦から移送へ | 0.5Hz | 運ぶ部隊、使う輸送の枠、降ろす領域 |
| 内政から移送へ | 0.5Hz | 運ぶ建設機と降ろす領域 |
| 移送から内政へ | 0.5Hz | どの輸送も応えられなかった要求と、その乗客の種別(輸送の不足) |
| 移送から作戦へ | 毎周期 | 輸送の枠ごとの輸送、位置、積載、何を運んでいるか |
| 全層から戦略へ | 0.1Hz | 戦線の状況と経済の推移、両軍の軍事価値、部隊が接触した敵編成 |

**拡張の計画**は、次に採掘施設を置いてよい領域を安全な順に並べた列である。内政層と作戦層が同じ列を受け取るので、軍が片付けている領域と建設機が向かう領域が食い違わない。人間が戦略層を引き取ったときに「ここへ広げろ」と言える場所でもある。列の作り方は[内政層](#内政層)にある。

## タスク契約

作戦層から戦術層へ渡す構造体である。潜在ベクトルではなく意味の固定された項目とする。

| 項目 | 型 | 値域 | 意味 |
| --- | --- | --- | --- |
| `squad` | `u16` | 部隊識別子 | 対象部隊 |
| `task_type` | `u8` | 6 種 | 攻撃 / 防衛 / 襲撃 / 後退 / 護衛 / 包囲 |
| `target_kind` | `u8` | 3 種 | 目標が領域か、部隊か、ユニットか |
| `target` | `u32` | | 領域スロット番号([05-interface.md](05-interface.md))、部隊識別子、ユニット ID |
| `stance` | `u8` | 7 種 | `game.units.a` へ直接写像する |
| `cost_budget` | `f32` | クレジット | この任務で失って構わない自軍価値 |
| `deadline` | `u32` | ゲーム内時刻(ミリ秒) | 完了を期待する時刻 |
| `issued_at` | `u32` | ゲーム内時刻(ミリ秒) | 実損害を切り出す起点 |

交戦スタンスの定数は順に `outOfRange`、`onlyInRange`、`returnFire`、`holdFire`、`guardArea`、`aggressive`、`mixed` である([../game/03-observation.md](../game/03-observation.md))。契約はこの値をそのまま持ち、戦術層は既定挙動としてこれをユニットへ設定する。作戦層がタスクから決めるスタンスは、攻撃・包囲・襲撃が `aggressive`、防衛・護衛が `guardArea`、後退が `returnFire` である。

### タスクごとの実行

ゲーム側は契約をタスクごとに違う命令で実行する([05-interface.md](05-interface.md) の契約の書き換え)。戦術層の逸脱 `hold` は、この実行へ戻ることを意味する。

| タスク | ゲーム側の実行 |
| --- | --- |
| 攻撃 | 目標へ攻撃移動 |
| 包囲 | 構成員を進入方向の左右で二手に分け、目標の両脇 250 の地点へそれぞれ攻撃移動。構成員が 1 体なら攻撃と同じ |
| 防衛 | 目標へ移動し、契約のスタンスで留まる。攻撃移動ではないので、途中の敵を追わない |
| 襲撃 | 目標から 600 以内の敵の採掘施設と建設機のうち最も近いものを攻撃し、倒れたら次へ移る。無ければ目標へ攻撃移動 |
| 後退 | 目標へ移動し、契約のスタンス(反撃のみ)で下がる |
| 護衛 | 目標のユニット、または目標の部隊のうちその部隊の目標に最も近い構成員を `guard` で守る。目標が領域なら、そこへ移動して留まる |

構成員のうち目標へ自力で行けないもの(地形の成分が違うもの)と、輸送に乗っているものには命令を出さない。

### `cost_budget` は絶対値で渡す

自軍総価値に対する比ではなく、**クレジットの絶対値**とする。理由は三つある。

**実損害と同じ単位で比べられる。** 部隊の現有価値も撃破された敵の価値も価格の総和であり([軍事価値](#軍事価値は価格の総和とする))、達成度の判定が引き算で済む。

**契約が任務の途中で意味を変えない。** 比で渡すと分母である自軍総価値が任務中に動く。序盤に「総価値の 20 パーセントまで」と渡した契約が、軍拡の途中で勝手に増額される。契約は発行時点で凍結されるべきである。

**人間が読める。** 介入 UI で書くのは「損害は 2000 まで」であって「総価値の 18 パーセントまで」ではない。

学習に渡す入力としての正規化は観測の側で行う。契約の `cost_budget` と併せて、それを自軍総価値で割った値も観測に載せる。**契約の意味と入力の尺度は別の問題である。**

### `deadline` は絶対時刻で渡す

残り時間ではなく到達すべきゲーム内時刻とする。1 周期の遅れ([05-interface.md](05-interface.md))があっても意味がずれない。

### 任務状況

戦術層から作戦層へ返す。

| 値 | 判定の初期値 |
| --- | --- |
| 進行中 | 下記のいずれにも当たらない |
| 膠着 | 30 秒のあいだ目標領域の勢力差が 10 パーセント以上動かない |
| 劣勢 | 実損害が `cost_budget` の 70 パーセントを超えた |
| 完了 | 目標領域に敵の可視戦力がなく、自軍の戦力が居座っている |
| 期限切れ | `deadline` を過ぎた |
| 届かない | 契約を受けた時点で、構成員の誰も目標へ自力で行けなかった。命令は何も出ていない |
| 移送待ち | 部隊を運ぶ移送の輸送が、まだ積む地点へ向かっている |
| 移送中 | 部隊が積み込まれているか、運ばれているか、降ろされている |

判定は移送待ちと移送中、届かない、目標の部隊やユニットが失われたこと(膠着として返す)、完了、期限切れ、劣勢、膠着の順に試し、最初に当たったものを返す。移送が続く間は移送が部隊を動かしているので、それ以外の状況は意味を持たない。

作戦層は、膠着・劣勢・完了・期限切れ・届かないを、部隊を別の任務へ回す理由として読み、移送待ちと移送中は任務を続けている状態として読む。届かない任務の領域は、膠着や劣勢と同じく次の答えの候補から外す。**ただし防衛と護衛の完了は任務を続けている状態として読む。** 守備部隊にとって、自分の領域に居座って誰にも争われていないことは任務の遂行そのものであり、それを完了として別の領域へ送ると、守備部隊は争われていない二つの領域の間を往復し続ける。

**契約を出した直後の 1 周期、ゲーム側はまだ前の契約について報告している。** 編成層は、報告の発行時刻が手元の契約より古ければ、その任務状況を進行中、実損害を 0 として読む。前の任務の膠着や完了が新しい契約に引き継がれないようにするためである。

## 部隊

部隊は名前と生存期間を持つ第一級の実体である([04-model-design.md](04-model-design.md))。その生存期間を管理するのが編成層であり、放置すると部隊が際限なく増える。

### 同時部隊数の上限は 8 とする

作戦層の行動空間を固定するためである。観測の部隊ブロックも 8 スロットである([05-interface.md](05-interface.md))。**上限は編成層が守る。** 上限に達しているとき、編成層は新しい部隊を作らず既存の部隊への増援に回す。

上限を 8 に置いた根拠は行動空間の側にある。作戦層の 1 回の決定は「どの部隊をどの領域へ」であり、8 部隊 x 24 領域 x 6 種別で 1152 通りである。0.5Hz で 20 分の試合なら 1 試合あたり約 600 回の決定であり、毎時数百の試合([03-throughput.md](03-throughput.md))から毎時数十万回の決定が集まる。この行動空間はその規模で扱える大きさである。

### 生成・増援・統合・解散

| 事象 | 規則 | 初期値 |
| --- | --- | --- |
| 生成 | 未配属ユニットがドクトリンの最小構成を満たし、かつ部隊数が上限未満 | 下記のドクトリン表 |
| 増援 | 未配属ユニットを、その役割を定数に持ち、ユニットと同じ領域で編成された部隊のうち「定数割れが最大」かつ「距離が近い」ものへ配属 | 定数割れを優先し、同率なら距離 |
| 輸送 | 配属先の部隊が遠いユニットは、同じ部隊へ向かうユニットが揃うまで未配属のまま待ち、揃ったらまとめて配属する。待ちすぎたら単独で送る | 距離 1500、3 体、30 秒 |
| 統合 | 現有価値が編成時価値の 40 パーセントを割り、かつ同じドクトリンで同じ領域の部隊が距離 1200 以内にいる | 40 パーセント、距離 1200 |
| 解散 | 所属ユニットが 0、または現有価値が編成時価値の 15 パーセント未満で統合先がない | 15 パーセント |

**遠い部隊への増援はまとめて送る。** 工場を出た 1 両が盤面の反対側の部隊へ単独で向かうと、途中で出会った敵に 1 両ずつ減らされる。待っている間のユニットは未配属のままなので、新しい部隊の編成に使われることもある。

**攻める部隊を先に揃える。** 増援は既存の部隊の定数割れを先に埋めるので、ユニットが 1、2 両ずつ届く試合では、最小構成の小さい守備隊(装甲 2)が先に立ち、届く装甲を受け取り続け、前衛の最小構成(装甲 4)がそろう前に部隊の上限まで守備隊で埋まる。軍全体が守備に立ち、攻める部隊が 1 つも無い試合になる。`vanguards` のとき、守備隊は `tuning.max_garrisons` までしか作らない。探索はこれを 1 に選んだ。守備隊が 1 つだけなら、拡張の先頭を守る規則([守備隊は拡張の先頭に立つ](#守備隊は拡張の先頭に立つ))を担うのもその 1 つである。また、前衛が受け入れるユニットは、部隊の枠が空いている限り、他の種類の部隊へ定数を超えて押し込まず、前衛を組める数がそろうまで未配属のまま待たせる。

**増援の配属は編成層が決め、作戦層は関与しない。** 作戦層が見るのは部隊の一覧と健全度だけであり、どのユニットがどこへ行くかは見ない。層の分担をこう切ると、作戦層の観測が部隊数に対して固定長で済む。

### ドクトリン

部隊の型である。スクリプト方策の初期値として 6 つ置く。

| ドクトリン | 最小構成 | 定数 | 編成する領域 | 主な任務 |
| --- | --- | --- | --- | --- |
| 前衛 | 装甲 4 | 装甲 8、砲 2 | 地上、水陸 | 攻撃、包囲 |
| 守備 | 装甲 2 | 装甲 4、対空 2 | 地上、水陸 | 防衛、護衛 |
| 襲撃 | 高速 3 | 高速 6 | 地上、水陸 | 襲撃、後退 |
| 工作 | 建設 1 | 建設 3 | すべて | 護衛の対象 |
| 艦隊 | 装甲 2 | 装甲 4、砲 2、対空 1 | 水上 | 攻撃、防衛、護衛 |
| 航空 | 装甲 2 | 装甲 6、対空 2 | 空 | 攻撃、襲撃、護衛 |

**部隊は一つの領域で編成し、同じ領域のユニットだけを受け入れる。** 構成員の誰もが他の構成員の行ける所へ行けるようにするためである。部隊の通行の区分(構成員の移動タイプのうち最も狭いもの)がこれで一つに決まり、どの領域へ歩いて行けるかが部隊ごとに答えられる。ドクトリンが複数の領域を持つときは、最小構成を満たす候補が最も多い領域で編成する。

**種別は、エンジンが見本ユニットから答えた能力だけで分類する**(`catalogue.py`)。名前は使わない。

| 軸 | 値 | 定義 |
| --- | --- | --- |
| 領域 | 地上 / 水陸 / 水上 / 空 / 静止 | 移動タイプから。LAND と OVER_CLIFF は地上、HOVER と OVER_CLIFF_WATER は水陸、WATER は水上、AIR は空、建物と動かないものは静止 |
| 機能(複数) | 戦闘 / 砲 / 対空 / 高速 / 輸送 / 建設 / 生産 / 偵察 / 建物 | 戦闘は攻撃でき(`canAttack`)動くもの、砲は射程 250 以上、対空は空だけを撃つ、高速は地上と水陸で速度 75 以上、輸送は容量が正、建設は建設者、生産はメニューに建物でないものがある、偵察は攻撃できず輸送でも建設者でもない動くもの |
| 役割 | 装甲 / 砲 / 対空 / 高速 / 建設 / 建物 / 輸送 / その他 | 部隊の定数と目標構成で数える一つの機能。建設、建物、攻撃できるものは対空、砲、高速、装甲の順、それ以外の輸送、の順に最初に当たったもの |

**武装しているかは射程で決めない。** 輸送と建設機は攻撃できないが射程を持つ([05-interface.md](05-interface.md) の種別表)。**輸送は部隊に入れない。** 戦えない輸送は移送の層が預かる([移送の層](#移送の層))。

**工場と司令部もメニューで決める。** 建設機のメニューにある建物のうち、メニューに戦える種別を持つものが工場であり、建設機が置かない建物のうちメニューに建設機を持つものが司令部である。**種別表は起動時に一度で完成する。実体を見るまで待つ必要はない。**

### 守備隊は拡張の先頭に立つ

工作部隊は作戦層の契約を受けない(建設機を動かすのは内政層である)ので、建設機を守るものは部隊の側に置く。**手の空いた守備隊を 1 つ、拡張の計画の先頭の領域へ防衛の契約で送る。** 手が空いているとは、契約を持たないか、自分の領域が誰にも争われず任務が完了しているということである。送るのは、その領域に自軍の戦力が立っておらず、どの部隊もそこを目標にしていないときだけであり、候補のうち最も近いものを選ぶ。どの守備隊が最も近いかは、部隊の行にある計画の先頭までの距離から読む。どの守備隊について決めるときにも答えが同じになるためである。採掘施設が立つと計画の先頭は次の領域へ移り、守備隊の領域は静かになるので、同じ守備隊が次の領域へ進む。拡張とともに守りが外へ動く。

学習した作戦層はこの規則を使わない。規則は作戦層の判断器の中にあり([作戦層の判断](#作戦層の判断))、学習した作戦層が差し替えるのはまさにその部分である。

### 作戦層の判断

**作戦層は、符号化した状態だけを読んで決める**(`rwintel/control/policy/judgement.py` の `OperationsJudge`)。学習した作戦層が読むのと同じ数字である([08-learning.md](08-learning.md) の観測の符号化)。スクリプトが生徒に見えないものを読んで決めると、生徒はその教師を途中までしか写せないからである。判断器は領域と計画(タスクと手段の組)のそれぞれに点を付け、最も高いものを選ぶ。

作戦層が部隊について決めるのは、契約が無いとき、任務状況が膠着・劣勢・完了(防衛と護衛を除く)・期限切れ・届かないになったとき、前に決めてから 30 秒たったとき、そしてその部隊について一度も決めたことが無いときである。それ以外の周期では部隊は持っている任務を続ける。移送待ちと移送中の部隊は、30 秒たっても決め直さない。途中で決め直すと、渡る途中で置き去りになるからである。膠着・劣勢・完了・届かないの任務の領域は、次の答えの候補から外す。

**部隊を送れる領域は、その部隊が行ける領域である。** 判断器には領域ごとに開いている計画のマスクを渡す。歩きが開くのは、乗っていない構成員の全員が領域の中心へ歩いて行ける領域であり、輸送の枠 k が開くのは、歩いて行けない領域のうち、その輸送が全員を積めて、積む地点と降ろし地点の両方へ行け、降ろされた全員がそこから中心へ歩いて行け、空いているか同じ部隊をそこへ運んでいる最中の領域である。中心へ歩いて行けるかは、ゲーム側が契約の目標へ行けるかを判定するのと同じ規則で答える(`reach.py`)。構成員の立つ地点の地形の成分と、中心の地形の成分(中心のタイルが通れなければ 3 タイル以内で最初に見つかる成分)が同じことである。中心が内陸にある領域は、沖の水が近くても艦隊には開かない。歩いて行ける領域へは運ばない。どの計画も開いていない領域は候補にならない。判断器は領域とタスクを選んだうえで、**手段**を次の規則で決める。歩いて行ければ歩く。行けなければ、その領域へ運べる輸送の枠のうち、すでにその部隊を運んでいる枠、無ければ部隊に最も近い輸送で運ぶ。運ぶ部隊は、契約を出したうえで移送の層に移送を頼む。契約の期限には運ばれる時間として 45 秒を足す。同じ周期に決める二つの部隊が同じ輸送を選ぶことはない。先に決めた部隊に渡した枠は、後の部隊のマスクで閉じる。続けている任務の手段も周期ごとに同じ規則で決め直す。渡り終えた部隊は歩いて任務を続け、一部だけが渡った部隊は、まだ歩いて行けない構成員をユニットの一覧として運ぶ。輸送の容量を超える部隊はこうして何便かに分かれて渡る。**戦略層の優先度が 0.5 以上の領域に、歩いても運ばれても行けない部隊があれば、移送の層に輸送の不足として伝える。** ただし、構成員の全員を積める輸送の型が目録に無い部隊(艦隊など)は伝えない。造っても運べない輸送を求めることになり、同じ周期に陸の部隊が求めた輸送まで造られなくなるからである。

| ドクトリン | 決め方 |
| --- | --- |
| 前衛 | `concentrate` のとき、争われている領域のうち、その部隊とそこへ向かっている部隊とそこに立つ自軍を合わせて戦闘表が勝てると予測する(結果が `tuning.attack_edge` 以上)ものから、優先度、行軍の遠さ、他の部隊がそこへ向かっている価値(重み `tuning.concentration`)、予測の結果(重み `tuning.predict_weight`)で選ぶ。予測が `tuning.encircle_edge` 以上なら包囲、それ以外は攻撃である。勝てる領域が無ければ、自軍の押さえた領域のうち、他の部隊が向かっていて自軍が立ち、前線に近いものに集結する |
| 守備 | 拡張の先頭を守る規則が当たらなければ、自軍の資源のある領域を、優先度、資源、敵の圧力、自軍の混み具合、行軍の遠さで選ぶ |
| 襲撃 | 押さえていない資源のある領域を、優先度、資源、敵の強さ、行軍の遠さで選ぶ。劣勢なら本拠地へ後退する |
| 艦隊、航空 | 行ける領域の中で前衛と同じ規則で選び、包囲はせず攻撃とする |

**艦隊と航空は、運んでいる輸送を護衛する。** 任務の進んでいない艦隊か航空の部隊は、護衛の付いていない、何かを運んでいる輸送のうち、輸送のいま立つ地点へ構成員の全員が行け、かつその輸送の降ろし地点から 30 タイル以内(上陸に使う到達の範囲)へ全員が行けて最も近いものへ、目標をその輸送のユニットとする護衛の契約を受ける。判定に使うのは領域の中心ではなく降ろし地点なので、中心が内陸にある領域へ渡る輸送も、艦隊は岸の沖まで水の上を護衛する(`Logistics.escortable`)。輸送が運び終えて何も運んでいなくなると、作戦層はその護衛を決め直す。輸送が沈めば、ゲーム側が目標が失われたとして膠着を返す。

**`concentrate` は戦力を集める。** 前衛は勝てると予測できる所だけを攻め、他の部隊が向かっている所へ引き寄せられ、どこでも勝てなければ前線の手前で集まって待つ。二乗則のもとでは、戦力は分けて使うほど弱い。切ると、前衛は争われている領域へ散らばる。

### 人間から指揮権が返るとき

**返却されたユニットは部隊を保持せず、全て未配属プールへ戻す。** そのうえで通常の増援配属規則を適用する。

人間が動かした結果は指揮系統にとって未知の状態であり、返却を「新しい部隊の受け入れ」と同じ扱いにするのが素直である([04-model-design.md](04-model-design.md))。元の部隊を復元しようとすると、構成も配置も変わった部隊に古い契約が適用され、契約の前提が崩れた状態から始まることになる。

返却直後の 1 作戦周期は、配属先の部隊に契約を出さずスタンス保持で待機させる。作戦層が新しい編成を見てから決める。

## 戦術の逸脱

戦術層の既定挙動は「割り当てられた目標へ、契約のスタンスで `attackMove`」である。学習するのはそこから逸脱すべき場面の判定と逸脱の内容だけである([04-model-design.md](04-model-design.md))。

**逸脱は部隊単位で 1 つ選ぶ。ユニット単位では選ばない。** 推論の回数が部隊数で決まり、ユニット数では決まらなくなる。

| 逸脱 | 内容 | 対応する局所要因 |
| --- | --- | --- |
| `hold` | 既定のまま。契約の目標へ `attackMove` を継続する | - |
| `withdraw` | 部隊を目標から離す向きへ歩幅 400 で後退させる | 交換比が悪い、`cost_budget` に近い |
| `withdraw_far` | 同じ向きへ、離脱の上限まで後退させる(完全に離脱する) | 劣勢が報告され、再配置でなく戦いから抜けるべき |
| `focus` | 全ユニットを射程内で最も体力の低い敵へ `attack` させる | 敵を 1 体ずつ減らす方が総火力の減りが速い |
| `focus_threat` | 全ユニットを射程内で最も射程の長い敵へ `attack` させる | 遠くまで届く砲を先に消す方が総被害を減らせる |
| `spread` | 重心から放射状に散開させる | 範囲攻撃 |
| `kite` | 射程の内側に入られないよう後退しながら攻撃する | 射程差 |

**基本の 5 つ**(`hold` `withdraw` `focus` `spread` `kite`)は、Rusted Warfare で局所的に効く要因が概ね「被弾」「範囲攻撃」「射程差」の三つであり、これに「集中」と「何もしない」を足した最小集合である。行動が増えるほど逸脱すべき場面の判定が難しくなるので、最小から始めている。**残りの 2 つ**(`withdraw_far` と `focus_threat`)は新しい種類の動きではなく、既にある `withdraw` と `focus` の、規則が決めていたパラメータ(どれだけ引くか、誰に集中するか)を層に渡したものである。行動空間の粗さが学習した層の天井を決めているかを確かめるために足したが、7 つに広げても学習した層は手書き層を上回らなかった([08-learning.md](08-learning.md))。

**戦術層も、符号化した交戦だけを読んで決める**(`judgement.TacticsJudge`)。規則の梯子は上から順に、任務の予算を使い切ったか交換で負けているなら後退、`predict` のとき戦闘表が交戦を負けと予測する(結果が `tuning.predict_withdraw` 以下)なら損害が出る前に後退(`tuning.predict_withdraw_far` 以下なら完全に離脱)、範囲攻撃に固まって撃たれているなら散開、射程で勝っているならカイト、撃てる構成員が 3 体以上いて敵が 2 体以上いて最短射程内に敵がいるなら集中、である。当てはまる段にはその順に点が付き、`hold` は 0 点、当てはまらない逸脱はそれより下の点になる。

`focus` の目標選択(射程内で最も体力が低い)と `withdraw` の後退先・歩幅(重心から契約の目標の逆向きに 400)は、その逸脱では規則で決めたままである。**足した 2 つは、その規則が決めていた 1 つのパラメータだけを、別の離散の逸脱として層に渡す。** `withdraw_far` は後退の歩幅を上限まで、`focus_threat` は目標を最も射程の長い在射程敵に取る。どちらも「逸脱の種類」として選ばれるので、**方策が選ぶのは逸脱の種類だけ**という形は変わらず、行動空間は種類の数(いま 7)のままで、方策は連続値を出さない。

### 後退する三つには境界がある

`withdraw`、`withdraw_far`、`kite` の三つが、部隊を目標から離す向きへ動かす。どれも出す命令は同じ形で、重心から契約の目標(領域の中心、部隊の重心、ユニットの位置)の逆向きへの移動である。輸送に乗っている構成員は動かさず、移送で運ばれている部隊にはどの逸脱も出さない。`withdraw` は歩幅 400 で、離脱の途中に振り返って撃たないようスタンスを撃ち方やめに落とす。`withdraw_far` は歩幅を後退の上限いっぱいに取る、すなわち一度で下がれるだけ下がる。`kite` は歩幅を「自軍の最短射程から、400 以内にいる敵の最長射程を引いた差」に取り、スタンスは契約のまま、すなわち**下がりながら撃つ**。その差が 0 以下なら射程で勝っていないということなので、`withdraw` と同じ動き(歩幅 400、撃ち方やめ)に落ちる。

**そして `hold` 以外の逸脱は、戦術周期ごとに出し直される**([05-interface.md](05-interface.md) の 5Hz、ゲーム内 200 ミリ秒)。出し直されるということは、1 回の後退が歩幅ぶんで終わらないということである。同じ逸脱が選ばれ続ける限り、部隊は毎周期その歩幅ずつ後ろへ送られる。したがって**後退する逸脱には、どこまでを後退と呼ぶかの境界が要る**。上限を一つ置いてあり、`withdraw_far` はその上限そのものを歩幅にする。

| 境界 | 値 | 内容 |
| --- | --- | --- |
| 接敵 | 900 | 重心から 900 以内に相手側のユニットが 1 体もいなければ、後退の命令を**一切出さない**。部隊は直前に受けた命令を続ける |
| 目標からの距離 | 1400 | 契約が名指した領域の中心から 1400 を超えて押し出さない。1 周期の歩幅も残りの余裕まで切り詰める |

**接敵の条件が要るのは、後退が敵に対して定義される動作だからである。** 近くに何もいない部隊にとって「離れる」に意味のある行き先はなく、それでも命令は出続ける。この条件が無いと、後退を命じられた部隊は誰もいない方向へ毎周期 400 ずつ歩き続け、盤面の外へ出ていく。交戦アリーナではそれが特に効き、終わった交戦の生き残りが盤全体に散らばって、次の交戦を組む場所が塞がる([08-learning.md](08-learning.md))。

**目標からの距離の上限は初期値である。** 接触を切ってなお歩いている部隊は、目の前の戦闘について何を命じられていたにせよ、もう契約を遂行していない。1400 はそれが明らかになる距離として置いた値であり、**敵が追ってくる場合にも歩きを止める**ためにある。

## 戦略層

学習させない層であり、人間に渡す価値が最も高い層である([04-model-design.md](04-model-design.md))。**出力は離散の姿勢とし、資源配分比は姿勢からの表引きとする。**

連続値の配分比を直接出す形は採らない。介入のしやすさを優先する。人間が触るのは「今は軍拡」であって「資源配分を 0.62 対 0.38 に」ではない。表現力が足りないと分かった時点で、姿勢に連続の修正子を足す形で拡張する。

| 姿勢 | 経済 | 軍備 | 技術 | 作戦の含意 |
| --- | --- | --- | --- | --- |
| 拡張 | 0.7 | 0.2 | 0.1 | 未占有の資源領域を優先、許容総損害は小さい |
| 技術 | 0.4 | 0.2 | 0.4 | 本拠地周辺を保持、交戦を避ける |
| 軍拡 | 0.3 | 0.6 | 0.1 | 前線を維持、決戦は避ける |
| 防衛 | 0.4 | 0.5 | 0.1 | 自軍が押さえた領域のみ、許容総損害は大きい |
| 決戦 | 0.1 | 0.8 | 0.1 | 敵拠点領域へ集中、許容総損害は無制限に近い |

比は内政層への予算配分であり、資金そのものの分割ではない。**内政層はこの比を、次に何を作るかの重み付けとして使う。**

姿勢の遷移もスクリプトで書く。規則は「拡張で始め、収入が頭打ちになったら軍拡、敵の拠点が 1 つ残ったら決戦、自軍の領域が奪われ続けるか自軍の軍が敵の軍よりはるかに小さければ防衛」である。技術は規則からは選ばれず、人間が固定したときにだけ選ばれる。

| 規則 | 内容 | 初期値 |
| --- | --- | --- |
| 頭打ち | 5 周期の窓で収入の伸びが最古の値の 5 パーセント未満。収入が 10 未満なら頭打ちと呼ばない | 窓 5 周期、5 パーセント |
| 劣勢の防衛 | 敵の軍事価値が下限以上あり、自軍の軍事価値がその一定倍未満 | 比 `tuning.yield_odds`、下限 1000 |
| 押し出し | 自軍の軍事価値が下限以上あり、敵の一定倍以上。姿勢は変えず、作戦層へ攻勢を指示する | 比 1.5(`push` のとき `tuning.push_odds`)、下限 1000 |
| 滞留 | 決戦と防衛以外への遷移は、直前の遷移から 30 秒たつまで保留する | 30 秒 |
| 軍拡からの復帰 | 軍拡から拡張へ戻るには、窓での伸びが 15 パーセント以上要る | 15 パーセント |
| 優勢での決戦 | `push` のとき、自軍の軍事価値が下限以上あり、敵の一定倍以上なら決戦に入る。それより低い保持の比を割るまで決戦を続ける | 比 `tuning.decide_odds`、保持 `tuning.decide_hold_odds` |

`tuning.` で始まる初期値は探索で選んだものであり、既定値は `rwintel/control/policy/tuning.py` にある([規則の切り替え](#規則の切り替え))。

**軍事価値の比は軍どうしで取る。** 両側とも建物と建設機を除いた価格の総和である。敵の司令部を敵の軍に数えると、開幕の自軍はつねに大差で負けていることになる。

**滞留と復帰の閾値は、姿勢の往復を止めるためにある。** 採掘施設の強化が 1 つ終わるだけで収入は窓の 5 パーセントを超えて伸び、頭打ちの判定が外れる。閾値が一つだけだと、姿勢はそのたびに軍拡と拡張を行き来し、攻勢か守勢かと許容総損害がそれにつれて切り替わる。

**拡張している姿勢は、拡張の計画の先頭の領域の優先度を 2 倍にする。** 建設機が次に向かう領域へ、軍が先に着くようにするためである。

**押し出しは姿勢ではなく攻勢の旗で表す。** 姿勢を 5 種のまま保つためである。押し出している軍拡は、前線に加えて敵の採掘施設のある領域にも優先度を付ける。先行している軍が差を広げるには敵の収入を削るのが早い。人間が姿勢を固定しているときは押し出さない。攻めるかどうかも人間の選択に含まれる。

**`push` は攻める時機を探索の選んだ比に置き換え、攻めを深くする。** 押し出しの比を `tuning.push_odds` にし、押し出している間の許容総損害を自軍の価値の `tuning.push_allowance_share` 倍まで広げ、大差が付いたら敵の拠点の数によらず決戦に入る。探索は押し出しの比を 1.5 より上に選んだので、既定では `push` は押し出しを早めず、押し出したときの許容総損害と、比による決戦だけを変える。「敵の拠点が 1 つ」の条件は、敵が拡張した後に押し戻されたことを言うためのもので、二人で戦う地図ではまず成立しない。先行している軍が待つ間に、まだ育っている敵の軍は追いついてくる。守る前線に合わせた許容総損害では、攻撃は着く前に劣勢として打ち切られる。決戦は、比が保持の比を割るまで続ける。小さな負けのたびに攻撃を取りやめないためである。

**部隊が接触した敵の編成で、軍備の目標構成を曲げる。** 全部隊の任務報告の接触を足し、そのうち空を飛ぶものの価値が 4 分の 1 以上を占めていれば、目標構成の 4 分の 1 を対空へ移す。任務報告は接触を役割ごとに載せるほかに、飛ぶものの価値を別に載せる。役割は領域をまたいで共有され(空の装甲も地上の装甲も装甲である)、対空は飛ばないものを撃てないので、役割の割合で判定すると飛ばない敵に対空で答え、役に立たない軍を作る。

**地上の軍が行けない領域は、計画にも優先度にも入れない。** 地形が届いた後、本拠地から地上か水陸の移動タイプで自力で行ける領域と、種別表にある輸送の種類のどれかが本拠地から行けて降ろせる領域を一度だけ求める。それ以外の領域は優先度 0 とし、拡張の計画から外す。

## 内政層

ビルドオーダである。姿勢の配分比を重みとして、次に作るものを選ぶ。下の表は判断器が段として持つ規則であり、候補の列挙と実行の分け方は [内政層の判断](#内政層の判断) にある。

開始条件は試合設定で決まる。既定の開始クレジットは 4000 である([../game/05-match-control.md](../game/05-match-control.md))。**部屋の開始ユニット数には効果がない。** 本プロジェクトの開始手順が `config.g` へ何を書き込んでも、出撃地点を持つプレイヤーは司令部 1 と建設機 1 で始まる。内政層が最初の周期で手元に見るのはこの二つであり、設定で増減させることはできない。

| 順序 | 作るもの | 条件 |
| --- | --- | --- |
| 1 | `extractor` | 本拠地領域の資源地点のうち未占有のもの。敵が立っている領域を後回しにし、そのうえで安全な順 |
| 2 | 基幹の工場 | 採掘施設が 2 基以上。基幹の工場は、工場のうち第 1 段階のメニューに地上の戦える種別を持つ最も安いもの(既定のユニットでは `landFactory`) |
| 3 | 工場のメニューのうち、敵の編成に対してクレジットあたり最も強い種別 | 工場が空いていて、軍備の配分比が閾値を超えている |
| 4 | `extractor` | 戦略層の拡張の計画にある領域の資源地点。順序は 1 と同じ |
| 5 | `builder` | 建設機が目標数未満、かつ拡張の配分比が閾値を超えている |
| 6 | `turret` | 敵と接触した領域の境界。軍備の配分比が閾値を超えている |
| 7 | 2 基目の工場 | 収入が `tuning.second_factory_income` を超えている |
| - | 3 基目以降の工場(`tuning.max_factories` 基まで) | 手元のクレジットが `tuning.banked_credits` を超えて溜まっている |

### 内政層の判断

**内政層は、いま取れる投資を並べ、次に何を取るかを 1 つずつ決める**(`rwintel/control/policy/economy.py`)。1 周期のあいだ、候補を列挙し、判断器が次の 1 つを選び、それを実行し、また列挙する。判断器が「止める」を選ぶと、その周期は終わる。候補は次の 7 種で、行動空間は固定の 32 スロットに並ぶ。

| 候補 | スロット | 何を指すか | 規則が決めること |
| --- | --- | --- | --- |
| 止める | 1 | 残りのクレジットを次の周期へ回す | - |
| 生産 | 16 | 空いた工場のメニューにある種別 1 つ | 作らせる工場(その種別を出す最初の空いた工場) |
| 建設機 | 1 | 建設機 1 体 | 注文先(司令部、なければ工場) |
| 採掘施設 | 6 | 本拠地か拡張の計画にある領域 1 つ | 地点(領域の中で最も安全なもの)と、置く建設機。行ける建設機がいなければ、建設機を運ぶ移送 |
| 工場 | 4 | 工場の種類 1 つ | 置く建設機と置き場所 |
| 強化 | 3 | 採掘施設の第 2 段階、工場、採掘施設の第 3 段階 | 強化する建物(本拠地に近い順) |
| 砲台 | 1 | 敵と接触した領域の境界 | 置く建設機と置き場所 |

**選ぶのは判断器であり、判断器は符号化した状態だけを読む**(`judgement.EconomyJudge`、符号化は [08-learning.md](08-learning.md) の内政の切り出し)。表の順序は、判断器の点の高さとして書いてある。上の段ほど点が高く、同じ段の中の並びは段と段の差より小さい点で付ける。止めるは 0 点で、どの段のゲートも通らない候補はそれより低い点になる。段は上から、工場を失った後の建て直し(`recovery`)、本拠地の採掘施設、最初の工場、建設機、輸送(輸送の不足があり工場が立っているとき)、拡張の計画の採掘施設と建設機が現地で待つ採掘施設の貯金(`expand_first`)、強化、2 基目の工場、軍備、手元が溜まったときの工場、計画の残りの採掘施設、砲台である。建設機・工場・強化・砲台は、1 周期に 1 つまでである。

**今払えない候補を選ぶことが、それを貯めて待つことを意味する。** その価格はその周期のうちに後から選ぶすべてのものから差し引かれ、その候補は次の周期まで出てこない。生産の候補なら、作らせるはずだった工場はその周期は何も作らずに待つ。スクリプトが待つのは、強化、2 基目の工場、そして払えるもので間に合わせるより待つ方がよい種別の三つである。候補の列挙は払えない候補も出すので、学習した内政層は何を貯めて待つかも選べる。

**学習した内政層が差し替えるのは、判断器の答えだけである。** 列挙と実行は同じコードが動く。

**拡張の計画は、押さえた土地から外へ伸びる。** 計画に入る領域は、誰も採掘施設を置いていない資源地点があり、敵が根を下ろしておらず(敵の採掘施設が無く、立っている敵の価値が建設機を送り込める程度に収まっている)、中心が本拠地か自軍の採掘施設のある領域から 1600 以内にあるものである。採掘施設を 1 つ置くたびに、その先の領域が届く範囲に入る。本拠地からの距離だけで区切ると、経済は本拠地の周りの円を取り尽くしたところで止まり、戦略層はそれを収入の頭打ちと読んで軍拡へ移る。並び順は採掘施設の安全な順(下記)と同じ尺度であり、内政層も作戦層も同じ順で読む。

**拡張の計画の採掘施設は、強化と軍備より先に置く。** 表の順序 4 は、実際には順序 3 の前で決まる。軍備は空いている工場をすべて使い、クレジットを入ってくる端から使うので、その後ろに置いた拡張には 700 が残らない。建設機は空いた資源地点の横で手を空けたまま待ち、その地点が生むはずの収入は入らない。建設機の数と地点の数で上限があるので、この順序で軍備が止まることはない。

**2 基目の工場も、軍備より先に決める。** 表の順序 7 も、実際には順序 3 の前で決まる。拡張と同じ理由で、軍備の後ろに置いた工場には価格が残らない。今払えないときは、その価格を軍備の予算から差し引いて取り置く。設置の注文を出したら、立つまでの猶予の間は注文し直さない。立っていない工場は工場の数に数えないので、猶予が無いと同じ注文が毎周期繰り返される。

**立たなかった設置の地点は、2 回で諦める。** 設置の猶予が切れても誰も立っていない地点を失敗と数え、失敗が 2 回になった地点はその試合では候補から外す。一度建った地点が後で壊された場合は失敗に数えない。

**採掘施設の命令が建設機に届かなかったら、その地点はすぐに返す。** 命令はゲームが後のフレームで取り込むので、配置を命じた建設機は 5 秒の間、待ち行列が空でも空いていない扱いにする。それを過ぎても何も積まれておらず地点に何も立っていなければ、命令が届かなかったかエンジンに断られたので、建設機を空きに戻し、地点も猶予を待たずに候補へ戻して失敗を 1 回数える。試合の最初の周期の命令は届かないことがある。地点を猶予の間押さえたままにすると、空いた建設機は本拠地の地点を取れず、遠い地点へ回されてしまう。

**設置は、その地点へ行ける建設機にだけ任せる。** 陸と水陸の建設機は地形の成分が同じ地点へ、建設艇は自分が行ける水のうち地点から見本の射程(建設の届く距離)以内に水がある地点へ置ける([../game/04-actions.md](../game/04-actions.md) の届かない命令)。**行ける建設機がいない地点は、建設機を運べるときにだけ候補に出す。** その候補を選ぶと、何も置かずに、空いた建設機のうち降ろす領域に最も近いものを移送の層に運ばせる。運ぶだけでクレジットは使わないので、その候補の価格は 0 である。同じ領域へは 60 秒のあいだ二人目を送らない。運ばれている建設機には他の設置を任せない。降ろされた建設機は、その領域では行ける建設機になり、普通の候補として置く。運べる輸送が無ければ、その要求を輸送の不足として移送の層に残す。

**建設機が現地で待っている採掘施設は、貯金してでも置く。** 計画の領域に、そこへ置ける空いた建設機がすでに立っている採掘施設は、今払えなくても拡張の段で選び、価格を取り置く。運んだ建設機が収入の届かない島で立ち尽くし、その間に軍備がクレジットを使い切ることを防ぐ。

**輸送は、不足があるときにだけ作る。** 移送の層が、どの輸送も応えられなかった要求(建設機の移送と、作戦層が報告した部隊)の乗客の種別を報告していて、立っている輸送と注文中の輸送が輸送の枠の数(4)に満たないとき、空いた工場のメニューにある輸送のうち、その乗客をすべて積めるものを候補に出す。注文した輸送は 45 秒のあいだ到着待ちとして数える。

**艦船は水上の戦いがあるときにだけ作る。** 試合の中で一度でも敵の艦船を見たら、それ以降である。それまでは工場のメニューに艦船があっても戦える種別として扱わない。艦船は陸の奥の戦いに届かないからである。

**工場の置き場所は、置くたびに変える。** 工場は建設機の脇に置くが、その場所が建てられない地形なら注文は何も生まない。毎回同じ場所を選ぶと、最初の工場が試合の終わりまで立たないことがある。置くたびに黄金角だけ向きを回し、6 回ごとに少し遠くへ出す。

**建設機の目標数は、計画の上の空き地点で増える。** 基本は 2 体で、計画の領域にある誰も向かっていない資源地点 3 つごとに 1 体を足し、5 体を上限とする。建設機が 2 体で固定だと、広い地図では採掘施設を置く速さが建設機の歩く速さで決まる。

**建設機の補充は軍備より先に行う。** 軍備の生産は空いている工場をすべて使うので、その後ろに置いた補充は実行されない。建設機がいなくなった経済は、拡張も、失った工場の建て直しもできない。建設機が目標数に満たないとき、建設機を 1 周期 1 体ずつ注文する。注文先はまず司令部で、司令部が手一杯なら工場である。司令部を先にするのは工場を軍備に残すためであり、最初の工場が立つ前に建設機が倒されたとき、建設機を作れるのは司令部しか無いからでもある。工場からしか補充しない経済は、開幕に唯一の建設機を失うとそこで止まる。注文する種別は、その建物が作れるもののうち最も安い建設機である。役割表で建設機に当たる最も安い種別は、シナリオの生き物のように、ここにあるどの建物も作らないものであることがある。注文した建設機は 45 秒のあいだ到着待ちとして数え、同じ不足に対して毎周期注文し直さない。建設機が 1 体もいないときは、経済の配分比によらず補充する。

**手元のクレジットが溜まっていれば、工場を増やす。** 溜まるのは生産が収入に追いつかないときであり、生産を増やすのは工場だけである。

**建物の段階を上げる強化は、軍備の生産より先に決める。** 順序は、採掘施設の第 2 段階、工場の第 2 段階、採掘施設の第 3 段階である。収入を増やす強化が先に来るのは、後の買い物がすべてそこから払われるからである。強化するのは敵のいない領域の建物だけで、本拠地に近い順に 1 周期 1 つずつ行い、注文した建物には 60 秒のあいだ注文し直さない。

| 強化 | 条件 |
| --- | --- |
| 採掘施設の第 2 段階 | 敵のいない領域にある |
| 工場の第 2 段階 | 収入が閾値を超え、生産を続ける工場が他にある(またはユニット上限で生産が止まっている)。一度に 1 基 |
| 採掘施設の第 3 段階 | 敵のいない領域にある |

**強化はそのための貯金をする。** 生産はクレジットを入ってくる端から使うので、残りで買う強化は買われない。次の強化が今払えないときは、軍備の生産がその価格を手元に残す。ただし価格が `tuning.upgrade_saving` を超える強化と、自軍の軍事価値が敵より小さいときの採掘施設の第 3 段階は、貯金をせず余りでだけ買う。どちらも貯金の間に、すでに負けている軍備をさらに遅らせるからである。

**技術投資の上限は、方式によって毎分の積立として使う。** 積立を使う方式では、戦略層が渡す上限(クレジット毎分)がゲーム内時間に比例して技術の積立に貯まり、8000 を上限とする。上限の下に置いた強化は、積立がその価格に達するまで候補に上がらず、買ったら積立から差し引く。どの強化を上限の下に置くかは三通りある。

| 方式 | 上限の下に置く強化 |
| --- | --- |
| `factory`(既定) | 工場の段階。軍が作れる種別の段階を決めるのはこれである。採掘施設の強化は収入への投資として内政が払う |
| `all` | すべての強化 |
| `off` | どれも置かない。上限は 0 のときに第 2 段階以上の種別を禁じるだけになる |

上限は戦略層の配分比の技術の値と収入の積であり、技術以外の姿勢では収入の 1 割、技術の姿勢ではその 4 倍にあたる。**既定は工場の段階だけを上限の下に置く。** 人間が戦略層を引き取って技術を選んだとき、工場の段階が実際に速く上がるのはこの方式だけである。`factory` と `off` の試合の採点の差は、測って区別できるほど大きくない。**採掘施設の強化まで上限の下に置く `all` は、採点をはっきり下げる。** 採掘施設の強化は後の買い物をすべて払う収入そのものであり、積立を待つ間その収入が入らない。

**工場が作る種別の段階は、工場の段階で決まる。** 工場のメニューは工場の段階とともに広がる。技術投資の上限が 0 のときは、完成した自軍の工場の段階によらず第 1 段階の種別だけを作る。強化した採掘施設は段階の高い種別として報告されるが、それは工場の段階ではない。

**ユニット上限に近づいたら、1 体に載せられる強さを最大にする。** 自軍のユニット数が上限の 6 割を超えたら、クレジットあたりではなく 1 体あたりの強さで選ぶ。上限の手前では先に尽きるのはクレジットだが、上限に近づくと先に尽きるのは枠だからである。上限に達したら軍備は作らず、クレジットは強化に回る。

**工場が作れるかどうかは、エンジンに尋ねる。** 自軍の完成した建物と建設機が**いま**出している生産と設置のアクションが、観測の生産メニューブロックで届く([05-interface.md](05-interface.md))。内政層は、空いた工場ごとにその工場のメニューから選び、設置はその種別をメニューに持つ建設機に任せる。定義ファイルは確かめる手段にならない。作り手を名指さない定義は、エンジンの本体が作る基本ユニットのこともあれば、他のユニットの付属品(多脚機の砲塔など)のこともあり、付属品を工場に注文しても何も生まれないからである。メニューが届く前の、建物が立った最初の周期に限って、種別表がその種類の見本ユニットから読んだ第 1 段階のメニューを使う。

**崩れても立ち直る。** 一度でも工場が立った試合で工場が 1 基も無くなったら、工場の設置を梯子の先頭に置く。採掘施設の数の条件は見ず、置き場所は本拠地の脇で、空いた建設機が無ければ本拠地に最も近い建設機を仕事から外して使う。工場が無ければ何も作れず、クレジットは溜まるだけだからである。また、仕事を持ったまま 20 秒動かず、送られた地点から 200 より離れて立っている建設機は、行き着けない所へ向かっているとみなして空いているものとして扱う。建てている最中の建設機は地点の脇で止まっているので、距離で区別する。

**採掘施設の「安全な順」は、本拠地からの距離そのものではない。** 素の距離で選ぶと、二人で取り合うマップでは本拠地の次に近い未占有の資源地点はたいてい盤面の中央にあり、開幕に 1 体しかいない建設機をそこへ送ることになる。それは開幕の終わり方の典型である。順位は本拠地からの距離から、敵の出撃地点に対する余裕(敵の出撃地点までの距離と本拠地までの距離の差)を引いたものであり、少し遠くても自陣の奥にある地点が、少し近くても前線上にある地点に勝つ。敵が現に立っている領域は、それとは別のより強い条件として先に後回しにする。歩く建設機からの距離ではなく本拠地からの距離で順位を付けるのも同じ理由で、二つの順序が食い違うのはまさに中央の地点においてである。

**順序 3 が作るものは、敵の編成に対する強さで選ぶ。** 空いている工場のそれぞれについて、そのメニューにある戦える種別(攻撃でき、動き、毎秒ダメージの記録があるもの。艦船は水上の戦いがあるときだけ)のうち、敵が現に立てている編成に対してクレジットあたり最も強いものを作る。強さの見積もりは `rwintel/control/policy/combat.py` の戦闘表が出す。Lanchester の二乗則で、戦力の強さを「受け止められる体力」と「相手に届く毎秒ダメージ」の相乗平均とする。同じ支出で買える強さの 2 乗は、体力と毎秒ダメージの積を価格の 2 乗で割ったものになる。相手の編成のうち撃てる相手の体力の割合だけダメージを数え、相手のダメージのうち自分に届く割合で体力を割る(届かない相手には下限 `tuning.unreachable_floor` を置く)。射程が相手の平均を上回る分には加点をする(`tuning.range_bonus`)。体力はエンジンの見本ユニットから、毎秒ダメージと射程は定義ファイルから取る。定義を持たない種別には毎秒ダメージの記録が無いので、定義を持つ種別のクレジットあたりの中央値を当てる。敵を見ていないうちは、自軍の編成を敵の編成の代わりにする。

**最も強い種別が今払えないときは、待つこともある。** 手元のクレジットと `tuning.save_horizon_s` 秒ぶんの収入で届かない種別は候補にしない。届くが今払えない最も強い種別に対して、今払える種別がその `tuning.save_share` 倍以上の強さなら、そちらを作る。そうでなければ工場は待ち、その価格を他の工場の予算から差し引いて取り置く。工場の数ではなくクレジットが軍備を縛っている間は、待っても生産の速さは落ちない。

**工場の種類も強さで選ぶ。** 最初の工場は基幹の工場とする。2 基目以降は、空いた建設機が置ける工場の種類のうち、第 1 段階で作れる最も強い種別がクレジットあたり最も強いものを置き、同点なら基幹の工場を選ぶ。作れる種別は、その種類の工場が自軍に立っていればメニューから、無ければ第 1 段階は種別表のメニューから、それより上の段階は定義ファイルの記述から読む。工場の段階の強化は、次の段階で作れる最も強い種別が今のメニューの最も強い種別を 1 割以上上回るとき、またはユニット上限に近いときに限る。

`choose` を切ると、次の段落の役割ごとの規則に戻る。**役割ごとの規則では、**空いている工場のそれぞれについて、装甲・砲・対空・高速の 4 役割のうち、戦略層が渡した軍備の目標構成に対して現有価値のシェアが最も足りていないものを選ぶ。両数ではなくシェアで見るのは、目標構成が軍事支出の割合だからである。重い戦車 1 両は軽い 2 両ぶんであり、両数で数えると同じ支出が役割によって別の意味を持つ。編成層が報告した増援の不足は、この不足度を重み 0.5 で曲げる。目標構成に建設機の取り分が入っていても工場ではそれを作らない。建設機を作るのは順序 5 であり、条件が別だからである。選んだ役割を工場のメニューで満たせないとき、またはその最も安い種別が手元のクレジットで払えないときは、不足度の順に次の役割を試す。

価格は種別表から取る。主要なものは `builder` 500、`extractor` 700、`landFactory` 700、`commandCenter` 3000、`turret` 500、`tank` 350 である([../game/06-content.md](../game/06-content.md))。

**建設は建設ユニットの特殊アクション、生産は工場の特殊アクションとして発行する。** 識別子はそれぞれ `"b_" + 内部名` と `"u_" + 内部名` である([../game/04-actions.md](../game/04-actions.md))。

## 移送の層

**輸送は部隊に入れず、移送の層が 4 つの固定の輸送の枠で預かる**(`logistics.py`)。作戦層が「どの輸送で運ぶか」を枠の番号で名指せるようにするためであり、部隊の 8 枠は使わない。枠には輸送をユニット ID の小さい順に空いた枠へ入れ、失われた輸送の枠は空ける。戦える輸送は戦闘の役割で数えるので部隊に入り、枠には入らない。

決めるのは作戦層(どの部隊を、どの枠で、どの領域へ)と内政層(どの建設機を、どの領域へ)であり、移送の層が決めるのは答えの決まる部分である。

| 決めること | 規則 |
| --- | --- |
| 運べるか | 枠の輸送が乗客の種別をすべて積め(`carries`)、積む地点と降ろし地点の両方へ行けること |
| 積む地点 | 乗客の中央に最も近い乗客から、その乗客と輸送の両方が行ける最も近い地点 |
| 降ろし地点 | 降ろす領域の陸の成分に入るタイルのうち、輸送が止まれて中心に最も近いもの(水陸の輸送は陸と水陸の両方で通れるタイル、空の輸送は陸のタイル)。輸送は陸の上でしか降ろさない |
| 積み荷 | 部隊ごと運ぶか、作戦層が渡したユニットの一覧を運ぶ。ゲーム側は輸送に収まるだけを積む |
| 枠の貸し出し | 空いた枠か、その部隊をその領域へすでに運んでいる枠だけ。他を運んでいる枠は貸さない |
| 建設機 | 空いた枠のうち、その建設機を運べて最も近い輸送で運ぶ。運べる輸送が無ければ不足として内政層へ返す |
| 期限 | 120 秒。過ぎた移送はゲーム側が打ち切る |

移送の進み具合はゲーム側が毎周期報告する([05-interface.md](05-interface.md) の移送ブロック)。枠は移送を出してから完了か失敗が返るまで塞がる。10 周期のあいだ報告されない移送の枠は空ける。再接続でゲーム側がその移送を忘れたときである。作戦層が歩いて行ける領域へ決め直した部隊の移送は、取り消しの行で止める。

## 軍事価値は価格の総和とする

部隊の現有価値、`cost_budget` の実損害、領域の勢力、交換比のすべてが「軍事価値」を必要とする。**定義は `am.cL()` が返す価格の総和とする。**

根拠は定義ファイルにある。組み込みの武装可動ユニットについて、価格と戦闘を決める量の対数相関を取ると、価格は最大体力と強く、最大体力と毎秒ダメージの積ともよく相関し、毎秒ダメージ単体や射程単体とは弱くしか相関しない。値は [../game/06-content.md](../game/06-content.md) にある。

**価格は耐久をよく代理し、耐久と火力の積もよく代理する。** 火力単体や射程単体との相関は弱いが、それらは価値というより相性の問題であり、価値の尺度に求めるものではない。

価格を選ぶ利点は相関の高さだけではない。**正確で、O(1) で読め、経済と同じ通貨である。** 独自の重み付けを作れば、その重みを調整する作業がそのまま新しい未決事項になる。

相関は次で計算し直せる。

```bash
python -m rwintel.data units
```

## 乱入への頑健性

学習中に、部隊の増減と契約の外部キャンセルをランダムに注入する([04-model-design.md](04-model-design.md))。スクリプト乱入者の初期値を決めておく。

| 事象 | 初期値の頻度 |
| --- | --- |
| 部隊からユニットを抜く | 作戦周期あたり 2 パーセント、抜く量は部隊の 10 から 50 パーセント |
| 部隊ごと指揮を奪う | 作戦周期あたり 0.5 パーセント、保持は 20 から 90 秒 |
| 契約を外部から書き換える | 作戦周期あたり 1 パーセント、目標領域を無作為に差し替える |
| 部隊を返却する | 保持期間の終わりに、配置を動かした状態で返す |

**頻度は作戦周期あたり陣営全体についての値であり、部隊あたりではない。** 部隊あたりと読むと、上限の 8 部隊が揃った盤面では数秒に一度の介入になる。それは干渉ではなく第二の指揮官であり、乱入者が模しているものではない。実装 `rwintel/control/intruder.py` はこの読みで書いてあり、1 作戦周期につき三つの事象をそれぞれ 1 回抽選し、当たった事象ごとに対象の部隊を 1 つ選ぶ。

**乱入者が発行するものは指揮系統が発行するのと同一形式の契約である。** 人間の介入と同じ経路を通す([04-model-design.md](04-model-design.md) の UI)。学習と評価の両方で使い、実際の人間は最終確認だけに使う。

## 規則の切り替え

上の規則のうちいくつかは、切り替えて外せるようにしてある。規則が残る根拠は試合の採点に対する効果であり、試合は再現しないので、効果は規則を外した方策と同じ実行の中で交互に回して測るほかない([07-evaluation.md](07-evaluation.md))。切り替えは `rwintel/control/policy/options.py` にあり、評価では `script:<名前>=<値>` のアームとして指定する。`baseline` は全部をこれらの規則が無かったときの設定に戻した状態である。強化の貯金は以前からある規則なので、`baseline` でも入っている。建設機の種別をその建物が作れるものから選ぶことと、軍事価値の比を軍どうしで取ることは誤りの修正なので、切り替えを持たず `baseline` にも入っている。作れる種別をエンジンの生産メニューから取ることと、2 基目の工場を軍備より先に決めることも同じ扱いである。

**規則の初期値のうち採点を動かしうるものは、探索の対象として `rwintel/control/policy/tuning.py` に集めてある。** アームでは `script:tune.<名前>=<値>` と書く。探索の範囲も同じファイルにある。初期値をモジュールの定数ではなく層に渡す値にしてあるのは、比較のアームが同じプロセスの中で並んで動くからである。定数を書き換えたアームは、他のアームの定数も書き換えてしまう。探索の手順は [07-evaluation.md](07-evaluation.md) の初期値の探索にある。

**採点をはっきり動かすのは内政層の規則である。** 全部を入れた階梯は `baseline` を大きく上回り、その大半は司令部から建設機を作ること(`hq`)による。拡張の計画、建設機の目標数、拡張を先に置くこと、立たない地点を諦めることは、それぞれ小さく採点を上げ、陸で広がれる地図で大きく効く。強化の貯金(`saving`)を外すと採点ははっきり下がる。**`contact`、`convoy`、`cover`、`dwell`、`relative` は、外しても採点の差が測って区別できる大きさにならない。** 既定で入れてあるのは、それぞれが答える状況(空の敵、遠い部隊への増援、拡張先の守り、姿勢の往復、両軍の差)が設計上の理由を持つからであり、採点を上げると示されたからではない。

| 名前 | 既定 | 外したとき |
| --- | --- | --- |
| `frontier` | `on` | 拡張の計画は本拠地から 1600 以内に限られる |
| `builders` | `scaled` | `fixed` で建設機は 2 体に固定 |
| `hq` | `on` | 建設機は工場からしか注文しない |
| `expand_first` | `on` | 拡張の計画の採掘施設は、強化と軍備の生産が残したクレジットでだけ置く |
| `retry` | `on` | 立たなかった設置の地点を諦めず、工場は毎回同じ位置へ置こうとする |
| `saving` | `on` | 強化のための貯金をせず、生産の余りでだけ強化を買う |
| `cover` | `on` | 守備隊は拡張の先頭に立たず、拡張の姿勢も計画の先頭を重くしない |
| `contact` | `on` | 接触した敵の編成が戦略層に届かない |
| `relative` | `on` | 両軍の軍事価値の比で防衛にも押し出しにもならない |
| `dwell` | `on` | 姿勢の滞留が無く、軍拡からの復帰も頭打ちと同じ閾値で起きる |
| `convoy` | `on` | 遠い部隊への増援も 1 体ずつ送る |
| `tech` | `factory` | `all` はすべての強化を技術の積立から払い、`off` はどの強化も積立から払わない |
| `recovery` | `on` | 工場を失っても採掘施設の条件が満たされるまで建て直さず、止まった建設機も放置する |
| `vanguards` | `on` | 守備隊の数に上限が無く、届く装甲を守備隊が受け取り続ける |
| `predict` | `on` | 戦術層は損害が出るまで交戦を続け、予測では後退しない |
| `concentrate` | `on` | 前衛は勝てるかどうかを見ずに争われている領域へ散らばり、集結もしない |
| `push` | `on` | 押し出しは 1.5 倍からで許容総損害は姿勢どおり、決戦は敵の拠点が 1 つになったときだけ |
| `choose` | `on` | 作るものを役割ごとの最も安い種別で選び、工場は陸上工場だけを建て、工場の強化を強さで判断しない |

## スクリプト方策が果たす役割

一つの実装が四つの役割を兼ねる。

**骨格である。** 全層が最初から動く。学習方策は 1 層ずつ差し替える。

**教師である。** スクリプトが出す契約と逸脱は、そのまま「状態と行動」の対になる。人間のリプレイから取れる対は人間が遊んだ分に限られ、行動も契約の形に推定し直す必要があるが([04-model-design.md](04-model-design.md))、スクリプトからは契約の形のまま無制限に取れる。

**評価基準である。** 学習方策がスクリプト方策を多数エピソード平均で上回るかどうかが、最初の合格条件になる([07-evaluation.md](07-evaluation.md))。

**契約の検証である。** 渡す情報が足りなければスクリプトが書けない。書けたなら、その粒度で層が分けられることが実物で示されている。
