# 作戦層と構築作戦アリーナの記録

**環境の仕様は [../system/04-learning.md](../system/04-learning.md) にある。この文書はそこで測ったことだけを書く。** 種の書き方と読み方の規律は [03-tactics.md](03-tactics.md) と同じである。

## 結論

**先に、いちばん新しい読みを置く。この場で測った最大の優位は、フル試合へ持って行くと消える。** 構築作戦アリーナで手書きの梯子を -0.2041、集中アームを -0.0761 上回った世代を、集中アームが +0.065 を出したのと同じ条件の試合に置いた。**梯子との差は +0.040(梯子が上、要 233 対)で分解せず、自分が鍛えられた戦術層だけの鎖との差——すなわちこの記録が初めて分けた作戦層だけの寄与——は +0.029 で 0 を含む。そして六つの対のうち唯一分解したのは、集中アームがその学習した鎖を +0.087 で上回る対である**(要 58 対に対し 96 対)。**アリーナの順位(学習層 > 集中 > 梯子)は、試合では(集中 > 梯子 ≒ 学習した鎖)に入れ替わる**([この場の最大の優位を試合へ持って行った](#この場の最大の優位を試合へ持って行った乗ったのは集中のほうで学習層は集中に負ける))。

**下に凍結する戦術層はこの場の計器そのものであり、交戦アリーナで最も強い層が最良の計器とは限らない。** 新しい梯子から 5,120 エピソード鍛えた層——交戦アリーナで梯子を上回る唯一の層——を凍結すると、**その層は決定の 95.6 パーセントで `hold` を選び、旧い凍結層は 80.4 パーセントで `focus` を選んでいた。** 同じ作戦層 b3 の梯子に対する優位は、旧い計器で -0.1840 ± 0.0233、新しい計器で **-0.1217 ± 0.0187** へ縮む。**部隊が送り先で撃ち合いを解決しないなら、どこへ送ったかが盤面に現れる量そのものが小さい**([凍結する戦術層を「最強のもの」に替えたら、計器のほうが変わった](#凍結する戦術層を最強のものに替えたら計器のほうが変わった))。**そしてその計器の上で鍛え直した層は、長さを揃えても旧い層に届かない**(150 エピソードどうしで -0.0728 ± 0.0283)。

**フル試合では、作戦層の選択は測れない。** 相手・地図・長さ・難易度を変えて六通り測り、梯子・模倣・強化のどれもが互いに 0.02 の内側に並んだ。**選択そのものが試合を動かす幅は点推定でおよそ 0.04 あるが、それはフル試合の測定の床(±0.02、経済と AI の数が作る散らばり 0.11 から 0.24)に埋もれる。**

**経済を構成で取り除いた場を作ると、選択は分解できる。** 構築作戦アリーナ(`OpsArena`)の上では、**訓練済みの戦術層を両側の下に凍結し、その下で 150 エピソード鍛えた作戦層が、同じ実行に立てた手書きの梯子を上回った。ただし三世代の計器を並べると、上回りは計器を直すごとに縮み、いまは二つの測定種のうち一つでしか区間つきに言えない**——`script` − `learnt` は -0.1111 と -0.1122(枠を運ぶ計器)、-0.1045 と -0.1142(戦術の方位を自陣基準にした計器)、そして**作戦の切り出しまで鏡像合同にすると -0.0132 ± 0.0346(種 80001、0 を含む)と -0.0632 ± 0.0356(種 90001)**である([作戦の切り出しを鏡像合同にすると、学習層は落ちた](#作戦の切り出しを鏡像合同にすると学習層は落ちた))。**この計画で手書き層を上回った学習方策は、いまもこの場の作戦層だけである。**

**そして取り下げたものが二つある。「学習した層が集中アームも上回った」は二度反転した。** 傾いた計器では `concentrate` − `learnt` = -0.0508 と -0.0487 で学習層が上、戦術の方位を直すと -0.0186 と -0.0113 で区別が付かず、**作戦の切り出しまで直すと +0.0637 ± 0.0399 と +0.0395 ± 0.0376 で、二つの種とも集中アームが上である。** **そのうえ「枠を取り除けば良くなる」も成り立たなかった。** 地図の番号で並んだ行は一つの固定マップの上では「どの場所か」を名指ししており、自陣中心の並びはその同一性を捨てる。**戦術の方位で起きたことと同じで、不変性は情報と引き換えである。** そして**関門はこれまでで最も締まっている**(`script` アームが -0.0008 ± 0.0093 と -0.0010 ± 0.0139)ので、この落ち込みはいちばん信用できる計器の上のものである。

**鏡像同変な符号化はいま在る。欠陥の一つは視界ではなく符号化にあった——58 個の戦術特徴のうち、点反射で符号が変わるのは目標への単位方向ベクトルの 2 つだけで、残り 56 個は二つの側でビット一致していた。脅威の重心から見た目標の方位に置き換え、網が盤面とその点反射に同じ答えを返すことを試験で固定してある**([03-tactics.md](03-tactics.md))。**新符号化で鍛え直した層を凍結して三つの種で関門を取り直すと、偏りは小さくなった——+0.0107 が -0.0020(種 80001、49 盤面)、+0.0297 が +0.0047(90001、52 盤面)、+0.0267 が +0.0200(93001、49 盤面)で、旧符号化では八つの読みがすべて正だったのに対して一つは負に転じ、三つの平均は約 +0.022 から約 +0.008 へ落ちた。** **そして方位の基準を脅威の重心から各側の自陣(このアリーナでは各側の staging point)へ移し、アリーナが側ごとの基準点を層に渡すようにして取り直すと、三つの種はどれも関門を通った——-0.0046・-0.0047・+0.0020 で、二つが負、平均は約 -0.002 である。二つの符号化で外し続けていた種 93001 を含む。ただし取り直した種は三つで、種 91001・92001 はどちらの符号化でも取っていない**([03-tactics.md](03-tactics.md))。

**そのうえで四つを同じ場所に読まなければならない。第一に、「凍結した戦術層の下で自己対戦ゼロが通る」と書けるのは取り直した三つの種についてだけで、旧い系統性は五つの種の八つの読みの上のものだった。三つの読みで五つの種の系統性を否定することはできない。第二に、上の四つの数字は二世代前の計器の上で取られたままで一つも測り直していない——変わったのは限界の原因の一つが分かって取り除かれたことであって、測定が取り直されたことではない。第三に、この符号化の戦術層が強くなったのでもない。脅威基準で -0.0398 ± 0.0228 と 0 を外して下回った層は、自陣基準で +0.0036 ± 0.0226 と 0 を含むところへ戻っただけで、梯子を上回ってはいない。第四に、符号化とは別の説明——出撃地点の反射が合同な行軍を与えないこと——は消えていない。脅威基準で三点が揃っていた「より近くまで届いた側が正の側」は自陣基準では再現しなかったが、行軍の非合同は基準点とは別のものである**([下の節](#符号化を直すと偏りは落ち基準点を自陣へ移すと三つの種とも関門を通った))。

**確かめの種に付く注意と、その傾きの出所は、いま分かっている。傾きを作っているのは凍結した戦術層であって、種 90001 の抽選ではない。五つの種で取った八つの読みがすべて正なので、これは一つの種に起きた事故ではない。** その種では `script` アーム自身のプールした平均が +0.0297 ± 0.0182 で 0 を外し、**アリーナ自身の関門である自己対戦ゼロを通っていない。実行器は正しく警告を出した。** **同じ種の同じ 52 盤面を手書きの戦術層の下で回すと、同じ `script` アームは -0.0058 ± 0.0183 で 0 を含み、関門を通る。盤面は種だけで決まるので、二つの実行の違いは下で戦った層だけである。** **これは網が点反射に対して不変ではないというこの記録自身の警告が当たった形である**——相手側の盤面は所有の旗を裏返して作るのであって座標を反射して作るのではないので、二つの側には「意味は合同だが場所は合同でない」入力に同じ関数が当たり、**距離と強さを読む手書きの梯子はどちらの側でも同じ答えを返すが、網はそうである必要が無い。** 対差は同じ盤面どうしの差なので**両アームに共通する加法的な傾きは打ち消され、上の四つの結論は単独の平均ではなく対差の上に立ててある。ただし系統的な偏りは二つのアームに違う効き方をしうるので、対にしたことをもって除けたとは言えない。単独の平均は傾きぶん膨らんでおり、そのようにしか読めない。**

**取りに行くべき disc の数がそれを裏書きする。** 敵の garrison が開始時に立っていた disc のうち、学習層は種 80001 で 98 本中 22 本、種 90001 で 104 本中 32 本を取る。**同じ実行の集中アームは 14 本と 21 本、梯子は 11 本と 8 本である。** 保てばよい側は 88 本と 98 本を保っている。**学習した層が奪取数と点数の両方で集中アームを上回り、しかも点数の区間が 0 を外したのは、これが初めてである。**

**「集中は学習層と区別が付かない」は「上回った」に更新される。** その一つ前は「集中はまだ学習層の上にいる」で、`concentrate` − `learnt` が +0.0580 ± 0.0386(o1)、次いで +0.0450 ± 0.0486(p1)、そこからエントロピー賞与を下げた二本で +0.0157 ± 0.0480(p3)と +0.0045 ± 0.0402(p4)まで縮んで 0 を含んだ。**凍結した戦術層の下では符号が変わって -0.0508 ± 0.0378 と -0.0487 ± 0.0328 になり、二つの種で 0 を外した。** **そしてその更新は取り下げてある。** 同じ設定を、基準点が側ごとに正しく入る戦術層の下で測り直すと -0.0186 ± 0.0540 と -0.0113 ± 0.0426 で、**二つの種とも 0 を含む。いまの読みは「集中は学習層と区別が付かない」である**([直した計器で測り直した](#直した計器で測り直したh1梯子超えは再現し集中超えは再現しなかった))。

**この結果に至る梯子は四段で、後ろの一段は分けられた。効いたのは凍結した戦術層であって、訓練の長さではない。** 四段とは、終端を送られた disc の開始所有から読むこと(o1)、周期ごとに終端へ畳み込まれる信用を払うこと(p1)、エントロピー賞与を既定の 10 分の 1 の 0.0002 に置くこと(p3・p4)、そして訓練済み戦術層を両側の下に凍結すること(f1・f2)である。**前の三つは一段ずつ足して同じ 49 盤面で測ってあるので、それぞれが何を買ったかは切り分けられている。** 集中アームを区間つきで上回った f2 は、p3・p4 から凍結と 150 エピソードという長さを同時に変えていたが、**手書き戦術層の下で他をすべて f2 と同じにして 150 エピソード鍛えた実行(f3)が落ちて、その二つが分かれた。手書きの層の下では、長く鍛えると集中アームが学習層を区間つきで上回る**(`concentrate` − `learnt` = +0.0587 ± 0.0443(種 80001、49 盤面)と +0.0660 ± 0.0492(種 90001、52 盤面)、どちらも 0 を外す)。**同じ手書きの層の下で 50 エピソードだった p3・p4 は集中アームと区別が付かなかったので、長さは手書きの層の下ではむしろ悪くしている。** **四つの箱を並べた表は[下記](#交絡は分解された)にある。骨格が置いた学習の順序——戦術層を先に固め、凍結したそれに対して作戦層を学習させる——は、これで仮定ではなく測定になった。** **ただしこの対照は、傾いていたほうの計器の上で取ってある。** 直した計器では学習層と集中アームが区別できないので、この四つの箱のうち f2 の側の読みは動いている。**手書きの層の下の f3 を直した計器で取り直した実行は無いので、対照そのものは取り直されていない**([直した計器で測り直した](#直した計器で測り直したh1梯子超えは再現し集中超えは再現しなかった))。

**この結果を出した設定は一つに書き下せる。終端を送られた disc の開始所有から読み(`ops_train --opening 1`)、周期ごとにその終端へ畳み込まれる信用を払い(`--credit region`)、契約更新で軌跡を切らず、盤面から消えた部隊の図を凍結し、エントロピー賞与を既定の 10 分の 1 の 0.0002 に置き(`--entropy 0.0002`)、作戦の決定周期をエージェントの既定 2000 ミリ秒のままにして、梯子を相手に 160 エピソード鍛えた戦術層を両側の下に凍結し(`--tactics local/tactics-vs-script2.pt`)、フル試合の模倣 `local/operations-bc.pt` から 150 エピソード鍛える。**

**この場の学習信号には欠陥が二つあり、どちらも実測で確定して直した。** 一つは終端の基準点で、終端が部隊の行いではなく地面の立ち方を払っていた。もう一つは信用の届き方で、再契約のたびに優位が恒等的に 0 になり、決定の 1.2 パーセントにしか終端が届いていなかった。**ただしこの二つを直しただけの層(p1)は梯子を上回るところまでしか行かず、集中アームには +0.0450 ± 0.0486 で届いていなかった。**

**それでも方策は一つの配置に落ち着いていない。用務の長さは f1 が 20.7 決定、f2 が 22.3 と 22.5 決定、すなわち 41 から 45 ゲーム秒ごとに行き先を変えており、同じ実行の梯子は 138.2 から 144.6、集中は 129.9 から 133.5 決定続ける。** **決められないまま梯子を上回ったので、「配置を決められないこと」は成績の説明にならない。この読みは賞与を下げた二本の時点で取り下げてある。** 直した計器でも用務の長さは 20.7 決定、梯子は 131.5 と 127.3 で、比は変わらない。

**変わったのは立つ場所である。** 学習層の最接近の中央値は f1 が 257、f2 が 221(種 80001)と 249(種 90001)で、**種 80001 の 49 盤面を手書き戦術層の下で測った七つの層がどれも catchment 半径 400 の外(418 から 698)だったのに対して、初めて内側に入った。** 部隊が一つも catchment に入らなかった盤面は f2 で 49 枚中 4 枚・52 枚中 2 枚であり、p3 の 28 枚・p4 の 26 枚から落ちている。**ただし計器そのものが動いている**——同じ実行の梯子の最接近の中央値は 331 から 423 で、手書き戦術層の下の 291 から 295 より遠い。**比べてよいのは同じ実行の中のアームどうしだけで、そこでは f2 の学習層が三つのアームで最も近い。**

**そしてエントロピー賞与が何を通じて効いたのかは、依然として分かっていない。** 賞与だけを 10 分の 1 にした対で、測ったエントロピーは下がっていない(既定の賞与で回した p1 の平均 1.696 に対して、p3 が 1.544、p4 が 1.756)。**凍結した戦術層の下の二本は平均 1.438(f1)と 1.291(f2)でこれまでで最も低いが、この二本は賞与以外も変えているので、賞与の機序についての測定ではない。** **「分布が尖ったから決まるようになった」はこの結果の説明ではなく、機序を当てた測定は無い。**

## アリーナの技能はフル試合へ乗った——集中が梯子を 0.065 上回る

**この場が報いている技能がフル試合で良い打ち回しなのかは、この記録がずっと未解決として挙げていた問いである。答えが出た。乗る。**

**三つのアームを同じ実行に並べた。** マップ Lake、打ち切り 300 秒、内蔵 AI 一体(難易度 1)、乱入込み、アームごと 96 試合。鎖はどれもスクリプトで、違うのは作戦層だけである。

| アーム | 試合 | 採点 | 散らばり | 経済成分 |
| --- | --- | --- | --- | --- |
| `ops-concentrate`(行き先を最優先領域へ上書き) | 96 | **-0.471** | 0.177 | **-0.315** |
| `script`(手書きの梯子) | 96 | -0.536 | 0.131 | -0.369 |
| `ops-pin`(最小番号の領域へ固定) | 96 | -0.539 | 0.130 | -0.395 |

| 対 | 差 | 必要な試合数 | 読み |
| --- | --- | --- | --- |
| `ops-concentrate` − `script` | **+0.065** | 91 対(96 対ある) | **分解した。集中が梯子を上回る** |
| `ops-concentrate` − `ops-pin` | +0.068 | 81 対 | 同じ |
| `script` − `ops-pin` | -0.004 | **19,441 対** | **梯子の選択は、何も選ばない配備と区別が付かない** |

**三つのことが同時に言える。**

**一つ、アリーナの読みが試合で再現した。** 構築作戦アリーナで集中は梯子を 0.076 から 0.095 上回っており、試合では 0.065 である。**場を作った目的そのものが果たされている**——経済を取り除いた盤面で分解した差が、経済のある試合でも同じ向きに同じ桁で出た。

**二つ、経済成分が動いた。** -0.369 から -0.315 である。**収入は資源地点に立つ採掘施設から来るので、地面を取ることは経済の上流であり、それが数字に出た。** 480 試合の集計で自軍の収入が 35.5、相手が 77.9 だったこの鎖にとって、そこは負けている場所そのものである。

**三つ、手書きの梯子の作戦選択は、何も選ばない配備と区別が付かない。** `ops-pin` との差は -0.004 で、区別するには 19,441 試合が要る。**梯子は丁寧に選んでいるが、その丁寧さが試合を動かしているという証拠は無い。** 動かしているのは「一点へ集めること」である。

**したがって、手書きの作戦梯子は集中すべきである。** これは学習の話ではなく、規則の話である。**ただし今夜は入れ替えていない**——測定中の実行が現在の梯子を相手にも基準線にも使っており、途中で入れ替えるとその実行が測っているものが変わる。**入れ替えは記録に残した問いのいちばん上にある**([06-open-questions.md](06-open-questions.md))。

## 長く鍛えると弱くなる——同じ実行の 4 アームで区間つきに出た

**150 エピソードの層と、そこから 150 エピソード続けた層を、同じ盤面の上に並べた。** 種 80001、97 盤面、アームは `script`・`concentrate`・c1(150)・c2(300)の四つで、**四つとも同じ 97 盤面を戦っている。**

| アーム | side score | 取るべき disc | 保つべき disc | 最接近の中央値 | 用務の長さ |
| --- | --- | --- | --- | --- | --- |
| `script`(自己対戦ゼロ) | +0.0005 ± 0.0090 | 8/194 | 179/194 | 309 | 133.8 |
| `concentrate` | +0.0952 ± 0.0278 | 39/194 | 176/194 | 266 | 119.3 |

**対にした差は三つとも区間が 0 を外すか含むかがはっきりしている。**

| --- | --- | --- | --- |

**どちらの機序かは、この実行では分けられない。** 用務の長さが 26.3 決定(梯子の 5 分の 1)しかないので、部隊が行き先を変え続けて到着しない、という読みができる。**一方で、優先度の付いていない領域へ契約することは、この報酬ではちょうど 0 を払う**——取りに行って失敗しても 0、守って少し削られれば負、という並びの中で、**何もしない場所を選ぶことが安全な 0 になる。** 前者なら部隊は盤面の中ほどをうろつき、後者なら staging point の近くに留まる。**435 という中央値はその中間にあり、記録は契約が名指した領域を書き留めていないので、どちらとも決められない。** そこを分ける欄を足した([契約が採点される地面を名指したか](#契約が採点される地面を名指したか))。

## 契約が採点される地面を名指したか

**エピソード記録に一欄足した。** この側の作戦決定のうち、**盤面が優先度を置いた領域を名指した決定の数**である。優先度は係争点にしか置かれないので、これは「その決定は採点される地面を指していたか」とちょうど同じ問いになる。

**足した理由は上の一段落である。** 長く鍛えた層が採点される地面から離れていくことは測れていたが、**それが「行き先を変え続けて到着しない」のか「そもそも採点されない場所を指している」のかを、記録が区別できなかった。** 前者は用務の長さに、後者はこの欄に出る。**どちらであるかで直し方が違う**——前者なら契約の保持や引き直しの費用、後者なら報酬が abstention に 0 を払っていることそのものである。

**測った。churn である。**

| アーム | 採点される地面を名指した決定 | 用務の長さ | side score |
| --- | --- | --- | --- |
| `script` | 44.0 パーセント | 131.7 | -0.0038 |
| c1(150 エピソード) | **58.3 パーセント** | 35.5 | +0.0269 |
| c2(300 エピソード) | **52.6 パーセント** | 26.8 | -0.0123 |

**長く鍛えた層は、梯子より高い割合で採点される地面を名指している。** 52.6 対 44.0 パーセントであり、**abstention ではない。** 変わったのは指し続ける長さで、35.5 から 26.8 決定へ落ちている。**指す先が悪いのではなく、54 ゲーム秒ごとに指す先を変えるので到着しない。**

**同じ実行で、長さの結果が三度目の再現をした**——`c1` − `c2` = +0.0392 ± 0.0280(75 盤面)。

**この読みのうち、機序の側は残り、成績の説明の側は取り下げる。** 切り出しを広げて鍛え直した世代(e1)は**用務の長さ 16.1 決定と、ここで測ったどの層より短く気を変えるのに、この場で測ったどの層より強い**([切り出しを広げた世代](#切り出しを広げた世代が梯子を大きく上回り集中と並んだ))。**「指し続ける長さが短いから点が落ちる」は成り立たない。** 長さと点数が同時に動いた実行が三つあることは測定であって、そこから長さが原因だと読むことは推論であり、その推論はこの一つで反証される。**残るのは「長く鍛えると何が変わるか」の答えとしての churn であって、「なぜ点が落ちるか」の答えではない。**

**そこで、作戦の切り出しに「いま決定を訊かれている部隊がそこへ契約しているか」を足した。** 部隊行は任務の経過と予算の消化を持ちながら行き先を持っておらず、**いま走らせている用務が見えない方策は、それを続けることを表現できない**([../system/04-learning.md](../system/04-learning.md))。**切り出しが 424 次元になったので、それ以前のパラメータと教師はすべて刻印で拒まれる。取り直す一巡を回している。**

## 構築作戦アリーナの設定は掃引で選んだ

**当初の設定(半径 250・2 対・地平 120 秒)の自己対戦ゼロは自明なゼロだった。** 32 エピソードで +0.0001 ± 0.0003 と出たが、shares を見ると各 catchment はちょうど 0.0 か 1.0、すなわち**鏡像対の garrison だけを含んでいた。** staged 部隊は生き残るのに交戦点から平均 492 外で止まり、円板にほとんど登録されない(平均 0.12 体)。garrison は構造で相殺するので平均は 0 になるが、**測りたい作戦選択がスコアを動かしていない。「傾いていない」ではなく「何も測っていない」である。**

**catchment を standoff の帯まで広げる(半径 400 から 500)と部隊が登録され、shares が 0.2 から 0.8 に散り、選択がスコアを動かすようになった。同時に Lake では自己対戦の平均が +0.06 から +0.075 へ跳ねた。** garrison の相殺が隠していた盤面の傾きが、部隊が実際に係争して初めて露呈したのである。

**その傾きの出所はマップだった。** 半径 400・2 対で Lake は +0.060 ± 0.029 と 0 を外すが、より対称でコンパクトな Hills は +0.021 ± 0.026 で 0 を含み、部隊も交戦点により近づく(最接近 282 対 419 から 492)。**配線に系統的な非対称は無い**——あれば Hills でも同じだけ傾く。**点反射が Lake の地形を保存しないことである。** ops アリーナは局所交戦と違って盤面を横断行軍させるので、マップの大域的な非対称に強く晒される。

**この掃引が選んだ三つが、そのまま実装の既定になっている:地平 300 秒、catchment 半径 400、マップ Hills。**

## アリーナは選択を分解した——ただし勝っていたのは盤面を捨てることだった

**固定配置アーム(`pin`)を足して手書きと対にすると、手書き − 固定 = -0.040 ± 0.027、区間 [-0.067, -0.013] で 0 を外した**(Hills、66 盤面、種 40001)。**分解できたが、符号が予想と逆で、選択をしない層が手書きを上回った。**

**これを「分散する相手に対する戦力の集中」と読んだのは誤りだった。同じ実行の記録がそう言っている。** `PinnedRegion` が選ぶのはマップ上の最小番号の合法領域であり、係争点とは何の関係も無いので、部隊は採点される盤面の外へ行進する。**その実行の固定配置アームは、採点された 68 エピソードのうち 50 本で部隊が一つも catchment に入っておらず、最接近の中央値は catchment 半径 400 に対して 770、空で終わった disc は 272 中 47 本である。同じ抽選の手書きアームは 66 本中 16 本、中央値 260、264 中 18 本である。** **敵 garrison を制圧したのではない。盤面を捨てて disc が空のまま終わるに任せており、空の disc は敗北ではなく半分と読まれる。** 測っていたのは集中の値打ちではなく、**突撃をやめることの床**である。

**アームごとの最接近と catchment 内数は最初から記録されていて、固定配置のアームに向けられていなかっただけである。** いまは実行がアームごとに報告し、中央値が catchment の外なら警告する。

## disc は開始の所有で分けて数える

**取りに行くべき disc は開始時に敵の garrison が立っていたもの、保てばよい disc は自軍の garrison が立っていたものである。** 対はその反射なので、盤面の係争 disc はちょうど半分ずつに分かれる。**終わりのシェアが半分から 0.05 より外れたときだけ勝敗を数え、内側は半とする**(`rwintel/learn/ops_run.py` の `_DECIDED`)。**アリーナは開始の所有を journal に書き(`held`)、実行はアームごとにこの内訳を自分で報告する。**

**この内訳が要るのは、プールした side score が「地面を取ったアーム」と「地面を捨てたアーム」を区別できないからである。** 空で終わった disc は敗北ではなく半分と読まれるので、突撃をやめる方策は平均の上では上に出る。**固定配置アームの優位がまさにそれだった。**

**journal の disc ごとのシェアと優先度から side score が再構成できることも確かめてある。** 優先度加重の (シェア − 0.5) の平均が side score そのものであり、journal の丸めを含めても最悪の食い違いは **3.2e-5** である(種 80001 の 4 アーム、196 エピソード)。

## 直した信号で鍛え直した——梯子を初めて上回り、学んだのは保つことだった

## 終端が、部隊の行いではなく地面の立ち方を払っていた

**対の両側の係争領域は同じ優先度を持つ。** 優先度は対ごとに一度引いて両方の領域に置くので構造であり、実測でも対ごとに一致する。

**旧い終端は `符号 × (優先度 × (シェア − 0.5) − 倍率 × (garrison シェア − 0.5))` で、倍率は 0.0 に置いてあった。** すなわち**中立の半分を基準点とする領域の絶対支配**である。**その倍率(構築作戦アリーナの `STRENGTH_SLOPE`。交戦アリーナの同名の二つとは別物である)はもう存在しない。** 同じ garrison シェアを引くのではなく、**基準点そのものに据えた**からである。

**この場の実測の率が、その読みを罰から報酬に反転させる。** 守備側の garrison は、部隊を送られようが送られまいが、地平まで自分の disc の約 88 パーセントを保つ(種 80001 の 49 盤面で、`script` アームが hold 98 本中 87 本、`concentrate` アームが 86 本、`pin` アームが 90 本)。一方、**全部隊を一つの敵 disc へ集める集中アームでも、その 1 枚を取れるのは 49 盤面のうち 18 枚、およそ 4 割である**(奪った disc は 21 本だが、集中は盤面あたり一点しか攻めない)。**梯子は取りに行くべき 98 本のうち 7 本、およそ 7 パーセントしか取らない。**

**その率を絶対支配に入れると、期待値の符号がこうなる**(p はその領域の優先度)。

| 用務 | 期待値(旧い読み) | 期待値(直した読み) |
| --- | --- | --- |
| 突撃(4 割成功) | `p × 0.5 × (0.40 − 0.60) = −0.10p` | `+0.40p` |
| 守備(8 割 8 分保つ) | `p × 0.5 × (0.88 − 0.12) = +0.38p` | `−0.12p` |

**方策は「行くな」と言う報酬を正しく最大化していた。** 旧い終端で鍛えた層(l3)の 96/98 保持・4/98 奪取・最接近中央値 441 は、その帰結である。

**直した終端は `符号 × 優先度 × (シェア − opening)`、`opening = 0.5 + OPENING_BASELINE × (その領域の開始 garrison シェア − 0.5)`、`OPENING_BASELINE = 1.0` である**(`ops_train --opening`。0 に置くと旧い読みが戻る)。**用務が払われるのは、送られた地面が動いたぶんであって、地面がどこに立っているかではない。**

**反対称性は構造で保たれる。** `_finish_side` は両側に同じ shares と同じ garrison シェアを符号だけ変えて渡し、一つの disc の両側の開始シェアは終わりのシェアと同じく和が 1 なので、**基準点をどこに置いても片側の終端はもう片側の負である。** 自己対戦ゼロはこの量について何も言わない。

**旧いコードのコメントは、この量を交戦アリーナの戦力シェア倍率と同じ「方策不変の制御変数」と書いていた。それは誤りで、訂正した。** 戦力シェアは抽選で決定より前に固定されるので方策不変だが、**こちらは部隊が測られる領域を自分で選ぶので基準点も自分で選ぶ。** 制御変数ではなく終端の定義である。

**基準点だけを直すと、単独では逆効果だった。** 同じ模倣から同じ種 51001 で 50 エピソード鍛えた層(o1、146 更新)を、種 80001 の同じ 49 盤面で測った(`local/ops-arms-o1-80001.jsonl`)。

| アーム | 単独 | 2se | 最接近中央値 | take 勝/負/半 | hold 勝/負/半 |
| --- | --- | --- | --- | --- | --- |
| `script` | -0.0110 | 0.0145 | 294 | 5/90/3 | 88/6/4 |
| `concentrate` | +0.0769 | 0.0374 | 220 | 21/72/5 | 87/7/4 |
| `learnt`(o1) | +0.0189 | 0.0131 | 667 | **2**/91/5 | 96/2/0 |

**対差は `script` − `concentrate` = -0.0878 ± 0.0386(0 を外す)、`script` − `learnt` = -0.0298 ± 0.0189(0 を外す)、`concentrate` − `learnt` = +0.0580 ± 0.0386(0 を外す)である。** 旧い終端の l3(+0.0375、最接近 441、奪取 4)に対して、o1 は下(+0.0189、最接近 667、奪取 2)。**訓練そのものは健全に走っている**(最初の生の更新で平均リターン -0.155・エントロピー 1.42、最後の更新で +0.128・0.98)。**基準点は必要だったが、それだけでは足りなかった。**

## 終端が決定の 1.2 パーセントにしか届いていなかった——実測で確定した

**計測の道具を先に入れた。** drain のたびに、そのバッチが何でできているかを**正規化の前に**数える(`Rollout.census`)。数えるのは、段数、終端の届いた用務にある段、優位がちょうど 0 の段、閉じた軌跡の数、切断の理由別の数、相異なる優位の数である。**正規化のあとでは数えられない。中心化と尺度合わせが、同一の 0 の塊を同一の非ゼロ値の塊に変えてしまうからである。**

**修正前の実測**(`local/ops-train-gate.log`、種 51001、2 エピソード、8 インスタンス、warmup 0、全 5 更新。**直した終端の下で、信用の払い方だけが地平で一度だったときの実行である**)。

| 更新 | 段数 | 終端の届いた用務にある段 | 優位ちょうど 0 | 切断の理由 | 相異なる優位 |
| --- | --- | --- | --- | --- | --- |
| 1 | 1152 | 9 | 729 | renewed 729 | 424 |
| 2 | 1148 | 11 | 804 | renewed 804 | 345 |
| 3 | 1303 | 9 | 774 | renewed 774 | 530 |
| 4 | 1180 | 23 | 817 | renewed 817 | 364 |
| 5 | 1126 | 20 | 741 | renewed 741 | 386 |

**合わせて 5909 段のうち終端が届いたのは 72 段(1.2 パーセント)、優位がちょうど 0 なのが 3865 段(65.4 パーセント)、切断は 5 更新とも全部が再契約である。**

**機序は算術で言い切れる。** 学習作戦層は毎周期引き直すので、契約が変わるたび `_settle` が軌跡を切る。`Rollout.cut` は最後の段を自分自身の価値でブートストラップするから、割引 1・trace 1 では長さ 1 の切断軌跡の delta はその段の報酬ちょうどであり、**契約更新の周期は `OperationalReward.step` の構造上 0 を払う。ゆえに再契約の決定の優位は恒等的に 0 であり、`normalise` の中心化がその同一の 0 を全て同一の非ゼロ値に変える——いま引いている行動を、根拠なく一様に強化する定数である。**

**これが二つの体制を説明する。** 旧い終端では終端が強く正なので定数が負になり、全行動が抑制されて実行が不活性だった(l3 と l4 が区別できなかったこと)。**直した終端では終端が 0 近傍で、決定の 65 パーセントがちょうど 0 なので定数の符号が雑音になり、方策が任意の領域へ崩れて盤外へ行進した**(o1 の最接近 667、奪取 2)。

**生存者バイアス説は棄却する。** 「学習層は部隊が早く死ぬから catchment に居ないのだ」という読みは、診断が否定する。o1 の学習アームは `our_alive` が三つのアームで最高(21.3、梯子 20.8、集中 18.8)なのに `our_in_catchment` は最低(1.73)である。旧い終端の l3 も生存は梯子と同水準(20.4 対 20.6)で catchment 内は半分以下(2.47 対 5.18)。**部隊は死んで消えたのではない。生きたまま、採点される地面の外に立っている。**

**直し方は密度である。** 周期ごとに、その部隊自身の採点図の移動を払う。**図は毎周期アリーナが自分の disc を読んで両側へ渡し、地平の終端は同じ級数の最後の一項になる。** 差分なので伸縮し、エピソードの和は地平の図ちょうどになる——**目的は変わらず、密度だけが変わる。** 契約更新では切らない(採点する盤面では `renewed` が立たない)。盤面から消えた部隊の図は凍結する。

**修正後の実測**(`local/ops-train-p1.log`、種 51001、50 エピソード、census の出た全 141 更新)。**168,886 段のすべてが終端の届いた用務にあり、優位ちょうど 0 は 0 段、切断は 0 本、相異なる優位は 168,868 である。** 修正前の 5909 段中 72 段と並べて、**死んだ勾配は実測として消えた。**

| p1 | 開始の所有 | 周期ごと | +0.0324 | 691 | **7** |

**奪取数は初めて梯子(この実行では 5 本)を上回った。しかし方策は配置を決められていない。** 用務の長さが 18.1 決定、作戦周期は 2000 ミリ秒なので **36 ゲーム秒ごとに行き先を変えている**(梯子 133.3、集中 122.7)。最接近の中央値 691 は catchment 半径 400 のはるか外である。

**訓練中のエントロピーは、下がらずに上がった。** p1 は最初の生の更新で 1.542、最後の更新で 1.795 である。旧い信号の l3 は 1.32 から 0.915 へ、o1 は 1.42 から 0.98 へ落ちていた。**エントロピーが上がるのは、行動を選り分ける勾配が無く、一貫した向きを持つのがエントロピー項だけであることの徴候であり、フル試合の作戦層で記録されているものと同じである。**

**そこから「機序は決定の頻度である」という仮説を立てた。** 地平 300 秒・作戦周期 2000 ミリ秒なので 1 部隊は 1 エピソードに約 150 回決定するのに、独立な結果は 1 つしか無い。**エントロピー賞与はその 150 段すべてに足されるので、情報のある信号に対して実質 150 倍に重み付けされている**、という算術である。

**その仮説は走らせて外れた。** 周期を 10000 ミリ秒へ粗くした実行(p2)は梯子と区別が付かないところまで落ち、**賞与そのものを 10 分の 1 にした実行(p3・p4)が集中アームに並んだ**(下記の二節)。**しかも賞与を下げた二本でも、測ったエントロピーの平均は 1.5 から 1.8 のまま下がっていない。** 賞与の重みが結果を動かしたことは測ってあるが、**「賞与が信号を圧倒していたので下げたら分布が締まった」という機序は、エントロピーの実測がそれを支持しない。この節に書いた 150 倍の算術は、いまも動機であって説明ではない。**

**アリーナ自身の実行間の床も、これで測れた。** 同じ 49 盤面の同じアームを、手書き戦術層の下で回した七つの実行(l3・o1・p1・p2・p3・p4・f3)で測ると、`script` が -0.0040 / -0.0110 / -0.0034 / -0.0063 / -0.0063 / -0.0060 / -0.0127、`concentrate` が +0.0706 / +0.0769 / +0.0774 / +0.0762 / +0.0731 / +0.0667 / +0.0826 である。**実行をまたぐ幅は `script` で 0.0093、`concentrate` で 0.0159 で、集中の奪取数は 21 / 21 / 18 / 19 / 18 / 18 / 21、梯子の奪取数は 7 / 5 / 5 / 6 / 5 / 5 / 5 である。** エンジンが再現しないことの帰結であり、交戦アリーナの ±0.02 の床に対応する量である。**同じアームの二つの実行の差が 0.016 未満なら、それは方策についての数字ではない。** **この床は手書き戦術層の下のものである。凍結戦術層の下は別の計器なので、この七つと同じ列には並べられない。**

## 決定の頻度を粗くする道は外れた

**作戦の決定周期をエージェントの既定 2000 ミリ秒から 10000 ミリ秒へ粗くして、同じ模倣から同じ種 51001 で 100 エピソード鍛えた**(`tools/macos/learn-run.sh --operational 10000`、`ops_train --opening 1 --credit region --warmup 5`、エントロピー賞与は既定の 0.002、`local/ops-train-p2.log`)。**問うていたのは一つで、p1 が配置を決められないことと訓練中にエントロピーが上がることが、決定の頻度の関数かどうかである。** 10000 ミリ秒では 1 部隊が 1 エピソードに 30 回しか決定しないので、エントロピー賞与が独立な結果 1 つに対して掛かる倍率が 5 分の 1 になる。種 80001 の同じ 49 盤面で測った(`local/ops-arms-p2-80001.jsonl`)。

## 切り出しを広げた世代が、梯子を大きく上回り集中と並んだ

**三つの所見がある。**

**一つ、これはこの計画で手書き層を最も大きく上回った学習方策である。** 前の世代の梯子超えは直した計器で -0.0132(0 を含む)から -0.0632 まで縮んでいた。**それが -0.1306 に戻り、しかも計器は締まったままである。**

**二つ、「気を変える頻度が点数を説明する」は反証された。** e1 は用務の長さ 16.1 決定と、この記録のどの層よりも短く気を変えるのに、どの層よりも強い。**長さと点数が同時に動いた実行が三つあることは測定だが、そこから長さが原因だと読むことはこの一つで潰れる**([測った。churn である](#エピソード記録に一欄足した))。**したがって「気を変えることに値段を付ける」という直し方は、根拠を失った。** 値段を付ける実装はしていない。

**三つ、梯子が優先度のある地面を名指す割合の低さが、初めて三つのアームの並びとして見えた。** 44 対 86 対 100 パーセントであり、**得点の並びは 0.002 対 0.133 対 0.116 である。** これが手書きの梯子に優先度の関門を入れさせた変更であり([../system/03-script-policy.md](../system/03-script-policy.md))、**その関門が何点ぶんかは `spread` アームとの対で測る。走らせている。**

## 優先度を関門にする直しは、41508 決定のうち 1 決定しか変えなかった

**梯子が優先度のある地面を決定の 44 パーセントでしか名指していないという診断に対して、最初に入れた直しは関門であった**——各ドクトリンの候補を優先度のある領域だけに絞り、行軍・混雑・資源・脅威はその内側で順位を付ける。**種 84001 の 73 盤面、4 アーム同一実行で測った**(`local/ops-gate-84001.log`。下の戦術層は e1 と同じ凍結層)。

| アーム | 単独 | 優先地を名指した決定 | 用務の長さ |
| --- | --- | --- | --- |
| `script`(関門あり) | +0.0187 ± 0.0192 | **18333 / 41508 = 44 パーセント** | 116.3 |
| `narrow`(関門なし、当時の名は `spread`) | +0.0387 ± 0.0254 | **18332 / 41544 = 44 パーセント** | 124.8 |
| `concentrate` | +0.1293 ± 0.0342 | 100 パーセント | 107.6 |
| e1(学習) | +0.1031 ± 0.0333 | 87 パーセント | 16.4 |

**関門を入れた梯子と外した梯子は、41508 の決定のうち 1 決定しか違わない。** 点数の差(`script` − 関門なし = -0.0200 ± 0.0217)は 0 を含み、**そもそも同じ決定を下している二つのアームの差なので、これはこの計器の実行間の揺れの直接の読みである。**

**なぜ効かなかったかが、診断の意味を書き換えた。** 絞り込みは、候補にそもそも欲しがられた領域が入っている決定しか動かせない。**入っていれば梯子は既にそれを選んでいたか、選ばなかったとしてもそれは 1 決定ぶんしかなかった。すなわち「優先度のある地面を指していない 56 パーセント」は、割引が優先度を覆した決定ではなく、候補集合に欲しがられた領域が一つも無かった決定である。** ドクトリンの候補は「何を好むか」で書かれている——守備は自軍が保持し**資源を産む**領域、襲撃は保持しておらず**資源を産む**領域——ので、**収入を産まない係争点は、守れと言われても候補にならない。**

**そこで直しを逆向きにした。優先度は排除ではなく加入をする**——戦略層が重みを置いた領域は、そのドクトリンがそこで行動してよいなら候補に加わる([../system/03-script-policy.md](../system/03-script-policy.md))。**関門の版は残していない。1 決定しか変えないと測れたものを、二つ目の規則として並べておく理由が無いからである。** **加入の版の測定はまだ無い。**

**この実行はもう一つ、e1 の再現を持っている。** 別の種の 73 盤面で `script` − e1 = **-0.0844 ± 0.0325**、`concentrate` − e1 = +0.0262 ± 0.0329(0 を含む)である。**梯子超えは二つ目の測定種で再現し、集中と区別が付かないことも再現した。** 差の大きさは種 80001 の -0.1306 から縮んでいる。

## 加入の版も動かさなかった。そして計器が関門に落ちた

**逆向きに直した版**——欲しがられた領域を、ドクトリンの絞り込みが落としていても候補に加える——**を種 86001 の 186 盤面、4 アーム同一実行で測った**(`local/ops-admit-86001.log`)。

| アーム | 単独 | 優先地を名指した決定 |
| --- | --- | --- |
| `concentrate` | +0.1083 ± 0.0221 | 100 パーセント |
| e1(学習) | +0.1006 ± 0.0204 | 78 パーセント |
| `script`(加入あり) | **+0.0199 ± 0.0138** | **56622 / 109628 = 52 パーセント** |
| `narrow`(加入なし) | +0.0126 ± 0.0134 | **56654 / 109628 = 52 パーセント** |

**加入も、梯子が何を指すかを動かさなかった。** `script` − `narrow` = +0.0073 ± 0.0172 で 0 を含み、この差を主張するには約 2019 盤面が要る。

**動かなかった理由は、関門の版が動かなかった理由とは別である。** 加入は候補を増やすので、変えられる決定は必ず「欲しがられた領域へ移る」決定であり、割合は上がるはずだった。上がらなかったということは、**加えた領域が採点で勝っていない**ということである。守備の得点は `優先度 + 資源 × 0.15 + 脅威 × 0.3 − 行軍 − 混雑` であり、**優先度は 1 を超えないのに資源 4 の地面は 0.6 を持つ。** 係争点が収入を産まなければ、加入させても自陣が勝つ。**したがって次の候補は候補集合ではなく項の尺度である——優先度に対して資源と脅威の重みが大きすぎるかどうか。実装も測定も無い。**

**そしてこの実行は関門に落ちた。** `script` アームの自己対戦ゼロが +0.0199 ± 0.0138 で 0 を外し、実行自身が警告を出している。**同じ凍結戦術層(8 逸脱で鍛えた層)の下の自己対戦ゼロは三つの種で +0.0020(75 盤面)・+0.0187(73 盤面)・+0.0199(186 盤面)で、三つとも正、平均およそ +0.0135 である。** これは以前この記録が別の戦術層について書いた系統的な正の傾きとちょうど同じ形であり、**符号化の基準点を各側の自陣へ移して閉じたはずの問いが、新しい戦術層の下で開き直っている。**

**したがってこの節と前節の作戦アームの数字は、傾いた盤面の上のものである。** 盤面ごとに対にした差は両アームに共通する加法的な傾きを落とすので、`script` − `narrow` のような「ほぼ同じ決定を下す二つ」の対は読んでよいが、**単独の平均と、決定の異なるアームどうしの差は、傾きが二つのアームに違う効き方をしうる分だけ弱い。** **切り分けの実行を回している**——同じ種の同じ盤面を手書きの戦術層の下で取り直せば、盤面は種だけで決まるので違うのは戦った層だけになる。

## 傾きは盤面ではない。同じ盤面で戦った層だけを変えて分けた

**同じ種は同じ盤面を引くので、下の戦術層だけを差し替えれば違うのは戦った層だけになる。二つの種で両方向に取った。**

| 盤面 | 下の戦術層 | 自己対戦ゼロ |
| --- | --- | --- |
| 種 86001、186 盤面 | 8 逸脱の凍結層 | **+0.0199 ± 0.0138**(0 を外す) |
| 種 86001、186 盤面 | 手書きの梯子 | **+0.0027 ± 0.0064**(通る) |
| 種 88001、183 盤面 | 8 逸脱の凍結層 | +0.0066 ± 0.0126(通る) |
| 種 88001、183 盤面 | 手書きの梯子 | +0.0002 ± 0.0074(通る) |

**盤面は無罪である。** 同じ 186 盤面が、手書きの下では 0 から 2 標準誤差 0.0064 の内側にぴたりと収まり、凍結層の下では 0 を外す。**そして凍結層は傾けるだけでなく散らばりもおよそ倍にする**(2 標準誤差 0.0064・0.0074 に対して 0.0138・0.0126)。

**符号化は無罪である。** 訓練済みのパラメータ(`tactics-close2` と模倣の `tactics-bc4`)に、構築した鏡像盤面を両方の席から読ませると、**logits の差も価値の差も厳密に 0 である**(浮動小数の最終ビットまで一致)。特徴 58 個の最大の食い違いは 1.1e-16 で、これは同じ数である。**「網が点反射に対して不変でない」という以前の欠陥は、この層には無い。**

**したがって残る説明は二つで、どちらもまだ測っていない。** 一つ、**傾きがこの層に固有であること**——訓練が一方の席の状態分布に寄り、鏡の側がその分布の外に落ちる。二つ、**傾きが実行ごとの引きであること**——エンジンは再現しないので、同じ設定の二本目が同じ +0.0199 を出すとは限らない。**分けるために、傾きが測れている同じ 186 盤面の上で、模倣の層・第一世代・そして同じ層のもう一本を回している。**

## 二つの席は違う打ち方をしていた。ただし打ち方の違いは傾きと同じではない

**エピソード記録に、下の戦術層が両側でそれぞれ何を選んだかを足した。種 86001 の同じ 186 盤面で三本取った。**

| 下の層 | 自己対戦ゼロ(全実行をまとめ) | 席が最も食い違う逸脱 |
| --- | --- | --- |
| 手書きの梯子(2 本) | +0.0019 ± 0.0044 | `hold` を **0.9** ポイント |
| 模倣のみ bc4(1 本) | **+0.0168 ± 0.0127** | (この欄より前の実行) |
| 第一世代 close(2 本) | -0.0011 ± 0.0091 | `focus` を **14.1** ポイント |
| 第二世代 close2(3 本) | **+0.0163 ± 0.0071** | `focus` を **4.1** ポイント |

**機序は確かめられた。学習した層は、二つの席を違う打ち方で打っている。** 手書きの梯子の席差が 0.9 ポイントなのに対し、学習した二つは 4.1 と 14.1 ポイントである。**一つの方策が、互いの点反射である二つの盤面の上で、百万回規模の逸脱にわたって別の混合比を出している。** 符号化は両席で厳密に一致するので、これは渡すものの違いではなく、**渡す元の地面の違いが決定境界を跨いだこと**である。

**しかし席差の大きさは傾きの大きさではない。** 最も席差が大きい close(14.1 ポイント)は傾かず(-0.0011 ± 0.0091、2 本)、席差の小さい close2(4.1 ポイント)が傾く(+0.0163 ± 0.0071、3 本)。**違う打ち方をすることは必要条件であって十分条件ではない——効くのは、その違いが片方の席に有利かどうかである。**

**これは計器の選び方として使える所見である。** `close` は自己対戦ゼロを通し、しかも交戦アリーナの決闘では手書きの梯子を上回っている唯一の層である([03-tactics.md](03-tactics.md))。**傾かない計器と最良の戦い手が同じ一つのファイルである以上、この場に凍結すべき層はそれである。** e1 を鍛えて測ったのは close2 の下であり、その実行の傾き +0.0163 はすべてのアームに共通なので**対にした差からは落ちるが、単独の平均には乗っている。**

**併せて一つ、この場についての事実が出た。手書きの戦術層は、この場では逸脱の 95.9 パーセントが `hold` である。** 交戦アリーナでは同じ梯子が `close` を 49 パーセント選ぶ。**この場の部隊は大半の時間を接敵せずに行軍しているので、梯子の段はほとんど発火しない。** すなわちこれまでの作戦測定の下にいた「手書きの戦術層」は、実質的に**ほぼ常に `hold`** であった。

## 傾かない計器の上で取り直した——最大の差が出て、診断の指標そのものが否決された

**傾かない層(第一世代 `close`)を凍結し、教師の収集から鎖ごと取り直した**(e2。種 54001、150 エピソード)。**測定は訓練にも選択にも使っていない種 92001 の 148 盤面、4 アーム同一実行**(`local/ops-arms-e2-92001.log`)。

| アーム | 単独 | 対にした差 | 優先地を名指した決定 | 用務の長さ |
| --- | --- | --- | --- | --- |
| e2(学習) | **+0.1752 ± 0.0256** | `script` − e2 = **-0.1732 ± 0.0282** | **42 パーセント** | **2.2** |
| `concentrate` | +0.1066 ± 0.0253 | `script` − 集中 = -0.1046 ± 0.0271 | 100 パーセント | 106.3 |
| `script` | +0.0020 ± 0.0116 | — | 49 パーセント | 121.5 |
| `narrow` | -0.0057 ± 0.0121 | `script` − `narrow` = +0.0078 ± 0.0125 | 49 パーセント | 121.5 |

**関門は通った。** `script` アームは +0.0020 ± 0.0116 で 0 を含む。**傾かない層を選べば計器は傾かないという予測が、選んだ後に取った測定で当たっている。**

**四つの所見がある。**

**一つ、この計画で学習方策が手書き層を上回った最大の差である**(-0.1732)。**そして初めて、集中アームを区間つきで上回った**(`concentrate` − e2 = **-0.0686 ± 0.0321**、0 を外す)。それまでの三世代はどれも集中と区別が付かないか下だった。

**二つ、「優先度のある地面を名指す割合」は品質の指標ではない。否決する。** 最強のアームが **42 パーセント**で、梯子の 49 パーセントより**低い**。集中は 100 パーセントで二番手である。**この数はもともと手書き梯子への二つの直しを動機づけたものであり、その二つはどちらも点数を動かさなかった。いま、その数そのものが順位と逆を向いている。**

**三つ、気を変える頻度も品質の指標ではない。今度は極端な形で。** e2 の用務は **2.2 決定**であり、ほぼ毎周期に行き先を引き直している。**それでいて最強である。** 契約を「用務の単位」ではなく**舵**として使っており、設計が契約を仕事の単位と呼んでいることと、勝つ方策が実際にしていることは、この場では一致しない。

**四つ、加入は二つ目の実行でも測れなかった。** `script` − `narrow` は +0.0078 ± 0.0125 で、前の実行の +0.0073 ± 0.0172 と合わせて **+0.0076 ± 0.0101** である。**二本とも符号は同じで、区間は 0 を含む。** 加入は「収入を産まない地面を守れという命令に、守備部隊が答えられるようになる」という表現力の直しであって、点数の直しではない——**そしてその値段は、いまのところ 0 と区別が付かない。**

## 「長く鍛えるほど弱い」が三度目に出て、機序が報酬の中に見つかった

**傾かない計器の上で、e2 から 150 エピソード続けて e3 を作り、同じ盤面に並べた**(種 94001、155 盤面。`script` は -0.0088 ± 0.0117 で関門を通る)。

| アーム | 単独 | 優先地を名指した決定 | 最接近中央値 | どの円板にも入らなかった episode | 用務の長さ |
| --- | --- | --- | --- | --- | --- |
| e2(150 エピソード) | **+0.1597 ± 0.0243** | 47 パーセント | 253 | 25 / 155 | 2.2 |
| `concentrate` | +0.0869 ± 0.0264 | 100 パーセント | 247 | 21 / 155 | 105.7 |
| e3(さらに 150) | +0.0584 ± 0.0206 | **17 パーセント** | **348** | **64 / 155** | 3.3 |
| `script` | -0.0088 ± 0.0117 | 49 パーセント | 264 | 42 / 155 | 126.5 |

**e2 − e3 = +0.1013 ± 0.0297 で 0 を外す。** 前の二度(+0.0343 ± 0.0229、+0.0371 ± 0.0339)の三倍の大きさであり、今度は関門を通る計器の上である。**そして e3 は集中アームより下へ落ちた**(`concentrate` − e3 = +0.0285 ± 0.0281)。

**今度は機序が報酬の中に見つかった。** 周期ごとの支払いは「その部隊の数字の動き」であり、その数字は**契約が名指す領域**から読まれる。そして**優先度の無い領域は数字を動かさない**ので、無価値な地面を名指した部隊の数字は 0 になる。**契約の引き直しは無料である。**

**したがって、負けている円板の上にいる部隊は数字が負であり、無価値な領域を名指すだけで数字が 0 へ上がる——それは正の支払いとして払われる。層は、負けているものから立ち去ることに対して金を受け取る。** そのうえ周期ごとの支払いは最後の数字へ伸縮するので、**最後の領域を選ぶ者が総額を選び、それを選ぶのは層である。方策が自分の終端を選べる。**

**これは訓練が長いほど強くなる穴である。** 表の三つの欄——優先地を名指す割合 47 → 17、最接近 253 → 348、円板に一つも入らない episode 25 → 64——は、**層が採点される盤面から歩き去った**という一つのことを三通りに言っている。

**塞いだ。** 部隊の代金を、契約を一切読まない読みに変えた(`--credit board`、既定)——**採点されるすべての円板について、その部隊の生存ユニットが説明する分の和**である。どこに立っていようと、どんな用務を与えられていようと同じ数字が出るので、**領域の選び方で代金を上げ下げできず、逃げ込む先が無い**([../system/04-learning.md](../system/04-learning.md))。**試験が、同じ部隊の同じ配置を四通りの用務(および用務なし)で読ませて、代金が動かないことを押さえている。** **この読みで鍛えた層はまだ無い。**

## 穴を塞いだら、長く鍛えても崩れなくなった

**契約を読まない代金(`--credit board`)で、模倣から 150 エピソード、そこからさらに 150 と鍛え、同じ盤面に並べた**(種 96001、152 盤面。`script` は +0.0045 ± 0.0125 で関門を通る)。**前の実行と計器も長さも同じなので、答えが一つ一つ対応する。**

| 代金の読み | 150 エピソード | さらに 150 | 二世代の差 |
| --- | --- | --- | --- |
| 契約の領域から読む(旧) | +0.1597 | +0.0584 | **+0.1013 ± 0.0297、0 を外す** |
| 契約を読まない(新) | +0.1398 | **+0.1508** | **-0.0111 ± 0.0285、0 を含む** |

**崩れは消えた。** 差は +0.1013 から -0.0111 へ動いており、これはどちらの区間よりも大きい移動である。**点推定の符号も裏返り、長いほうがわずかに上にいる。**

**ただし「長いほど強い」が示せたわけではない。** 差は 0 を含み、この大きさを主張するには約 1969 盤面が要る。**言えるのは「長く鍛えると弱くなる」が止まったことであって、「長く鍛えると強くなる」ではない。**

**両世代とも梯子と集中の両方を区間つきで上回る。**

| 対にした差 | b1(150) | b2(300) |
| --- | --- | --- |
| `script` − 層 | -0.1353 ± 0.0279 | -0.1463 ± 0.0247 |
| `concentrate` − 層 | -0.0414 ± 0.0296 | -0.0525 ± 0.0247 |

**そして診断欄の読み方が一つ変わった。** 新しい代金では**部隊がどの領域を名指すかは支払いと無関係**なので、「優先度のある地面を名指した割合」はもう層の振る舞いの尺度ではない——層は名指した場所ではなく**ユニットが立っている場所**で払われる。その割合は 55 から 33 パーセントへ落ちているが、**点数は落ちていない**(+0.1398 → +0.1508)。物理的な欄である最接近は 236 から 307 へ伸びており、これも点数を動かしていない。**旧い代金では同じ向きの動き(47 → 17、253 → 348)が 0.10 の点数を持ち去っていた。**

## 凍結した戦術層の下でこの場を回す経路

**`ops_run` と `ops_train` の `--tactics` が、訓練済みの戦術層を盤面の両側の下に凍結して置く。** 層は確率最大で読まれ、rollout を渡されないので何も記録しない。**両側なのは、片側だけを訓練済みにすると二つの側が交換可能でなくなり、script アームのプールした平均が 0 でなければならない理由そのものが消えるからである。** journal はその層の名前(パラメータ本体の SHA-256)を持ち、`ops_compare` は違う戦術層どうしの journal を対にしない。

**渡した実行は別の計器である。** 同じ層を両側に置くことは鏡が要求する最低限であって保証ではない——相手側の盤面は所有の旗を裏返して作るのであって座標を反射して作るのではないので、二つの側には「意味は合同だが場所は合同でない」入力に同じ関数が当たる。距離と強さを読む手書きの梯子はどちらでも同じ答えを返すが、網はそうである必要が無い。**したがって、その script アームが自己対戦ゼロを通り直すまで、その下で測った数字は読まない。**

**この警告は当たり、当たり方は「たまに傾く」ではなかった。** 取り直した自己対戦ゼロは五つの種で八つ取ってあり、**八つとも正、五つの種も五つとも正で、平均はおよそ +0.012 である。区間を外して関門に落ちるのは種 90001 と 93001 の二つで、残りの六つは通る。** **そしてその種 90001 の同じ 52 盤面を手書きの戦術層の下で回すと関門を通るので、傾きを作っているのは抽選ではなく凍結した網である**(下記)。

**そして主結果を取り直すべき計器は、いまや自陣基準の凍結層の上のものである。** 方位の基準は脅威の重心から各側の自陣へ移り、このアリーナはそれを**各側の staging point**(盤面の中心についての厳密な反射の対)として層に渡すようになった。**その計器の関門は三つの種とも通っている**(上の表)。**旧符号化の凍結層の下で取られた四つの数字は、二世代前の計器の上に立ったままである。**

## 乱入は最初から効いていた——記録が捨てていただけだった

**「乱入が発火していない」と二度書いたが、それが誤りだった。** 欠陥はセッションが試合を閉じる順序にあり、**乱入の記録が方策を片付けた後に取られていた**ので、読む相手がおらず毎回空が書かれていた。成績の内訳は片付けの前に読まれていたので正しい。

**測って確かめた。** 乱入者の契約書き換えの確率を一時的に 1 に上げて 1 エピソード回すと、**44 周期のうち 43 周期で契約が実際に書き換えられ**、方策が数えた介入回数もその実行の記録に載った。**それでも同じ記録の乱入欄は空だった。** 方策が片付けられる前の `close` は同じログをその場で読むので、**学習が乱入された部隊を信号から外す処理は効いていた。** 壊れていたのはエピソード記録の監査欄だけである。

**したがって `--intrude` を付けた実行は実は乱入込みであり、乱入者は両アームへ一様に付くので差の比較はそのまま成り立つ。** 直したあとの実測では、難易度 -2 の 300 秒で 160 エピソードのうち 154 で部隊が触られ、事象は 746、1 エピソードあたり平均 2.5 部隊・5 介入。900 秒では 64 エピソードすべてで触られ、平均 3.5 部隊・17 介入である。**乱入込みでも乱入なしでも、作戦層は梯子と互角という結論は動かない。**

**領域行に「この側の部隊が何隊そこへ契約しているか」を足した**([../system/04-learning.md](../system/04-learning.md))。**それまで領域行が運んでいたのは「いま訊かれている部隊がどこへ行くか」だけで、隣の部隊がどこへ送られたかはどの欄にも入っていなかった。部隊ごとの報酬も協調を値付けしないので、状態にも終端にも配分が現れていなかった。** 切り出しが 424 から 448 次元になり、それ以前の作戦層のパラメータと教師はすべて刻印で拒まれる(四つのファイルで確認した)ので、**教師の収集から鎖ごと取り直した**——凍結層は四つの比較が選んだ `close` 第一世代、代金は穴を塞いだ `board`、150 エピソード、訓練種 70001。**測定は種 110001 の 183 盤面**(`local/ops-arms-committed-110001.jsonl`)。

| --- | --- | --- | --- | --- | --- |

**三つ、それは前の切り出しの世代より弱い。** 同じ凍結層の下で取った前の実行(種 108001)では、150 エピソードの e2 と 600 の b3 と 900 の b4 が **`concentrate` を -0.0727 / -0.0639 / -0.0719 で区間つきに上回っていた。** **配分が見える切り出しの世代は、そこへ届いていない。**

**したがってこの一巡が言えるのは「150 エピソードでは前の切り出しに届かない」までである。** 欄が増えれば当てはめる関数も増えるので、**同じ長さで届かないことは欄が無駄であることと同じではない。延長した実行を回している。**

**限界を同じ強さで書く。** 第一、**一つの測定種の上の結果である。** 第二、**前の切り出しとの比較は依然として手書きアームを経由しており**(448 次元と 424 次元は同じ実行のアームになれない)、**集中アームとの対差で見ても区間は重なる。「同じ水準に達した」以上のことは言えない。** 第三、**集めることの否決は「この層は集めていない」ではない**——72 パーセントは梯子の 87 より低く、集中の 100 より低い。**言えるのは、その割合が三世代の順位を作らないことである。**

## この場の最大の優位を試合へ持って行った——乗ったのは集中のほうで、学習層は集中に負ける

**構築作戦アリーナでこの計画の最大の梯子超え(-0.2041)を出し、集中アームをも -0.0761 で上回った 600 エピソードの世代を、フル試合に置いた。** 条件は集中アームの +0.065 を出した実行と同じにしてある——マップ Lake、打ち切り 300 秒、内蔵 AI 一体(難易度 1)、乱入込み、アームごと 96 試合(`local/eval-ops-m3.jsonl`)。**二つの数字を並べて読めるようにするためである。**

**鎖は四本で、学習した鎖は自分が鍛えられた戦術層を運ぶ。そしてその戦術層だけの鎖が三本目に立っている**——四本目との差が作戦層だけの寄与であり、この記録がこれまで一度も分けられなかったものである。

**一つ、順位が入れ替わる。これがこの実行のいちばん強い読みである。** アリーナでは学習層が集中アームを -0.0761 ± 0.0277 で上回っていた。**試合では符号が逆を向き、六つの対のうち唯一これだけが分解する**(+0.087、要 58 対に対し 96 対)。**アリーナの順位(学習層 > 集中 > 梯子)は、試合では(集中 > 梯子 ≒ 学習した鎖)になる。**

**二つ、それでも「アリーナの技能は試合へ乗る」は取り下がらない。乗るものと乗らないものが分かれただけである。** 集中アームは同じ向き・同じ桁で再現した(+0.047、前は +0.065)。**ただしこの実行だけでは分解しない**(要 172 対)ので、集中の乗り移りはいまも前の実行と合わせて初めて言える。

**三つ、作戦層だけの寄与は 0 を含む。** `tactics-close` を下に敷いた二本の差は +0.029 で、分解するには 471 対が要る。**したがって言えるのは「梯子を上回るという主張が試合で支持されない」までであって、「この層は害である」ではない。** **点推定は三つとも同じ向きに並ぶ**(梯子より 0.040 下、凍結層だけの鎖より 0.029 下、集中より 0.087 下)**が、0 を外すのは集中との対だけである。**

**四つ、機序の徴候が二つ揃っている。** 契約の達成率は 0.12 で、他の三本(0.31 から 0.42)の三分の一である。**アリーナで測った「用務の長さ 8.4 決定に対し梯子 123.7」が、そのまま試合に出ている。** そして経済成分は -0.407 で四本の最下位である。**集中アームは地面を取ることで経済を上流から改善して -0.327 に立ち、気を変え続ける層は契約を捨て続けて -0.407 まで落ちる。** **アリーナは経済を構成で取り除いた場なので、そこで報われた技能が試合では罰されるという形になる。**

**五つ、戦術層の寄与は前の実行を再現した。** 凍結層だけの鎖と手書きの鎖の差は +0.011 で、区別するには 2,910 対が要る。**別の実行で三層とも学習した鎖について測った +0.011 と同じ値である。** **戦術層が試合の採点に対して小さいことは、これで二つの実行の上にある。**

**限界を同じ強さで書く。** 第一、**一つの地図・一つの長さ・一つの実行である。** 第二、**フル試合は同じ種で再現しないので、これは対にした差ではなく独立な標本の差である。** 第三、**分解したのは六つの対のうち一つだけで、残る五つはどれも点推定である。** 第四、**測ったのはこの場の最良の一世代であって、系統ではない**——150 と 300 エピソードの世代を試合に置いた実行は無いので、「長く鍛えるほど試合で悪くなる」という形の読みはここからは出ない。**アリーナの長さの梯子が試合でどちらを向くかは、掃いていない。**

## 二つの説明を測って、二つとも落ちた

**「アリーナの優位が試合へ乗らない」ことの説明として、機序の徴候から二つの候補が立った。どちらも測って落ちた。** 記録するのは、落ちた説明を書き残さなければ同じ道を二度歩くからである。

### 一つ目——地平の一瞬しか払っていないこと

**この場は地平の一枚の盤だけを読んでいた。** エピソードの目的は「時計が止まったときにユニットがどこに立っているか」がすべてで、その手前の 300 秒には一切値段が付かない。**最初の 1 分で disc を取ってそのまま保った用務と、最後の 1 秒に空の disc へ歩み入った用務は同じ額を受け取り、二つの係争点の間を往復し続けても代価は 0 である。** 試合における地面は収入の上流なので、これは試合には無い時計だった。**用務が 8.4 決定しか続かない層が試合で契約達成率 0.12 を出したことの説明として、形が合っていた。**

**そこで同じ disc を毎周期読み、立っていた時間で重み付けた平均(`side_tenure`)を足し、どちらを払う実行でも両方を journal に書くようにした。** 尺度は地平の読みと同じで、各周期の読みが反対称なのでその平均も反対称であり、**自己対戦ゼロの関門はそのまま成立する。**

**結果:順位は入れ替わらない。** 種 120001、Hills、`tactics-close` を両側の下に凍結、44 盤面。

| 読み | `script` | `concentrate` | 学習層 (600 エピソードの世代) |
| --- | --- | --- | --- |
| 地平の一枚 | +0.0033 ± 0.0223 | +0.1108 ± 0.0455 | +0.2086 ± 0.0470 |
| 保持時間の平均 | +0.0062 ± 0.0178 | +0.1123 ± 0.0417 | +0.1822 ± 0.0349 |

**対にした差も向きが同じである**(`script` − 学習層は -0.2046 ± 0.0547 と -0.1717 ± 0.0423、`concentrate` − 学習層は -0.0988 ± 0.0706 と -0.0709 ± 0.0536)。**学習層の優位は保持時間の読みでわずかに縮むが、六つの対のどれも順位を変えない。** すなわち**この層は、自分が地平に立っている地面をおおむね episode を通して保っている。気を変え続けることの代価は、この場では成績に出ていない。** **関門は両方の読みで通る。**

**この読みは残した。** 落ちたのは「これが試合への非転移の説明である」という仮説であって、読みそのものではない——地平の一瞬しか払わない場が、時間を値付けできないことは変わらない。

### 二つ目——優先度が採点される地面を名指していたこと

**この場は 9 領域のうち採点される 4 枚だけに 0.3 から 1.0 を置き、残る 5 枚を 0 にしていた。すなわち `優先度 > 0` は「払われる地面」の雑音の無いラベルだった。** **試合ではそうではない**——実際に集めた試合の 27,000 本の有効な領域行で `region.priority` を測ると、最小 0.08・中央値 0.33・平均 0.46 で、**0 の行は 0.0 パーセントである。** 「優先度が無い領域は捨てる」という門を学んだ層は、この場では 9 行中 5 行で発火し、試合では 24 行中 0 行で発火する門を学んだことになる。

**そこで、反射が対にできる採点外の領域にも 0.1 から 0.6 を配り、係争の帯と重ねた。** 採点に使う辞書と層に渡す辞書を分けたので、side score も関門も診断の `on_priority` も意味を変えない。

**結果:学習層の成績はラベルに依存していなかった。** 同じ 40 から 44 盤面の上で、旧い引きと密な引きを対にする。

| アーム | 旧 − 密(地平) | 旧 − 密(保持時間) | 用務の長さ 旧 → 密 | 優先地率 旧 → 密 |
| --- | --- | --- | --- | --- |
| `script` | -0.0109 ± 0.0216 | -0.0040 ± 0.0183 | 128.4 → 125.0 | 52 → 52 % |
| `concentrate` | **-0.0524 ± 0.0351** | **-0.0345 ± 0.0265** | 99.3 → 116.2 | 100 → 100 % |
| 学習層 | -0.0061 ± 0.0620 | -0.0042 ± 0.0371 | 6.1 → 6.0 | 81 → 79 % |

**学習層は動かない**(分解するには 3,000 盤面以上が要る)。**動いたのは集中アームだけで、しかも密な引きのほうが良い。** 集中アームは自分の選び方を変えていない(優先地率は 100 パーセントのまま、すなわち採点される地面を選び続けている)ので、**動いたのは相手側の手書きの梯子のほうである**——重みの付いた領域が増えると梯子は薄く広がり、一点へ集める相手にそのぶん強く負ける。**自己対戦は変わらない**(両側が同じだけ変わるので当然である)。

**この引きも残した。** 落ちたのは説明であって、直しではない——**この場が採点される地面をラベルで教えていたことは、試合には無い情報を教えていたことに変わりはない。**

### 残っている説明

**代金が、成功した突撃にちょうど 0 を払っていたことである**([04-learning.md](../system/04-learning.md))。上の二世代はどちらもその代金の下で鍛えられている。**シェアは 1 で飽和するので、一抜きの反実仮想では、守備が倒れた瞬間に集中した部隊の全員がちょうど 0 を受け取る。** 実測で、優先度 1 の disc に 4 部隊が集中すると、garrison が生きている間は各 +0.0500(side score +0.300)、倒した瞬間に各 **+0.0000**(side score +0.500)である。**削っている間だけ払われ、倒すと払われない。** side score は体力加重なので、瀕死の守備はほとんど地面を争わない——**すなわち「倒さずに削り切って立っている」ことがこの場では最適に近く、試合では守備が生きている限り撃ち返してくる。**

**代金は直した。** 部隊は、その円板を**この側の配備が動かした分**のうち、そこに残している値打ちに比例した持ち分を受け取る。起点は**この側の staged 部隊を一つも入れずに読んだ円板**なので、自陣の garrison は起点の内側にあり、**要らなかった守備はいまも 0 を払う**(開始基準点が導入された理由がそのまま残る)。抜いた結果が空になる場合は中立の半分ではなく **disc の開始所有**で読む。同じ三枚は、4 部隊集中で各 +0.2000 → +0.2500、単独で +0.7500 → +1.0000、自陣 disc への余分な守備で +0.0000 を払う。**倒すことが削ることより高くなり、集まることが罰されなくなった。**

**そしてその直しの中に、同じ欠陥が浮動小数点の形で戻っていた。** 起点を「この側の値打ち − 部隊が持っている分」と**引き算**で出していたが、二つの和は別々のまとめ方で積まれる——一方は盤面の行を順に足す走り、もう一方は部隊ごとに足してから足し合わせたもの——ので最後の桁に残差が残る。**配備が disc を取り切った盤面では差はちょうど 0 になるはずが、残差どうしの割り算になって起点が 1.0 になり、取り切った部隊全員がちょうど 0 を受け取る。** 条件は二つで、どちらも狭い:**2 部隊以上でしか起きず**(1 部隊なら二つのまとめ方が一致する)、**端数の体力が要る**(満タンのユニットだけなら値打ちは価格そのもので、二つの和は厳密に一致する)。**そして発火するのは disc が敵側から空になった盤面、すなわち突撃が成功した瞬間だけである。** 2 部隊以上を持つ 309 盤面のうち 74 枚で発火した。**残っているユニットを素直に足す形に直した。** 回帰試験は端数の体力と多部隊で組んであり、旧形では全員 0、新形では優先度まるごとを出す。

**この場は他にも三つ直っている**([04-learning.md](../system/04-learning.md))。**staged 部隊が引かれたドクトリンを名乗るようになった**——継いだ記録法は部隊の最初のユニットからドクトリンを引き直しており、`doctrine_for` は戦車を GARRISON に送るので、**4 部隊のうち VANGUARD の 2 部隊がどちらも GARRISON として記録され、DEFEND と ESCORT しか出されていなかった。地面を取れるかを測る場で、である。** 試合は逆に、編成層が戦う編成から先に組んで ATTACK を持たせる。**姿勢を盤面ごとに引くようになった**——`ARM` に固定していたので切り出しの姿勢 5 特徴は 4 つが常に 0 で、`offensive` と許容総損害を姿勢と無関係に引いていたので**試合が出せない命令の組み合わせ**になっていた。**そして作戦の教師は、盤面の採点が選んだ領域ではなく、規則が落ち着いた先(実際に出る契約)を書くようになった**——その覆しは梯子の用務が 127 決定続く理由そのものなので、**決定の大多数でラベルが違っていた。** 教師の刻印にその書き換えを歩かせたので、**それ以前に集めた作戦の教師はいま拒まれる。**

**直した場の上で鍛え直した世代の測定は、これからである。**
