# 分かっていないことと、次に試すこと

**測ってあることは [03-tactics.md](03-tactics.md)、[04-operations.md](04-operations.md)、[05-strategy.md](05-strategy.md) にある。この文書は、そこから残った問いだけを書く。** 順序は好みではなく、測定から導く。

## いま在るパラメータと教師はすべて退役した。三層とも取り直しである

**三層の学習側をまとめて監査し、見つかった欠陥を全部直した。六つの digest——三層の符号化と三層の規則——がすべて動いたので、既存の `local/*.pt` と教師は一つ残らず刻印で拒まれる。設計どおりの退役である。** **したがって、この文書の表と箇条書きが引いている学習層の測定は、一つ残らず退役した計器の上のものである。数字は取り下げない。取られた時点では、その計器の上で正しく測られたものである。**

| 何 | いまの値 |
| --- | --- |
| 切り出しの大きさ | 戦術 58 / 戦略 30 / 作戦 448(作戦網の入力は部隊の one-hot 8 を足して 456) |
| パラメータ | 戦術 8,521 / 作戦 130,783 / 戦略 6,534 |
| 符号化 digest | 戦術 `03b6b4de8f2232f8` / 戦略 `cf7701a2d9fb6001` / 作戦 `2bf345d9ebb34bbb` |
| 規則 digest | tactics `0ca9cef9b68e7a2d` / operations `9c92b0e780638340` / strategy `79b451cf433fe00e` |

**そのうち計器そのものを動かしたのは五つである。**

- **刻印の走査に穴があった。** digest は最外側の code object の名前しか歩いていなかったので、**内包表記・generator 式・lambda・入れ子 def の中からしか読まれない定数と補助は、値ごと digest に入っていなかった**(例:被弾中の部隊を数える generator 式の中でしか読まれない `RECENT_HIT_MS`)。**その種の定数はいくら書き換えても刻印が動かず、ファイルは退役しなかった。** いまは再帰で集める。
- **戦術の露出特徴が敵の位置を測っていなかった。** `ours_in_their_reach` が比べていたのは、自軍各員から敵ではなく自分の側の中心までの距離と、敵の最長射程である。敵がどこにいても値が動かず、測っていたのは自軍の散らばりだった。いまは両方ともユニット対ユニットで、射手ごとの射程と空地の別で数える([03-tactics.md](03-tactics.md))。
- **交戦アリーナの二つのアームは、同じ交戦を引いていなかった。** 地点の抽選は盤面を見るので消費する乱数量が候補数によって変わり、**同じ種の二つのアームがエピソードの途中で乱数列を分岐させていた。それでも対にする鍵は(インスタンス, 何巡目, 何件目)なので、別々の交戦どうしが引き算されていた。** いまは地点だけを第二の乱数列から引く。**予算・不均衡・角度・戦力は対になり、置かれる場所そのものは盤面依存なので依然として対にできない**([03-tactics.md](03-tactics.md))。
- **構築作戦アリーナは部隊の状況・散らばり・損害を一度も折り返していなかった**(全周期・全部隊・両側が ACTIVE・0・0)。**手書きの作戦梯子は状況でしか再タスク付けしないので、この場では一度も再タスク付けせず、各部隊に契約を一本出して地平まで持っていた**([04-operations.md](04-operations.md))。
- **戦略の切り出しに、この層が払われている当の量が無かった。** 終端(試合の採点)も整形(ポテンシャル)も「立っているもの全部どうし」でできているのに、29 特徴のどれもそれを持っていなかった。`standing_edge` を足して 30 になった。**同時に `income_growth` が試合の立ち上がりで潰れていた**——窓の最古が 0 の周期で「急伸中」と「完全な頭打ち」が同じ 0.0 になっていた([05-strategy.md](05-strategy.md))。

**残る五つは、計器ではなく信号と道具の側である。** 一つ、**試合の作戦報酬が契約の引き直しで台帳を再基準化していた**(上がったところで引き直せば下げ幅を払わずに済む経路)。二つ、**戦略報酬の終端が割引 1 未満で経路依存の残差を残していた**——いまは試合の収益が「採点 − 開始ポテンシャル」で、どの割引でも厳密に伸縮する。三つ、**戦術層の四つの終端のうち全滅が試合で一度も発火していなかった**——編成層は最後のユニットが死んだその周期に部隊を退役させるので、戦術層は「在籍が空の部隊」を一度も見られなかった。四つ、**`--width` で既定以外の幅に鍛えた網が、評価のアームにも `--frozen` にも載らなかった。** 五つ、**盤面 id 0 が「欄が無い」と読まれ、対の照合が単一アームにしか正しくない導出へ落ちていた**(盤面 id はアリーナの種そのもので、記録に残っている実行の種はどれも 0 ではない。**退役する照合は無い**)。

**そして二つの拒否を足した。** **`--without` は梯子が実際に答えうる逸脱しか受け付けない**——`hold` は梯子の落ち先であって枝ではなく、`close` は梯子から取り除かれて行動空間にだけ残っているので、どちらを withhold しても決定は一つも変わらず、**基準線を基準線と比べた 0 を「その逸脱の寄与」として報告することになる**(どちらも `--pin` では測れる)。**戦略層の学習実行は相手 1 体以外を拒む**——試合の採点は最強の相手一人と比べるのに、この層のポテンシャルは戦線報告経由で「見えている敵の総和」しか読めないからである。**評価の実行は制限しない。この記録の戦略学習実行はすべて内蔵 AI 一体なので、退役する測定は無い。**

**したがって、この文書に残っているどの問いよりも先に、三層とも直した計器の上で取り直すことがある。** それは新しい問いではなく、**既に答えたと書いてある問いを、答えられる計器の上で訊き直すことである。** **下の [作戦層](#作戦層) が「これがいちばん上である」と書いている「手書きの作戦梯子を集中させること」は、実装していないのでそのまま残る**——入れ替えると記録されたすべての数字の基準線が動くという但し書きに、いまは「どのみち全部取り直しである」が重なるだけである。

**取り直しの一巡目は回してある。三層とも教師から組み直し、短く鍛え、測った。** 交戦アリーナは自分の関門を通った(梯子どうしの基準線が交戦 318 件で +0.0021)。**構築作戦アリーナは通らなかった**——梯子どうしの側の点数が 35 盤面で +0.0438 ± 0.0369 で 0 を外し、実行器が正しく警告した。**戦略層は凍結した二層の下で通り、相手が本当に一人になった。** どの実行も 3 から 6 エピソードなので、強さについては何も言っていない([03-tactics.md](03-tactics.md)、[04-operations.md](04-operations.md)、[05-strategy.md](05-strategy.md))。

**そこから新しい問いが一つ出た。構築作戦アリーナはなぜ傾いたのか。** 候補は二つあり、この実行では分けられない。**盤面が 35 枚しかないこと**(この場は種によって関門を落とすことが以前にもあった)と、**折り返しを直したこと自体が場を変えたこと**——梯子が 7.8 決定ごとに再タスク付けを始め、部隊行の散らばり・損害・状況が定数でなくなった。**分けるには、盤面を増やした実行と、種を変えた実行が要る。この場の上で層を測る前に、これが先である。**

- **手書きの層より強い方策が作れるのかどうか。** 選択に使っていない種の上では、模倣も、三つの設定も、それを二度延長したものも、歩幅を上げた鎖も、macOS で独立に学習した層も、梯子を上回っていない。**候補の点推定を 0 から外すには、いまのおよそ 4 倍の交戦が要る。** それを取るなら、候補選びにも確かめにも使っていない新しい種で取る。**上回った方策は無いが、下回った方策は初めて区間つきで出た**——既定の自己対戦で鍛えた層が -0.0402 ± 0.0214 で、原因は訓練相手だった([03-tactics.md](03-tactics.md))。
- **梯子と同水準で止まる理由。信号の到達ではない。** 延長実行の全 478 更新・決定 748,358 段を数えると、94.6 パーセントが終端の届く用務にあり、優位ちょうど 0 は 0.081 パーセントしか無い。**残る候補は、行動空間、特徴、そして交戦アリーナが与える盤面の幅である。どれも測っていない。**
- **そのうち「盤面の幅」は掃いて閉じた**(上記)。**以下は掃く前に書いた見立てであり、測定は逆であった。** 両軍を置く間隔はアリーナの定数だったので、**それを動かした実行が一つも無いのは選択ではなく、動かす口が無かったからである。** いまは `--separation` で渡せて、エピソード記録が間隔・膠着秒・戦力比の下限・払った読みを書き留めるので、別々の間隔で取った実行が同じ計器として対にされることもない。**なぜこれが第一候補なのかは算術である**——既定の 250 はエンジンが二つの戦力を止める「見えるが届かない」隙間の内側に置いてあり、それは交戦を始めさせるための値であって、**departures が決められる幅を最小にする値でもある。** 両側が最初の周期から撃ち合っている盤面では、引くか集中するかの選択が動かせる余地は小さい。**間隔を広げると、その隙間で止まったまま何もしない交戦が増える**(700 で測ったとき 4 分の 3 がそうなった)ので、**間隔と行動空間は一つの問いである**:いまの 7 つには「詰める」が無く、外から始まる交戦では引くか止まるかしか選べない。**掃いていない。**
- **不変性を情報と引き換えに買ったところは、買い戻して訓練と決闘の両方で測ってある。下がりは消え、上回ってはいない。** 目標への方位を地図の軸から脅威の重心へ移したことで符号化は点反射に対して不変になったが、**脅威の無い部隊——係争点へ行軍している部隊がまさにそれ——は方向を一切持たなくなった。** その符号化で鍛え直した層は梯子に対して -0.0398 ± 0.0228 と 0 を外して下回り、旧符号化の同条件(-0.0042 ± 0.0224)は互角だった([03-tactics.md](03-tactics.md))。**基準はいま自陣から外へ向かう向きにあり、下がりは戻った**(`target_ahead_of_home`・`target_abeam_of_home`)。**同じ設定で鍛え直した層は +0.0036 ± 0.0226 で 0 を含む。点反射が自陣と敵陣を入れ替えるので不変性は保たれ、撃たれていない部隊も方向を持ち、前後の項は「外へ送られたのか自陣へ戻されたのか」を言う。基準点は側ごとに置かなければならず、それは視界を組む側の責務である——交戦アリーナは各側の出撃地点を、作戦アリーナは各側の staging point を入れる。両側で共有すると不変性はその場で壊れ、それを含めて四つの試験で固定してある。** **決闘も取った。** 選択に使っていない種 774001 で凍結して測ると、確率最大で +0.0057 ± 0.0213、抽選で -0.0085 ± 0.0219、基準線は +0.0045 で読める——**訓練中の成績と揃って、梯子と区別が付かない。****そして「符号化が差を作った」ことそのものは、三本になっても区間つきでは言えていない**——脅威基準と自陣基準の差は 0.0434、その区間は約 ±0.032 で、床の ±0.02 が別に乗る。**分けるには、同じ出発点から二つの符号化で鍛えた対を、決闘の基準線を引いて測る実行が要る。**
- **候補が一行の規則より上かどうか。** 4 アームの実行を一度走らせて「上に見えるが交戦 500 件では言えない」まで来た。**`withdraw` 固定がどこにいるかは三つの種で割れたままである。**
- **訓練済みの戦術層を盤面の片側だけに置く経路が無い。** 構築作戦アリーナの `--tactics` は層を両側の下に置くので side score が両側で反対称になって層の強さが打ち消し合い、**下の層を差し替えた 3 実行はどれも 0 を含んだ。成績で戦術層を測ることが、この場では構造で閉じている**([03-tactics.md](03-tactics.md))。**片側だけに置く経路を作れば side score で測れるが、それは `script` アームのプールした平均が 0 でなければならない理由——二つの側が交換可能であること——を手放すことでもある。** **代わりに何を関門にするのかを決めないまま作ってはならない。** 決闘のように相手側を手書きに固定した基準線アームを同じ実行で取る、という道はあるが、**設計も実装も無い。**
- **体力の読みでの幅。この問いは半分閉じた。** この記録の天井の数字はほとんどが疎な読みの上のものだが、**体力の読みでの幅は二つの種で取ってある**——hold が -0.0257(種 20260723)と -0.0130(20260725)、withdraw が -0.0145 と -0.0227 である(後者は残っている journal から読み直した)。**種による散らばりはその差と同じ程度あるが、四つの読みはすべて 0.013 から 0.026 の帯に収まる。** **残っているのは幅の値ではなく、その帯が測定の床(±0.02)とほぼ同じであることの帰結**——[戦術層](#戦術層) の最初の項に書いたとおり、この場では梯子の上に残っている余地が床より小さい。
- **直した六つのどれが効いたのか。** 割引と trace、他インスタンスの軌跡の切断、開始ポテンシャルの混入、採点の読み、建設機の紛れ込み、健全度の分母。**六つとも直したが、前後を比べた決闘が一つも無い。** 歩幅を上げた三本はそのすべてを同時に動かしている。**いま動く方策が手に入ったので、一つずつ戻して同じ種で測ることができる。**
- **抽選で打つことの税を払わずに済ませられるかどうか。** 八つの測定が同じ符号に並び、**そのうち一つは初めて区間が 0 を外した**(自己対戦で鍛えた層で +0.0377 ± 0.0214)。取り得る道は三つで、**そのうち一つは走らせて閉じた。** エントロピーの重みを 0.002 から 0.0002 へ下げると、**分布はむしろ広がった**(最終エントロピーが 0.443 に対して 0.578)。**同じ下げ方は作戦層のアリーナでは成績を動かしたが、そちらでもエントロピー自体は下がっていないので、この一致は「重みは分布の広さを通じて効くのではない」ことの二つ目の例である**([04-operations.md](04-operations.md))。残るのは、温度を入れて運用時だけ締めるか、確率最大で打つことを運用の定義そのものにするかである。**三つ目は最も安いが、探索と運用が別物になるので、次の訓練が何を最大化しているのかを言い直す必要がある。**
- **歩幅そのもの。** 3e-4 では動かず、1e-3 と 5e-4 で動いたことは測ってあるが、**三つのうちどれが良いかを比べた実行は無い。** バッチを小さくするのか、更新の回数を増やすのかも並べていない。
- **交換のポテンシャルがアリーナでまだ要るのかどうかは、実行ではなく算術で閉じた。** 重みを 0.5 と最も重くした根拠は「終端が交戦の序盤に届かない」という算術であり、割引 1・trace 1 のアリーナではそれが成り立たない。**そのうえ同じ 1・1 では、決定の収益は「成績 − その決定で保持していたポテンシャル」ちょうどで、そのポテンシャルは逸脱が選ばれる前に読まれる。行動に依らない量は方策勾配に寄与しないので、確保・未消費・交換の三つとも方策には届かない。** 外して比べる実行は差を測れないので、**走らせない**([../system/04-learning.md](../system/04-learning.md))。
- **膠着が大半であることが直せるのかどうか。** 交戦のおよそ 3 分の 2(21,212 件中 13,733 件、64.7 パーセント、2 標準誤差 0.7 ポイント)が膠着打ち切りである。
- **「膠着打ち切りの交戦は 0 点だから信号が無い」という見立ては取り下げた。** ちょうど 0 点は 33 件(0.24 パーセント)、両軍とも無傷は 13 件(0.09 パーセント)しかなく、疎な読みの成績の絶対値は平均 0.316 ± 0.004(2 標準誤差)である([03-tactics.md](03-tactics.md))。
- **残っている問いは薄まりの方である。** 膠着打ち切りは件数の 64.7 パーセントを占めながら、疎な読みの絶対値の合計では 41.4 パーセントしか運んでいない。**「決着しない交戦が多いほど差が薄まる」という見立ては、少なくとも抽選を偏らせる形では当たらなかった。**
- **準備運動の回数。** 写した方策が最初の更新を生き延びるのに 5 回で足りるかは測っていない。
- **戦力の抽選の質。** 価格だけを見ており、相性も地形も見ていない。同じ予算で編成がどれだけ偏るかは測っていない。
- **死産が 0 でないこと。** 記録の残っている全実行、組んだ交戦 26,420 件のうち死産は 2 件、**0.008 パーセント(95 パーセント区間 0.0009 から 0.027 パーセント)**である。**「1 から 2 パーセント」という読みは取り下げた**([03-tactics.md](03-tactics.md))。**残った 2 件はどちらもエピソードの 1 件目で、同じ地点が生成を受け付けなかったものである。**
- **方策が弱いほど盤面が混むこと自体は測れるが、それが死産に届いた記録は無い。** `withdraw` 固定のアームは、同じ抽選で対にした基準線より交戦 1 件あたり立っているユニットが 0.633 ± 0.238 多く、膠着で終わる割合が 0.138 ± 0.044 高い(400 秒 80 対。240 秒 80 対でも 0.468 ± 0.356 と 0.104 ± 0.042 で同じ側)一方、固定と貪欲の 3 アームは交戦 7,073 件で死産 0(95 パーセント上限 0.042 パーセント)である。**記録の残っている実行に乱数から始めた層のものが無いので、最も弱い方策で劣化がどこまで行くかは測り直せていない。**
- **既定と違う条件のアリーナ。** 240 秒より長いエピソードと別のマップは、引き直すようにしたアリーナでは測っていない。

**GAE の trace を 1.0 から 0.95 へ落とす道は、走らせて外れた。** 予告した機構は働いた——批評家の誤差は 0.06 から 0.012 へ落ち、勝敗は 707 対 711 まで揃った——が、**確率最大の側は h3 と区別が付かない(-0.0015 ± 0.0218)。** エントロピーの二本と合わせて徴候が同じである:**学習は分布の質量を動かし、採点される argmax を動かしていない。** **どちらの差も測定の床の内側なので、言えるのは「動かなかった」だけである。**

## 作戦層

- **この場は部隊がどうなっているかを一度も折り返していなかった。直した。この節の構築アリーナの数字はすべて、その基準線の上のものである。** 散らばりは 0、損害は 0、状況は ACTIVE のまま、全周期・全部隊・両側が開始値に固定されていた——**この場の部隊はゲーム側の squad ブロックを一度も通らないので、書く者がいなかった。** **帰結が二つある。** 一つ、**手書きの作戦梯子は状況(止まった・負けている・終わった・期限切れ)でしか再タスク付けしないので、この場では一度も再タスク付けしていない。梯子は各部隊に契約を一本出して地平まで持っていた**——2000 ミリ秒の実行で用務の長さ 127 から 145 決定(地平は 150 周期)、10000 ミリ秒の実行で 27.1 決定(地平は 30 周期)というのは、その言い換えである。**したがってこの節が「気を変える頻度」で梯子と学習層を比べているところは、比べる相手が選び直せなかった側である。** 二つ、**戦術の切り出しも作戦の切り出しも、部隊あたり散らばり 1・予算の消化 1・状況 one-hot 5 の 7 スロットを開始値に固定されたまま読んでいた**([04-operations.md](04-operations.md))。**フル試合の数字はこれを受けない。**
- **同じ形の欠陥が交戦アリーナの側に残っている。** こちらは塞がり、**契約がすべて ATTACK / AGGRESSIVE なので戦術の 13 個が定数である**ほうは開いたままである(下記)。**二つを並べて読む理由は、この場で見つかった同種の欠陥(staged 部隊の半分が garrison と記録され ATTACK を一度も出されなかったこと)が実際に大きかったことである。**
- **訓練の側にも二つ見つかって直した。** 一つ、**一つの盤面に載る四つの層は同じ instance 番号と同じバッファを共有するので、先に閉じた層の切断が他の層の生きた軌跡を切っていた**(いまは全層を park してから close する)。二つ、**決定を待たせずに消えた部隊の台帳が残り、同じ番号を次に受け取った部隊がそれを引き継いでいた**——この層は「任務を出せるほど健全な部隊」にしか決定を下さないので、擦り減って統合された部隊はまさにこの経路を通る。**さらに二つが試合の経路にだけ効く**——試合の作戦報酬が契約の引き直しで台帳を再基準化していたこと(上がったところで引き直せば下げ幅を払わずに済む経路。この場の台帳は最初からそうなっていない)と、封をされた軌跡が後のエピソードの乱入で汚れていたこと(この場に乱入者はいない)である。**試合の中で作戦層を鍛えた実行はこの記録に一本も無いので、動く数字は無い。**
- **この場と試合の観測の食い違いで、まだ塞いでいないものが三つある。** 一つ、**作戦の切り出しの経済側がこの場では定数である**——経済を構成で取り除いた場なので、領域行の `held_by_us` と `held_by_enemy` はどの行でも 0、全体ブロックの資金は 0、建造中は 0 で、試合ではどれも動く。**取り除いたのはこの場の存在理由そのものなので、直しは「経済を戻す」ではなく「その特徴を層に見せない」か「この場でも動かす」かのどちらかであり、どちらも測っていない。** 二つ、**staged 部隊は常に 4 隊なので `global.squads` が定数である**——盤面ごとに引けば動くが、盤面の難度が動くぶん散らばりが増えるので、対にした比較の分解能と引き換えになる。三つ、**交戦アリーナの契約はすべて ATTACK / AGGRESSIVE なので、戦術の 58 特徴のうちタスクと stance の one-hot 13 個が訓練中ずっと定数である**——試合ではどちらも動くので、戦術層はその 13 個について訓練の分布の外を読むことになる。**これは戦術層の計器を作り直す変更なので、`tactics-close` を下に凍結している作戦層の測定がすべて取り直しになる。**
- **霧は観測の食い違いではない。** この場は `fog=0`、試合の評価は `fog=2` で走るが、**観測はいまのところ全知であり、可視の判定は一箇所の切り替えとして通してあるだけで入っていない**([../system/02-interface.md](../system/02-interface.md))。したがって層が読むものは両方で同じである。**動くのは内蔵 AI の見え方とエンジン自身の目標捕捉であり、この場には内蔵 AI がいない。** 霧を実際に入れた日に、この項は食い違いに変わる。
- **下に凍結する戦術層をどう選ぶか。要る性質は二つに分かれ、四つの候補を同じ盤面で比べて一つだけが両方を満たした。** **戦いを解決すること**(送られた先で撃ち合いが終わらなければ、どこへ送ったかは盤面に現れない)と、**鏡像の下で反対称であること**(壊れていれば測っているのは方策ではない)である。**種 106001 の 193 盤面で四つを比べると、交戦アリーナ最強の層は手書きと同じ 12 本しか取らせず(`hold` 95.3 パーセント)、いちばん取らせる第四世代は 70 本を取らせるが関門を +0.0583 ± 0.0211 で外し、第一世代の `close` だけが -0.0067 ± 0.0112 で通りながら 25 本を取らせる**([04-operations.md](04-operations.md))。**この記録の最良の作戦層が実際に下に置いていたのはその第一世代であり、選択は当たっていた。** **残っているのは「交戦アリーナの成績で選んではならないなら、何で選ぶのか」を規則として書くことである**——いまの根拠は測定であって基準ではない。
- **以下は、その比較を取る前に書いた項である。** 設計の順序は「戦術層を先に固め、凍結したそれに対して作戦層を学習させる」であり、固まった層としていちばん強いものを置くのが素直だった。**測ると、その層はこの場で決定の 95.6 パーセントを `hold` に使い、旧い凍結層は 80.4 パーセントを `focus` に使っていた。撃ち合いが解決しない盤面では、どこへ送ったかが盤面に現れない**——同じ作戦層の優位が -0.1840 から -0.1217 へ縮み、その上で鍛えた層は届かない([04-operations.md](04-operations.md))。**残っているのは三つ。** 一つ、**機序そのものの測定**——同じ作戦層を二つの凍結層の下で回して分解能を比べる実行は、b3 について片側しか無い。二つ、**なぜその層はこの場で `hold` に落ちるのか**——交戦アリーナの盤面では `hold` は 38 パーセントで、作戦アリーナの盤面では 95.6 パーセントである。**同じ層が二つの場で違う方策になっている。** 三つ、**では何を凍結すべきなのか。** 「作戦層を測るのに都合の良い戦術層」を選ぶことは、計器を結論に合わせて選ぶことに近い。**選び方の根拠を決めないまま選んではならない。**
- **手書きの作戦梯子を集中させること。これがいちばん上である。** フル試合で `ops-concentrate` は梯子を **+0.065 上回り(必要 91 対に対し 96 対、分解)**、経済成分も -0.369 から -0.315 へ動く。同じ実行の `ops-pin` は梯子と区別が付かない(-0.004、必要 19,441 対)ので、**梯子の丁寧な選択が試合を動かしているという証拠は無く、動かしているのは一点へ集めることである**([04-operations.md](04-operations.md))。**入れ替えなかったのは、測定中の実行が現在の梯子を相手にも基準線にも使っているからであって、証拠が足りないからではない。** **入れ替えると、記録されたすべての数字の基準線が動く。それは承知のうえで入れ替えるべき変更である。**
- **入れ替えるなら、その前後で測るべきものが二つある。** 一つは別のマップと別の長さ——測ったのは Lake の 300 秒と Hills の地平 300 秒の二つだけである。もう一つは、集中の規則そのものの粗さ——`Concentrated` は優先度が最も高い一点へ全部隊を送るだけで、守備の強さも距離も見ない。**その粗い規則が梯子を上回るということは、梯子が見ているものの多くが役に立っていないということでもある。**

- **契約の最短保持や引き直しの費用という直し方もある。** ただしこちらは報酬か環境の側の制約であり、**整形ではないので最適方策そのものを動かす。** 上の符号化の欠落が先に潰せるなら、そちらが先である——**見えていないものを罰するより、見えるようにするほうが順序として正しい。**
- **なぜ配置を決められないのか。方策はいまも決められておらず、そしてそれは成績を損ねていない。** 学習層の用務の長さは 20.7 から 22.5 決定、すなわち 41 から 45 ゲーム秒ごとに行き先を変えるところで、梯子(138.2 から 144.6)の 6 分の 1、集中(129.9 から 133.5)の 6 分の 1 である。**周期を 10000 ミリ秒に粗くしてもこの比は変わらない**(5.8 対 27.1)ので、決められないことは周期の関数ではなく方策の性質である。**そのうえで、同じ 22 決定前後で気を変える方策が梯子も集中も区間つきで上回った。したがって「学習層が集中に届かないのは配置を決められないからだ」という読みは取り下げたままである。** **そして「決められるようにしたら上がるのか」は、押す仕掛けを作る前に反証された。** 広げた切り出しの世代は用務の長さ 16.1 決定と**この記録のどの層より短く気を変えるのに、どの層より強い**([04-operations.md](04-operations.md))。**長さと点数が同時に動いた実行が三つあることは測定だが、そこから長さが原因だと読むことはこの一つで潰れる。契約の最短保持や引き直しの費用は、根拠を失ったので実装していない。** **ただしフル試合ではその根拠が半分戻った**——アリーナで最も強い世代を試合に置くと**契約の達成率は 0.12 で、他の三本(0.31 から 0.42)の三分の一であり、経済成分も -0.407 と四本の最下位である**([04-operations.md](04-operations.md))。**アリーナでは粘らないことが罰されず、試合では罰されている徴候がある。ただし作戦層だけの寄与そのものは +0.029 で 0 を含むので、これは徴候であって測定ではない。分ける実行は無い。**
- **どの一点を選ぶか。** `concentrate` は全部隊を最も優先度の高い係争点へ送るだけの素朴な規則である。**優先度だけでなく守備の強さや距離を見る余地があり、それは学習が手書きの規則を上回れる余地そのものである。学習層はいまそこに並んでいる——直した計器では点数でも奪取数でも区別が付かない。傾いていた計器で「その上に出ている」と読んでいたのは取り下げた。** **残っているのは二つで、「何を見て選んでいるのか」を言う測定が無いことと、集中アームを実際に越えられるのかどうかである。**
- **アリーナで身に付けた技能がフル試合へ乗るか。答は二つに分かれた。手書きの集中アームは乗り、この場の最良の学習層は乗らない。** 集中アームはフル試合で梯子を +0.065 上回り(96 対、分解)、アリーナでの +0.076 から +0.095 と同じ向き・同じ桁である。**そしてアリーナで梯子を -0.2041、集中アームを -0.0761 上回った 600 エピソードの世代を同じ条件の試合に置くと、梯子との差は +0.040(梯子が上、要 233 対)で分解せず、自分が鍛えられた戦術層だけの鎖との差——この記録が初めて分けた作戦層だけの寄与——は +0.029 で 0 を含む。六つの対のうち唯一分解したのは、集中アームがその学習した鎖を +0.087 で上回る対である**(要 58 対に対し 96 対)([04-operations.md](04-operations.md))。**アリーナの順位(学習層 > 集中 > 梯子)は、試合では(集中 > 梯子 ≒ 学習した鎖)に入れ替わる。** **同じ実行で集中アームの再現は点推定どまりである**(+0.047、要 172 対)**ので、集中が乗ることはいまも二つの実行を合わせて初めて言える。** **残っている問いは三つ。** 一つ、**機序**——徴候は二つあり、契約の達成率が 0.12 と他の三本(0.31 から 0.42)の三分の一であること、経済成分が -0.407 と四本の最下位であることである。**アリーナは経済を構成で取り除いた場なので、そこで報われた技能が試合では罰される形になっている。分ける実行は無い。** 二つ、**測ったのは最良の一世代であって系統ではない**——150 と 300 エピソードの世代を試合に置いた実行が無いので、**アリーナの長さの梯子が試合でどちらを向くかは掃いていない。** 三つ、**作戦層だけの寄与は 0 を含むので、言えるのは「梯子超えが試合で支持されない」までであって「この層は害である」ではない。**
- **突撃が通らないのは何のせいか。** **学習層が突撃しなかった理由は終端の基準点と信用の届き方とエントロピー賞与であり、三つとも動かした。取りに行くべき 98 本のうち 4 本から 11 本まで来ている。** **梯子自身が 5 本から 7 本しか取れないことは変わっていない。** 守備側の値段は原因ではない——半分にしても取れる disc は 76 本中 1 本から 4 本にしか動かない。**決定の頻度は粗い側へ一度だけ動かして外れた。行軍の距離も、地平の長さも、採点の仕方も、まだ動かして測っていない。**
- **一部隊の終端の三つの読み(`board`・`region`・`marginal`)のどれが良いか。** 既定はいま `board` で、**契約を読む `region` が「負けている地面から立ち去ること」に金を払っていたことは実測で確かめて塞いである**([04-operations.md](04-operations.md))。残っているのは `marginal` との比較で、**同じ盤面の上で三つを並べた実行は無く、`--credit marginal` の実行は一本も無い。** 定義からの算術としては、`marginal` は一つの領域に乗った部隊が credit を分け合うので**この場では集中を罰する向き**である。それは測定ではない。
- **作戦ポテンシャルの二つの書き直しが数字を動かすのかどうか。** シェアから支配へ書き直したことと、開始ポテンシャルを打ち消すようにしたことである。**直す前と直した後を同じ種で並べた実行は無い。** 直した根拠は伸縮の算術だけである。**終端の基準点・周期ごとの信用割当・エントロピー賞与の三つとは分けて読む**——そちらは同じ 49 盤面に l3 / o1 / p1 / p2 / p3 / p4 として並べてある([04-operations.md](04-operations.md))。
- **8 逸脱で鍛えた戦術層の下で、その傾きが開き直った。** 自己対戦ゼロは三つの種で +0.0020(75 盤面)・+0.0187(73 盤面)・+0.0199(186 盤面)、三つとも正で平均およそ +0.0135、最後の一つは自分の区間を外す([04-operations.md](04-operations.md))。**基準点を各側の自陣へ移して三つの種で閉じた問いが、新しい層の下で同じ形に戻っている。** **切り分けは済んだ。傾きはそのパラメータの性質であり、盤面でも符号化でも実行の引きでもない。** 同じ 186 盤面で、手書きの梯子の下は +0.0019 ± 0.0044(2 本)、第二世代の下は +0.0163 ± 0.0071(3 本)、第一世代の下は -0.0011 ± 0.0091(2 本)、模倣のみの下は +0.0168 ± 0.0127 である。**符号化は無罪で、訓練済みパラメータは構築した鏡像盤面を両席から読んで logits も価値も厳密に一致する。** **そして機序が下から見えた**——エピソード記録が両席の逸脱を数え分けるようにしたところ、席の食い違いは手書きで 0.9 ポイント、学習した二つで 4.1 と 14.1 ポイントである。**渡すものは合同でも、渡す元の地面が決定境界を跨いでいる。ただし席差の大きさは傾きの大きさではない——最も席差の大きい層が傾かない。** **帰結は計器の選び方である:傾かない層と、決闘で梯子を上回った唯一の層は同じファイルなので、この場に凍結すべき層はそれである。その下で作戦層を鍛え直して測る一巡を回している。**
- **凍結した戦術層の下のアリーナは別の計器であり、その計器は系統的に正へ傾いている。** 取り直した自己対戦ゼロは種 80001 の四つ(97 盤面で +0.0021 ± 0.0104、49 盤面で +0.0135 ± 0.0206・+0.0107 ± 0.0134・+0.0072 ± 0.0099)、種 90001 の 52 盤面で +0.0297 ± 0.0182、種 91001 の 53 盤面で +0.0047 ± 0.0132、種 92001 の 47 盤面で +0.0026 ± 0.0119、種 93001 の 49 盤面で +0.0267 ± 0.0193 である。**したがって「この経路は関門を通る」とは言えない。八つとも正で五つの種も五つとも正、区間を外すのは 90001 と 93001 の二つであり、これは通ったり通らなかったりする計器ではなく、この過程の打つ側へ寄っていて二つの種でその寄りが区間を超えた計器である。** **原因の一つは分かっており、消してある——下に置いた網が点反射に対して不変でないことであり、そうさせていた特徴 2 つを不変な対に置き換え、さらにその基準点を各側の自陣に置いてアリーナが側ごとに渡すようにした。三つの種で取り直すと、脅威基準では -0.0020 ± 0.0100・+0.0047 ± 0.0205・+0.0200 ± 0.0158(93001 だけ通らない)、自陣基準では -0.0046 ± 0.0141・-0.0047 ± 0.0198・+0.0020 ± 0.0183 で三つとも通る。残り二つの種(91001・92001)はどちらの符号化でも未着手であり、三つの読みで五つの種の系統性を否定することはできない**([04-operations.md](04-operations.md))。 地平や半径を変えた実行も無い。
- **抽選に入れた二つの直しが数字を動かすのかどうか。** 対が自分自身と重なりうること、係争点が自陣の基地に届きうることの二つである。**基地に届く盤面の割合(約 4.8 パーセント)とそこでの上乗せ(+0.1 から +0.15)はマップと抽選の法則から見積もってあるが、直す前と後の自己対戦の平均を並べた実行は無い。**
- **「梯子を上回った +0.047 を同じ実行の 4 アームで測り直すこと」は済んだ。** 同一実行・新しい種で `script` − `learnt` = -0.0414 ± 0.0261 と再現し、**その後 -0.0637 ± 0.0351 と -0.0682 ± 0.0370、さらに -0.1111 ± 0.0318 と -0.1122 ± 0.0409 に更新された。** **同じ測り直しが「集中は学習層の 2 倍以上」を取り下げさせ、続く二本が「集中は学習層の上にいる」ごと取り下げさせ、凍結戦術層の下の二本が向きを逆にした**([04-operations.md](04-operations.md))。

## 戦略層

**一度回して、幅も測った**([05-strategy.md](05-strategy.md))。**姿勢の選択には確かな幅がある**——軍拡に固定すると梯子より 0.095 落ち、必要な試合数 22 対に対して 96 対取ってあるので分解している。**戦術層の逸脱の幅(0.013 から 0.026)の 4 倍以上である。** **一方、480 試合鍛えた層は写した規則と区別が付かない**(-0.007、必要 5,403 対)。**したがって「学ぶものが無い」ではなく「学べていない」である。**

- **批評家は、自分が予測すべき量を一度も観測していなかった。直した。この節の数字はすべて、その 29 特徴の上のものである。** この層の終端は試合の採点、整形はその進行中の形であり、どちらも「立っているもの全部どうしの差」でできているのに、**29 特徴のどれもそれを持っていなかった。** 見えていた `military_edge` は戦闘ユニットどうしの比なので、**採掘施設と工場でできた優劣——姿勢がまさにそのあいだで選ぶもの——はそちらに現れない。** `standing_edge` を足して 30 になった。**同時に `income_growth` が試合の立ち上がりで潰れていたことも直した**——窓の最古が 0 の周期に「急伸中」と「完全な頭打ち」が同じ 0.0 になっていた。頭打ちはこの層が読む当の値である([05-strategy.md](05-strategy.md))。**残っているのは取り直しである。**
- **試合の収益の定義が変わった。「採点」から「採点 − 開始ポテンシャル」へである。** 直す前は収益がちょうど採点になる代わりに、**割引 1 未満で経路依存の残差が残っていた**——整形が払うのは `割引 × 後のポテンシャル − 前のポテンシャル` の和であり、それが「動いた分」に等しいのは割引が 1 のときだけだからである。**開始ポテンシャルはこの層が最初の決定を下す前の盤面なのでエピソードの定数であり、姿勢では動かせない。** **既定の割引は 1.0 のままなので、この記録の実行が最大化していた量は変わらない。**
- **なぜ学べていないのか。説明の候補は三つで、どれも掃いていない。** 一つ、独立な結果が試合 1 本につき 1 つしかないこと(割引 1 の帰結)。二つ、480 試合がその形の学習には少なすぎること。三つ、**バッチが小さすぎること**——既定の 256 段は試合 8.5 本ぶんで、試合ごとの散らばり 0.13 に対してバッチ平均の標準誤差は **0.045**、すなわち**分解したい効果(0.095)と同じ桁である。** 実測でも訓練の clipped は 0.00 から 0.03 で、**更新のたびに方策がほとんど動いていない。** **この層ではバッチを大きくするほうが良い可能性があり、それは他の二層と逆向きの結論になる**——1024 段なら試合 34 本で標準誤差は 0.022 に落ちるが、8 並列で集まるのに 4 分かかり、「1 分を大きく下回って集まる大きさ」という設計の規則から外れる([../system/04-learning.md](../system/04-learning.md))。**規則の根拠は遅れに対する安全弁がクリップであることなので、どちらが勝つかは掃くまで分からない。**
- **五つすべてを固定した幅は取った。上限が決まった。** 幅は 0.11(`expand` の -0.514 から `decide` の -0.624 まで)で、上端と下端は 18 対から 29 対で分解する。**そして上端に手書きの梯子が既にいる**——最良の固定姿勢と梯子の差は +0.018 で、区別するには 986 対が要る。**したがって学習に残っている余地はおよそ 0.02 で、戦術層の幅と同じ桁である**([05-strategy.md](05-strategy.md))。**これは 300 秒の試合の上の話であり、その長さでは軍隊が報われる時間が無い。長い試合で取り直すことが、この層について次にすべき唯一の測定である。**
- **梯子の遷移先は、この長さでは下から二番目の姿勢である。** 規則は収入が頭打ちになると軍拡へ移るが、`arm` は `script` より 0.090 低く、29 対で分解する。**梯子が上端に留まっていられるのは遷移が遅いからであって、遷移が正しいからではない。** **長い試合で順位が変わるかどうかが、この規則が正しいかどうかである。**
- **割引を 1 にするか 1 未満にするか。** 試合はこの層から見て 1 本の有限な用務なので、構築した交戦と同じ算術で 1 に置いてある。**その代償は分散**で、1 試合の全決定が 1 つの終端を分け合い、決定どうしを分けるのは批評家だけになる。**1 未満にすると整形が方策に届くようになる**(1 では整形は行動が決まる前に読まれる量なので方策勾配に寄与しない)代わりに目的が近視になる。**掃いていない。** **掃ける状態にはなった**——終端の返し方を直すまで、割引 1 未満では整形が経路依存の残差を残しており、**それは方策が動かせる量だったので、掃いても「近視になったこと」と「残差を動かしたこと」を分けられなかった**(上記)。
- **相手を二人以上にする道は、学習側では閉じた。** 試合の採点は最強の相手一人と比べるのに、**この層のポテンシャルは戦線報告経由で「見えている敵の総和」しか読めない**——ワイヤのユニット行は敵味方の旗しか持たず所有者を持たないので、試合の中から相手を一人ずつに分けることができない。**相手が二人以上いると密な項と終端が別の量になるので、学習実行は `--opponents 1` 以外を拒む。** **評価の実行は制限しない。** **したがって「相手を増やすと姿勢の順位が変わるか」を訊くには、まず戦線報告が敵を所有者ごとに分けて運べるようにする必要がある。実装も設計も無い。**
- **独立な観測の数が足りるのか。** 8 並列・5 分の試合・倍率 10 で毎時およそ 300 試合、すなわち**独立な終端が毎時 300 個**である。試合の採点の散らばりは 0.11 から 0.24 と測ってあるので([04-operations.md](04-operations.md))、1 時間で標準誤差は 0.006 から 0.014 になる。**学習に足りるかどうかは、測るのに足りるかどうかとは別の問いであり、どちらも実行していない。**
- **技術(TECH)を選べるようにしたことが何を変えるか。** スクリプトの規則は決して選ばず、学習層は選べる。**選ぶのが良いかどうかの測定は無い。**
- **試合の長さ。** ランナーの既定は 300 秒で、これは作戦層の試合実行に合わせた値である。姿勢の遷移規則は収入の 50 秒窓を持つので、5 分の試合では拡張から軍拡への遷移が 1 度起きるかどうかというところである。**長い試合のほうが姿勢の違いが出るはずだが、1 試合あたりの単価はそのぶん上がる。掃いていない。**
- **凍結の一巡は回った。この項は閉じた。** 設計は戦術→作戦→戦略の順で他層を凍結して回すことを要求しており、**配線は `--frozen layer:path`(コンマで並べれば何層でも)として `rwintel/learn/frozen.py` にあり、戦略層の三世代は学習した戦術層と作戦層を凍結した下で鍛えてある**([05-strategy.md](05-strategy.md))。**残っているのは二巡目**——更新された戦術層の下で作戦層を、その二つの下で戦略層を、もう一度取り直す向きである。

## 戦線報告の二つの価値は、同じものを数えていない

**`FrontReport` は「自軍と敵の軍事価値」を渡すと文書化されているが、二つは同じ集合を数えていない。** 自軍側は `view.fighters`、すなわち**建物と建設機を除いた戦闘ユニットだけ**である。敵側は `view.enemies`、すなわち**その側に立っているものすべて**で、司令部も採掘施設も建設機も入る。

**これまで無害だったのは、誰もその比を読んでいなかったからである。** 手書きの戦略規則が遷移に使うのは収入・失った領域数・敵の拠点数で、軍事価値は許容総損害の尺度(自軍側だけ)にしか使われていなかった。

**いま読む者が二つできた。** 一つは戦略層の報酬のポテンシャル(軍事価値差)、もう一つは作戦の符号化の全体ブロック(`military_edge`、`allowance`、部隊の価値シェア)である。**どちらも「自軍の戦闘ユニット」対「敵の全部」を比べているので、自軍を実際より不利に読む。** 300 秒の試合で自軍の立っている価値が 9,650(建物込み)、うち戦闘ユニットは半分に満たない一方、敵側は 20,000 が丸ごと分母に入る。

**直し方は像を揃えることであり、揃え方が二通りある。** 終端(試合の採点)が数えているのは**両側の立っている価値の全部**なので、ポテンシャルを終端の進行中の形にしたいなら両側とも全部を数えるべきである。一方、許容総損害の尺度として使うなら自軍の戦闘ユニットが正しい。**したがって欄を分けるのが素直で、片方を書き換えるのは片方の読者を壊す。**

**直した。欄を分けてある**——戦闘価値の対(自軍の戦闘ユニット対敵の戦闘ユニット)と総価値の対(両側の立っているもの全部)で、許容総損害は前者を尺度に取り、戦略層のポテンシャルは後者を読む。後者が試合の採点と同じ量だからである。**作戦の符号化の `military_edge` も戦闘価値の対になった。** **これは特徴の名前を変えずに意味を変える変更だったので、当時の刻印では捕まらなかった**([../system/04-learning.md](../system/04-learning.md))——**したがって両層のパラメータと教師は、この変更と同時に捨てて取り直さなければならなかった。片方は取り直され、片方は取り直されないまま使われた。**

**作戦層は取り直してある。** 直しは 2026-07-26 23:45 に入り、`local/operations-bc4.pt` は 07-28 01:57、`local/ops-arena-b1.pt`・`b2`・`b3` は 07-28 の当てはめである。**戦略層も取り直してある。** `local/teacher-strategy.jsonl` と `local/strategy-bc.pt` はどちらも **07-26 23:30**、すなわち直しの 15 分前に書かれており、**「学習した鎖が手書きの鎖を 300 秒の試合で上回った」を運んだ `strategy-s1`・`s2` は、意味の動いた `military_edge` の上で当てはめた模倣から出発している。その三つは digest つきの刻印が拒むようになり、教師の収集から取り直した**([05-strategy.md](05-strategy.md))。**600 秒の三世代はその取り直した模倣から出ており、設計が要求した「変更と同時に捨てて取り直す」はそこで果たされている。**

**そして「刻印では捕まらない」は塞いだ。** 刻印は特徴の並びの隣に**その並びを埋めたコードの digest** を載せるようになり、名前が動いたときと同じように中身が動いたときもファイルは退役する。**この digest を過去のコミットに当てると、切り出しごとに最後に動いた時点がそのまま読める**——戦術は 2026-07-26 14:47(自陣基準の方位)、作戦と戦略はどちらも 07-26 23:45(戦闘価値の対)である。**上の判定はこの表から出したものであって、心当たりから出したものではない。**

**その走査には穴があり、いまは塞がっている。** digest は最外側の code object の名前しか歩いていなかったので、**内包表記・generator 式・lambda・入れ子 def の中からしか読まれない定数と補助は、値ごと digest に入っていなかった。** 例は被弾中の部隊を数える generator 式の中でしか読まれない `RECENT_HIT_MS` で、**その種の定数はいくら書き換えても刻印が動かず、ファイルは退役しなかった。名前が動いたときも幅が動いたときも捕まえる仕掛けが、内包表記の中身についてだけ盲だったということである。** **したがって上の「最後に動いた時点」も、穴のある走査の上で読まれた値であり、入れ子の中にしか現れない変更を見落としうる。直した走査で読み直した実行は無い。**

## 全体

- **凍結して交互に学習させる一巡は、一度だけ回った。そしてその順序が効いていることは、いまや仮定ではなく測定である。** 骨格が置いた学習の順序は、戦術を先に固めてから作戦を凍結した戦術に対して学習させる、である。**回したのは一巡だけで、その一巡がこの計画で最良の作戦層を出した。同じ設定・同じ長さを手書きの戦術層の下で回すと集中アームに区間つきで負けるので、その最良を作っているのは訓練の長さではなく下に凍結した層である**([04-operations.md](04-operations.md))。**二巡目——その作戦層を凍結して戦術層を鍛え直す向き——は、経路が半分できて実行が無い。** 訓練済みの層を学習中の層の**下**に凍結して置く道は `--frozen layer:path` で通った(試合の中で作戦層や戦略層を鍛えるとき、その下に訓練済みの戦術層を置ける)。**上**に置く道も同じ仕掛けで通る——`rwintel.learn tactics` が交戦アリーナの中で回るかぎり、その場に作戦層は存在しないからである。**したがって残っているのは「戦術の学習を試合の中で行う経路」であり、それは無い。** 交戦アリーナが存在する理由そのものが「戦術は試合を回さずに学習できる」ことなので、これは配線の不足ではなく、**二巡目を回すなら戦術の学習をどの場で行うかから決め直す必要がある**という設計の問いのままである。**実行は一つも無い。**
- **鍛えた鎖と測った鎖が食い違っていた。経路を作って測り直し、差は出なかった。この項は閉じた。** 戦略層の三世代は学習済みの戦術層と作戦層を凍結した下で鍛えてあるのに、測定のアームは作戦層と戦略層しか運べず、測った試合では下に手書きの戦術層が立っていた。**経路を作って**(`tactics:<パス>`、[../system/05-evaluation.md](../system/05-evaluation.md))**同じ世代を二通りの鎖として一つの実行に並べると、差は +0.011(手書きの戦術層を下に置いたほうが上)で、区別するには片側 1,916 試合が要るところを 256 打っている**([05-strategy.md](05-strategy.md))。**歪んではいなかった。ただしそれは幸運であって設計ではない。** **そして手書きの鎖に対する +0.053 は、別の実行で +0.056 として再現した。**
- **その同じ実行が、戦術層について新しい問いを開けた。** 交戦アリーナで梯子を確率最大 +0.0274 ± 0.0177 上回る層を鎖に載せても、**試合の採点は 0.011 の中に埋もれ、符号すら定まらない**([05-strategy.md](05-strategy.md))。**作戦層についてはアリーナの技能が試合へ乗ることが測ってあるが、戦術層についてはこれが最初の測定であり、答えは「この長さのこの試合では見えない」である。** **残っているのは、見えないのが試合の長さのせいなのか、戦術の決定が試合の採点に対して小さいからなのかを分けることである。実行は無い。**
- **戦術の学習を試合の中で行う経路のために要る性質が、一つ満たされた。** 設計が数えている戦術層の四つの終端のうち、**全滅(-1.0)は試合で一度も発火していなかった**——編成層は最後のユニットが死んだその周期に部隊を退役させるので、戦術層は「在籍が空の部隊」を一度も見られず、部隊を丸ごと失うことは「報告されなくなった部隊」として切られていた。**すなわち全滅は何の代償も伴っていなかった。** いまは編成層が破壊されて退役した部隊を書き、鎖がそれを戦術層へ渡す(合流・解散は生存者がいるので含まれず、従来どおり切られる)。**残っているのは経路そのもの——二巡目を回すなら戦術の学習をどの場で行うかから決め直す、という設計の問い——のままである。**
- **幅を掃く道具が、掃いた先を測れるようになった。** `--width` で既定以外の幅に鍛えた網は、**評価のアームにも `--frozen` にも載らなかった**(どちらも既定の幅で網を組んでから読み込むので、形が合わずに落ちる)。**すなわち幅を掃く口はあって、掃いた結果を測る口が無かった。** いまはどちらも最初の線形写像の形からファイル自身の幅を読む。**幅を掃いた実行はいまも一本も無い**——[全体](#全体) の最後の項が書いているとおり、幅を上げて良くなるという計測は無い。
- **網の大きさは、もう制約ではない。** 幅を絞った理由は毎秒 400 決定という要求であり、**その要求が当てていたのは GPU だった。** 実測では推論は 1 コアの数パーセントしか使わず、律速はシミュレーションである。**上げて良くなるという計測も無いので、これは「次に試すこと」ではなく「上を試すときに、幅を理由に諦めなくてよい」という但し書きである。**
