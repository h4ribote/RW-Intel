# 分かっていないことと、次に試すこと

**測ってあることは [03-tactics.md](03-tactics.md)、[04-operations.md](04-operations.md)、[05-strategy.md](05-strategy.md) にある。この文書は、そこから残った問いだけを書く。** 順序は好みではなく、測定から導く。

## 骨格の側でまだ決めていないこと

いずれも実装を止めるものではない。数値の初期値は [../system/03-script-policy.md](../system/03-script-policy.md) と [../system/04-learning.md](../system/04-learning.md) に置いてあり、計測で調整する。

- **打ち切り時の採点式の重み。** 経済差と軍事価値差と領域支配のどれをどれだけ効かせるか([../system/05-evaluation.md](../system/05-evaluation.md))。決着したエピソードが集まるまでは軍事価値差だけで採点する。
- **霧を有効にする時期。** 経路は最初から通すが、内容を切り替える判断は全知での足場ができてからになる。
- **報酬と最適化の各定数。** 網の形と算法は決まったが、報酬の重み、終端の比、アリーナの予算と戦力比は、いずれも根拠のある初期値であって計測で選ばれた値ではない。**例外が二つある。** 一つはアリーナの割引と trace の 1.0 で、これは好みでも計測でもなく、用務の長さと決定の頻度から出る算術で決まっている。**もう一つはエントロピー賞与で、構築作戦アリーナでは既定の 0.002 より 0.0002 のほうが良いという測定がある**——**ただしその測定は作戦層のこの場でしか取っておらず、既定を書き換えてはいない**([04-operations.md](04-operations.md))。

## 戦術層

- **この場では、そもそも動かせる幅が測定の床とほぼ同じである。** 逸脱をひとつも選ばない方策(常に `hold`)は梯子より体力の読みで 0.013 から 0.026 下、接敵したら離れるだけの方策は 0.014 から 0.023 下でしかない([03-tactics.md](03-tactics.md))。**戦術の決定を丸ごと取り上げてもその程度しか落ちないのだから、梯子の上に残っている余地はさらに小さく、訓練を伸ばして越えられる量ではない。** **次に動かすのは訓練の長さではなく盤面の幅である**(`--separation`、未実行)。
- **手書きの層より強い方策が作れるのかどうか。** 選択に使っていない種の上では、模倣も、三つの設定も、それを二度延長したものも、歩幅を上げた鎖も、macOS で独立に学習した層も、梯子を上回っていない。**候補の点推定を 0 から外すには、いまのおよそ 4 倍の交戦が要る。** それを取るなら、候補選びにも確かめにも使っていない新しい種で取る。**上回った方策は無いが、下回った方策は初めて区間つきで出た**——既定の自己対戦で鍛えた層が -0.0402 ± 0.0214 で、原因は訓練相手だった([03-tactics.md](03-tactics.md))。
- **梯子と同水準で止まる理由。信号の到達ではない。** 延長実行の全 478 更新・決定 748,358 段を数えると、94.6 パーセントが終端の届く用務にあり、優位ちょうど 0 は 0.081 パーセントしか無い。**残る候補は、行動空間、特徴、そして交戦アリーナが与える盤面の幅である。どれも測っていない。**
- **そのうち「盤面の幅」は、掃ける道具ができた。** 両軍を置く間隔はアリーナの定数だったので、**それを動かした実行が一つも無いのは選択ではなく、動かす口が無かったからである。** いまは `--separation` で渡せて、エピソード記録が間隔・膠着秒・戦力比の下限・払った読みを書き留めるので、別々の間隔で取った実行が同じ計器として対にされることもない。**なぜこれが第一候補なのかは算術である**——既定の 250 はエンジンが二つの戦力を止める「見えるが届かない」隙間の内側に置いてあり、それは交戦を始めさせるための値であって、**departures が決められる幅を最小にする値でもある。** 両側が最初の周期から撃ち合っている盤面では、引くか集中するかの選択が動かせる余地は小さい。**間隔を広げると、その隙間で止まったまま何もしない交戦が増える**(700 で測ったとき 4 分の 3 がそうなった)ので、**間隔と行動空間は一つの問いである**:いまの 7 つには「詰める」が無く、外から始まる交戦では引くか止まるかしか選べない。**掃いていない。**
- **不変性を情報と引き換えに買ったところは、買い戻して訓練と決闘の両方で測ってある。下がりは消え、上回ってはいない。** 目標への方位を地図の軸から脅威の重心へ移したことで符号化は点反射に対して不変になったが、**脅威の無い部隊——係争点へ行軍している部隊がまさにそれ——は方向を一切持たなくなった。** その符号化で鍛え直した層は梯子に対して -0.0398 ± 0.0228 と 0 を外して下回り、旧符号化の同条件(-0.0042 ± 0.0224)は互角だった([03-tactics.md](03-tactics.md))。**基準はいま自陣から外へ向かう向きにあり、下がりは戻った**(`target_ahead_of_home`・`target_abeam_of_home`)。**同じ設定で鍛え直した層は +0.0036 ± 0.0226 で 0 を含む。点反射が自陣と敵陣を入れ替えるので不変性は保たれ、撃たれていない部隊も方向を持ち、前後の項は「外へ送られたのか自陣へ戻されたのか」を言う。基準点は側ごとに置かなければならず、それは視界を組む側の責務である——交戦アリーナは各側の出撃地点を、作戦アリーナは各側の staging point を入れる。両側で共有すると不変性はその場で壊れ、それを含めて四つの試験で固定してある。** **決闘も取った。** 選択に使っていない種 774001 で凍結して測ると、確率最大で +0.0057 ± 0.0213、抽選で -0.0085 ± 0.0219、基準線は +0.0045 で読める——**訓練中の成績と揃って、梯子と区別が付かない。****そして「符号化が差を作った」ことそのものは、三本になっても区間つきでは言えていない**——脅威基準と自陣基準の差は 0.0434、その区間は約 ±0.032 で、床の ±0.02 が別に乗る。**分けるには、同じ出発点から二つの符号化で鍛えた対を、決闘の基準線を引いて測る実行が要る。**
- **候補が一行の規則より上かどうか。** 4 アームの実行を一度走らせて「上に見えるが交戦 500 件では言えない」まで来た。**`withdraw` 固定がどこにいるかは三つの種で割れたままである。**
- **訓練済みの戦術層を盤面の片側だけに置く経路が無い。** 構築作戦アリーナの `--tactics` は層を両側の下に置くので side score が両側で反対称になって層の強さが打ち消し合い、**下の層を差し替えた 3 実行はどれも 0 を含んだ。成績で戦術層を測ることが、この場では構造で閉じている**([03-tactics.md](03-tactics.md))。**片側だけに置く経路を作れば side score で測れるが、それは `script` アームのプールした平均が 0 でなければならない理由——二つの側が交換可能であること——を手放すことでもある。** **代わりに何を関門にするのかを決めないまま作ってはならない。** 決闘のように相手側を手書きに固定した基準線アームを同じ実行で取る、という道はあるが、**設計も実装も無い。**
- **体力の読みでの幅。この問いは半分閉じた。** この記録の天井の数字はほとんどが疎な読みの上のものだが、**体力の読みでの幅は二つの種で取ってある**——hold が -0.0257(種 20260723)と -0.0130(20260725)、withdraw が -0.0145 と -0.0227 である(後者は残っている journal から読み直した)。**種による散らばりはその差と同じ程度あるが、四つの読みはすべて 0.013 から 0.026 の帯に収まる。** **残っているのは幅の値ではなく、その帯が測定の床(±0.02)とほぼ同じであることの帰結**——[戦術層](#戦術層) の最初の項に書いたとおり、この場では梯子の上に残っている余地が床より小さい。
- **直した六つのどれが効いたのか。** 割引と trace、他インスタンスの軌跡の切断、開始ポテンシャルの混入、採点の読み、建設機の紛れ込み、健全度の分母。**六つとも直したが、前後を比べた決闘が一つも無い。** 歩幅を上げた三本はそのすべてを同時に動かしている。**いま動く方策が手に入ったので、一つずつ戻して同じ種で測ることができる。**
- **抽選で打つことの税を払わずに済ませられるかどうか。** 八つの測定が同じ符号に並び、**そのうち一つは初めて区間が 0 を外した**(自己対戦で鍛えた層で +0.0377 ± 0.0214)。取り得る道は三つで、**そのうち一つは走らせて閉じた。** エントロピーの重みを 0.002 から 0.0002 へ下げると、**分布はむしろ広がった**(最終エントロピーが 0.443 に対して 0.578)。**同じ下げ方は作戦層のアリーナでは成績を動かしたが、そちらでもエントロピー自体は下がっていないので、この一致は「重みは分布の広さを通じて効くのではない」ことの二つ目の例である**([04-operations.md](04-operations.md))。残るのは、温度を入れて運用時だけ締めるか、確率最大で打つことを運用の定義そのものにするかである。**三つ目は最も安いが、探索と運用が別物になるので、次の訓練が何を最大化しているのかを言い直す必要がある。**
- **歩幅そのもの。** 3e-4 では動かず、1e-3 と 5e-4 で動いたことは測ってあるが、**三つのうちどれが良いかを比べた実行は無い。** バッチを小さくするのか、更新の回数を増やすのかも並べていない。
- **交換のポテンシャルがアリーナでまだ要るのかどうかは、実行ではなく算術で閉じた。** 重みを 0.5 と最も重くした根拠は「終端が交戦の序盤に届かない」という算術であり、割引 1・trace 1 のアリーナではそれが成り立たない。**そのうえ同じ 1・1 では、決定の収益は「成績 − その決定で保持していたポテンシャル」ちょうどで、そのポテンシャルは逸脱が選ばれる前に読まれる。行動に依らない量は方策勾配に寄与しないので、確保・未消費・交換の三つとも方策には届かない。** 外して比べる実行は差を測れないので、**走らせない**([../system/04-learning.md](../system/04-learning.md))。
- **膠着が大半であることが直せるのかどうか。** 交戦のおよそ 3 分の 2(21,212 件中 13,733 件、64.7 パーセント、2 標準誤差 0.7 ポイント)が膠着打ち切りである。
- **「膠着打ち切りの交戦は 0 点だから信号が無い」という見立ては取り下げた。** ちょうど 0 点は 33 件(0.24 パーセント)、両軍とも無傷は 13 件(0.09 パーセント)しかなく、疎な読みの成績の絶対値は平均 0.316 ± 0.004(2 標準誤差)である([03-tactics.md](03-tactics.md))。
- **残っている問いは薄まりの方である。** 膠着打ち切りは件数の 64.7 パーセントを占めながら、疎な読みの絶対値の合計では 41.4 パーセントしか運んでいない。**「決着しない交戦が多いほど差が薄まる」という見立ては、少なくとも抽選を偏らせる形では当たらなかった。**
- **準備運動の回数。** 写した方策が最初の更新を生き延びるのに 5 回で足りるかは測っていない。
- **戦力の抽選の質。** 価格だけを見ており、相性も地形も見ていない。同じ予算で編成がどれだけ偏るかは測っていない。
- **死産が 0 でないこと。** 記録の残っている全実行、組んだ交戦 26,420 件のうち死産は 2 件、**0.008 パーセント(95 パーセント区間 0.0009 から 0.027 パーセント)**である。**「1 から 2 パーセント」という読みは取り下げた**([03-tactics.md](03-tactics.md))。**残った 2 件はどちらもエピソードの 1 件目で、同じ地点が生成を受け付けなかったものである。**
- **方策が弱いほど盤面が混むこと自体は測れるが、それが死産に届いた記録は無い。** `withdraw` 固定のアームは、同じ抽選で対にした基準線より交戦 1 件あたり立っているユニットが 0.633 ± 0.238 多く、膠着で終わる割合が 0.138 ± 0.044 高い(400 秒 80 対。240 秒 80 対でも 0.468 ± 0.356 と 0.104 ± 0.042 で同じ側)一方、固定と貪欲の 3 アームは交戦 7,073 件で死産 0(95 パーセント上限 0.042 パーセント)である。**記録の残っている実行に乱数から始めた層のものが無いので、最も弱い方策で劣化がどこまで行くかは測り直せていない。**
- **既定と違う条件のアリーナ。** 240 秒より長いエピソードと別のマップは、引き直すようにしたアリーナでは測っていない。

**GAE の trace を 1.0 から 0.95 へ落とす道は、走らせて外れた。** 予告した機構は働いた——批評家の誤差は 0.06 から 0.012 へ落ち、勝敗は 707 対 711 まで揃った——が、**確率最大の側は h3 と区別が付かない(-0.0015 ± 0.0218)。** エントロピーの二本と合わせて徴候が同じである:**学習は分布の質量を動かし、採点される argmax を動かしていない。** **どちらの差も測定の床の内側なので、言えるのは「動かなかった」だけである。**

## 作戦層

- **手書きの作戦梯子を集中させること。これがいちばん上である。** フル試合で `ops-concentrate` は梯子を **+0.065 上回り(必要 91 対に対し 96 対、分解)**、経済成分も -0.369 から -0.315 へ動く。同じ実行の `ops-pin` は梯子と区別が付かない(-0.004、必要 19,441 対)ので、**梯子の丁寧な選択が試合を動かしているという証拠は無く、動かしているのは一点へ集めることである**([04-operations.md](04-operations.md))。**入れ替えなかったのは、測定中の実行が現在の梯子を相手にも基準線にも使っているからであって、証拠が足りないからではない。** **入れ替えると、記録されたすべての数字の基準線が動く。それは承知のうえで入れ替えるべき変更である。**
- **入れ替えるなら、その前後で測るべきものが二つある。** 一つは別のマップと別の長さ——測ったのは Lake の 300 秒と Hills の地平 300 秒の二つだけである。もう一つは、集中の規則そのものの粗さ——`Concentrated` は優先度が最も高い一点へ全部隊を送るだけで、守備の強さも距離も見ない。**その粗い規則が梯子を上回るということは、梯子が見ているものの多くが役に立っていないということでもある。**

- **決定の頻度は、粗い側へ一度だけ掃いて外れた。** 作戦周期はエージェントの既定で 2000 ミリ秒、地平は 300 秒なので、**1 部隊は 1 エピソードに約 150 回決定するのに独立な結果は 1 つしか無い。** 周期はランナーの引数(`tools/macos/learn-run.sh --operational`、`tools/windows/Start-RwAgents.ps1 -OperationalMs`)なので掃引で選べる量であり、**10000 ミリ秒で 100 エピソード鍛えた実行(p2)が、梯子と区別の付かないところまで落ちた。** **その測定には交絡があって単独では読めない**——1 エピソードあたりの段数が 5 分の 1 になるため更新が 68 回にしかならず、比べている p1 の 142 回の半分である。**したがって残っている問いは「粗い周期そのものが悪いのか、同じエピソード予算で回すと勾配の一歩が半分になることが悪いのか」であり、それを分けるには粗い周期で更新数を揃えた実行が要る。走らせていない。** **細かい側(1000 ミリ秒以下)は一度も試していない**([04-operations.md](04-operations.md))。

- **凍結した戦術層の下のアリーナは別の計器であり、その計器は系統的に正へ傾いている。** 取り直した自己対戦ゼロは種 80001 の四つ(97 盤面で +0.0021 ± 0.0104、49 盤面で +0.0135 ± 0.0206・+0.0107 ± 0.0134・+0.0072 ± 0.0099)、種 90001 の 52 盤面で +0.0297 ± 0.0182、種 91001 の 53 盤面で +0.0047 ± 0.0132、種 92001 の 47 盤面で +0.0026 ± 0.0119、種 93001 の 49 盤面で +0.0267 ± 0.0193 である。**したがって「この経路は関門を通る」とは言えない。八つとも正で五つの種も五つとも正、区間を外すのは 90001 と 93001 の二つであり、これは通ったり通らなかったりする計器ではなく、この過程の打つ側へ寄っていて二つの種でその寄りが区間を超えた計器である。** **原因の一つは分かっており、消してある——下に置いた網が点反射に対して不変でないことであり、そうさせていた特徴 2 つを不変な対に置き換え、さらにその基準点を各側の自陣に置いてアリーナが側ごとに渡すようにした。三つの種で取り直すと、脅威基準では -0.0020 ± 0.0100・+0.0047 ± 0.0205・+0.0200 ± 0.0158(93001 だけ通らない)、自陣基準では -0.0046 ± 0.0141・-0.0047 ± 0.0198・+0.0020 ± 0.0183 で三つとも通る。残り二つの種(91001・92001)はどちらの符号化でも未着手であり、三つの読みで五つの種の系統性を否定することはできない**([04-operations.md](04-operations.md))。 地平や半径を変えた実行も無い。
- **抽選に入れた二つの直しが数字を動かすのかどうか。** 対が自分自身と重なりうること、係争点が自陣の基地に届きうることの二つである。**基地に届く盤面の割合(約 4.8 パーセント)とそこでの上乗せ(+0.1 から +0.15)はマップと抽選の法則から見積もってあるが、直す前と後の自己対戦の平均を並べた実行は無い。**
- **「梯子を上回った +0.047 を同じ実行の 4 アームで測り直すこと」は済んだ。** 同一実行・新しい種で `script` − `learnt` = -0.0414 ± 0.0261 と再現し、**その後 -0.0637 ± 0.0351 と -0.0682 ± 0.0370、さらに -0.1111 ± 0.0318 と -0.1122 ± 0.0409 に更新された。** **同じ測り直しが「集中は学習層の 2 倍以上」を取り下げさせ、続く二本が「集中は学習層の上にいる」ごと取り下げさせ、凍結戦術層の下の二本が向きを逆にした**([04-operations.md](04-operations.md))。

## 戦略層

**一度回して、幅も測った**([05-strategy.md](05-strategy.md))。**姿勢の選択には確かな幅がある**——軍拡に固定すると梯子より 0.095 落ち、必要な試合数 22 対に対して 96 対取ってあるので分解している。**戦術層の逸脱の幅(0.013 から 0.026)の 4 倍以上である。** **一方、480 試合鍛えた層は写した規則と区別が付かない**(-0.007、必要 5,403 対)。**したがって「学ぶものが無い」ではなく「学べていない」である。**

- **なぜ学べていないのか。説明の候補は三つで、どれも掃いていない。** 一つ、独立な結果が試合 1 本につき 1 つしかないこと(割引 1 の帰結)。二つ、480 試合がその形の学習には少なすぎること。三つ、**バッチが小さすぎること**——既定の 256 段は試合 8.5 本ぶんで、試合ごとの散らばり 0.13 に対してバッチ平均の標準誤差は **0.045**、すなわち**分解したい効果(0.095)と同じ桁である。** 実測でも訓練の clipped は 0.00 から 0.03 で、**更新のたびに方策がほとんど動いていない。** **この層ではバッチを大きくするほうが良い可能性があり、それは他の二層と逆向きの結論になる**——1024 段なら試合 34 本で標準誤差は 0.022 に落ちるが、8 並列で集まるのに 4 分かかり、「1 分を大きく下回って集まる大きさ」という設計の規則から外れる([../system/04-learning.md](../system/04-learning.md))。**規則の根拠は遅れに対する安全弁がクリップであることなので、どちらが勝つかは掃くまで分からない。**
- **五つすべてを固定した幅は取った。上限が決まった。** 幅は 0.11(`expand` の -0.514 から `decide` の -0.624 まで)で、上端と下端は 18 対から 29 対で分解する。**そして上端に手書きの梯子が既にいる**——最良の固定姿勢と梯子の差は +0.018 で、区別するには 986 対が要る。**したがって学習に残っている余地はおよそ 0.02 で、戦術層の幅と同じ桁である**([05-strategy.md](05-strategy.md))。**これは 300 秒の試合の上の話であり、その長さでは軍隊が報われる時間が無い。長い試合で取り直すことが、この層について次にすべき唯一の測定である。**
- **梯子の遷移先は、この長さでは下から二番目の姿勢である。** 規則は収入が頭打ちになると軍拡へ移るが、`arm` は `script` より 0.090 低く、29 対で分解する。**梯子が上端に留まっていられるのは遷移が遅いからであって、遷移が正しいからではない。** **長い試合で順位が変わるかどうかが、この規則が正しいかどうかである。**
- **割引を 1 にするか 1 未満にするか。** 試合はこの層から見て 1 本の有限な用務なので、構築した交戦と同じ算術で 1 に置いてある。**その代償は分散**で、1 試合の全決定が 1 つの終端を分け合い、決定どうしを分けるのは批評家だけになる。**1 未満にすると整形が方策に届くようになる**(1 では整形は行動が決まる前に読まれる量なので方策勾配に寄与しない)代わりに目的が近視になる。**掃いていない。**
- **独立な観測の数が足りるのか。** 8 並列・5 分の試合・倍率 10 で毎時およそ 300 試合、すなわち**独立な終端が毎時 300 個**である。試合の採点の散らばりは 0.11 から 0.24 と測ってあるので([04-operations.md](04-operations.md))、1 時間で標準誤差は 0.006 から 0.014 になる。**学習に足りるかどうかは、測るのに足りるかどうかとは別の問いであり、どちらも実行していない。**
- **技術(TECH)を選べるようにしたことが何を変えるか。** スクリプトの規則は決して選ばず、学習層は選べる。**選ぶのが良いかどうかの測定は無い。**
- **試合の長さ。** ランナーの既定は 300 秒で、これは作戦層の試合実行に合わせた値である。姿勢の遷移規則は収入の 50 秒窓を持つので、5 分の試合では拡張から軍拡への遷移が 1 度起きるかどうかというところである。**長い試合のほうが姿勢の違いが出るはずだが、1 試合あたりの単価はそのぶん上がる。掃いていない。**
- **凍結の一巡をどう回すか。** 設計は戦術→作戦→戦略の順で、他層を凍結して交互に回すことを要求している。**戦略層を鍛えるときに下二層を学習済みのもので凍結した実行は無い**——いまの経路は下二層をスクリプトに固定する。**学習済みの下二層を差し込む配線そのものは `LearningPolicy` に無く、`rwintel.eval` のアームにしかない。**

## 戦線報告の二つの価値は、同じものを数えていない

**`FrontReport` は「自軍と敵の軍事価値」を渡すと文書化されているが、二つは同じ集合を数えていない。** 自軍側は `view.fighters`、すなわち**建物と建設機を除いた戦闘ユニットだけ**である。敵側は `view.enemies`、すなわち**その側に立っているものすべて**で、司令部も採掘施設も建設機も入る。

**これまで無害だったのは、誰もその比を読んでいなかったからである。** 手書きの戦略規則が遷移に使うのは収入・失った領域数・敵の拠点数で、軍事価値は許容総損害の尺度(自軍側だけ)にしか使われていなかった。

**いま読む者が二つできた。** 一つは戦略層の報酬のポテンシャル(軍事価値差)、もう一つは作戦の符号化の全体ブロック(`military_edge`、`allowance`、部隊の価値シェア)である。**どちらも「自軍の戦闘ユニット」対「敵の全部」を比べているので、自軍を実際より不利に読む。** 300 秒の試合で自軍の立っている価値が 9,650(建物込み)、うち戦闘ユニットは半分に満たない一方、敵側は 20,000 が丸ごと分母に入る。

**直し方は像を揃えることであり、揃え方が二通りある。** 終端(試合の採点)が数えているのは**両側の立っている価値の全部**なので、ポテンシャルを終端の進行中の形にしたいなら両側とも全部を数えるべきである。一方、許容総損害の尺度として使うなら自軍の戦闘ユニットが正しい。**したがって欄を分けるのが素直で、片方を書き換えるのは片方の読者を壊す。**

**今夜は直していない。** 直すと戦略の符号化と作戦の符号化の両方で**特徴の名前は変わらないまま意味が変わる**——刻印が捕まえられない唯一の壊れ方である([../system/04-learning.md](../system/04-learning.md))。**したがって直すときは、両層のパラメータと教師を同時に捨てて取り直す。** 走行中の測定がその古いパラメータを読んでいるあいだは動かせない。

## 全体

- **凍結して交互に学習させる一巡は、一度だけ回った。そしてその順序が効いていることは、いまや仮定ではなく測定である。** 骨格が置いた学習の順序は、戦術を先に固めてから作戦を凍結した戦術に対して学習させる、である。**回したのは一巡だけで、その一巡がこの計画で最良の作戦層を出した。同じ設定・同じ長さを手書きの戦術層の下で回すと集中アームに区間つきで負けるので、その最良を作っているのは訓練の長さではなく下に凍結した層である**([04-operations.md](04-operations.md))。**二巡目——その作戦層を凍結して戦術層を鍛え直す向き——は、経路が半分できて実行が無い。** 訓練済みの層を学習中の層の**下**に凍結して置く道は `--frozen layer:path` で通った(試合の中で作戦層や戦略層を鍛えるとき、その下に訓練済みの戦術層を置ける)。**上**に置く道も同じ仕掛けで通る——`rwintel.learn tactics` が交戦アリーナの中で回るかぎり、その場に作戦層は存在しないからである。**したがって残っているのは「戦術の学習を試合の中で行う経路」であり、それは無い。** 交戦アリーナが存在する理由そのものが「戦術は試合を回さずに学習できる」ことなので、これは配線の不足ではなく、**二巡目を回すなら戦術の学習をどの場で行うかから決め直す必要がある**という設計の問いのままである。**実行は一つも無い。**
- **網の大きさは、もう制約ではない。** 幅を絞った理由は毎秒 400 決定という要求であり、**その要求が当てていたのは GPU だった。** 実測では推論は 1 コアの数パーセントしか使わず、律速はシミュレーションである。**上げて良くなるという計測も無いので、これは「次に試すこと」ではなく「上を試すときに、幅を理由に諦めなくてよい」という但し書きである。**
