# 分かっていないことと、次に試すこと

**測ってあることは [03-tactics.md](03-tactics.md) と [04-operations.md](04-operations.md) にある。この文書は、そこから残った問いだけを書く。** 順序は好みではなく、測定から導く。

## 作業の残り

**骨格([../system/01-architecture.md](../system/01-architecture.md))が並べた七つのうち、環境まではすべて揃っている。**

| 項目 | 状態 |
| --- | --- |
| 観測と行動の外部化 | 済。形式は [../system/02-interface.md](../system/02-interface.md)、実装は `agent/` と `rwintel/wire` |
| 全層のスクリプト実装 | 済。契約と規則は [../system/03-script-policy.md](../system/03-script-policy.md)、実装は `rwintel/control/policy/`。部隊は第一級の実体になっている |
| 評価の仕組み | 済。手順は [../system/05-evaluation.md](../system/05-evaluation.md)、実装は `rwintel/eval` |
| `u=5` の同期安全性 | 済。2 プロセスの共有試合で 18 体を生成してもチェックサムは一致した |
| 介入の経路と UI | **経路は済、UI は行入力まで。** 四操作は `rwintel/control/intervention.py` に揃い、人間が打つ側は `rwintel/control/console.py` である。編成の組み替えは分割・移送・統合がすべて通っている(統合は `merge N into M`。部隊を丸ごと畳み、空になった側は解散して枠が編成層に返る)。**残っているのは窓としての UI だけである** |
| 戦術の学習 | **環境は済み、実行が残っている。** 回してはあるが、手書き層を上回った方策はまだ無い |
| 作戦の学習 | **環境は済み、実行が残っている。** 構築作戦アリーナの上では梯子を上回ったが、**凍結して交互に学習させる一巡はまだ一度も回していない** |

## 骨格の側でまだ決めていないこと

いずれも実装を止めるものではない。数値の初期値は [../system/03-script-policy.md](../system/03-script-policy.md) と [../system/04-learning.md](../system/04-learning.md) に置いてあり、計測で調整する。

- **打ち切り時の採点式の重み。** 経済差と軍事価値差と領域支配のどれをどれだけ効かせるか([../system/05-evaluation.md](../system/05-evaluation.md))。決着したエピソードが集まるまでは軍事価値差だけで採点する。
- **霧を有効にする時期。** 経路は最初から通すが、内容を切り替える判断は全知での足場ができてからになる。
- **報酬と最適化の各定数。** 網の形と算法は決まったが、報酬の重み、終端の比、アリーナの予算と戦力比は、いずれも根拠のある初期値であって計測で選ばれた値ではない。**例外はアリーナの割引と trace の 1.0 だけで、これは好みでも計測でもなく、用務の長さと決定の頻度から出る算術で決まっている。**

## 戦術層

- **手書きの層より強い方策が作れるのかどうか。** 選択に使っていない種の上では、模倣も、三つの設定も、それを二度延長したものも、歩幅を上げた鎖も、macOS で独立に学習した層も、梯子を上回っていない。**候補の点推定を 0 から外すには、いまのおよそ 4 倍の交戦が要る。** それを取るなら、候補選びにも確かめにも使っていない新しい種で取る。
- **候補が一行の規則より上かどうか。** 4 アームの実行を一度走らせて「上に見えるが交戦 500 件では言えない」まで来た。**`withdraw` 固定がどこにいるかは三つの種で割れたままである。**
- **体力の読みでの幅。** この記録の天井の数字はほとんどが疎な読みの上のものである。体力の読みで測ったのは種 20260723 の一回だけ(hold が -0.0257、withdraw が -0.0145)で、**種による散らばりがその差と同じ程度ある。**
- **直した六つのどれが効いたのか。** 割引と trace、他インスタンスの軌跡の切断、開始ポテンシャルの混入、採点の読み、建設機の紛れ込み、健全度の分母。**六つとも直したが、前後を比べた決闘が一つも無い。** 歩幅を上げた三本はそのすべてを同時に動かしている。**いま動く方策が手に入ったので、一つずつ戻して同じ種で測ることができる。**
- **抽選で打つことの税を払わずに済ませられるかどうか。** 取り得る道は三つで、**そのうち一つは走らせて閉じた。** エントロピーの重みを 0.002 から 0.0002 へ下げると、**分布はむしろ広がった**(最終エントロピーが 0.443 に対して 0.578)。残るのは、温度を入れて運用時だけ締めるか、確率最大で打つことを運用の定義そのものにするかである。**三つ目は最も安いが、探索と運用が別物になるので、次の訓練が何を最大化しているのかを言い直す必要がある。**
- **歩幅そのもの。** 3e-4 では動かず、1e-3 と 5e-4 で動いたことは測ってあるが、**三つのうちどれが良いかを比べた実行は無い。** バッチを小さくするのか、更新の回数を増やすのかも並べていない。
- **交換のポテンシャルが、アリーナでまだ要るのかどうか。** 重みを 0.5 と最も重くした根拠は「終端が交戦の序盤に届かない」という算術であり、**その算術はアリーナでは成り立たなくなった。外して比べた実行は無い。**
- **膠着が大半であることが直せるのかどうか。** 交戦の 7 割から 8 割は膠着打ち切りである。**「決着しない交戦が多いほど差が薄まる」という見立ては、少なくとも抽選を偏らせる形では当たらなかった。**
- **準備運動の回数。** 写した方策が最初の更新を生き延びるのに 5 回で足りるかは測っていない。
- **戦力の抽選の質。** 価格だけを見ており、相性も地形も見ていない。同じ予算で編成がどれだけ偏るかは測っていない。
- **死産が 0 でないこと。** 1 から 2 パーセントまで落ちたが 0 ではなく、**方策が弱いほどアリーナが劣化するという性質は変わっていない。**
- **既定と違う条件のアリーナ。** 240 秒より長いエピソードと別のマップは、引き直すようにしたアリーナでは測っていない。

**GAE の trace を 1.0 から 0.95 へ落とす道は、走らせて外れた。** 予告した機構は働いた——批評家の誤差は 0.06 から 0.012 へ落ち、勝敗は 707 対 711 まで揃った——が、**確率最大の側は h3 と区別が付かない(-0.0015 ± 0.0218)。** エントロピーの二本と合わせて徴候が同じである:**学習は分布の質量を動かし、採点される argmax を動かしていない。** **どちらの差も測定の床の内側なので、言えるのは「動かなかった」だけである。**

## 作戦層

- **なぜ学習が「一点へ集める」を見つけないのか。** 集中アームが +0.1175 を出すのに、学習した層は +0.047 で頭打ちになる。候補としては、報酬が部隊ごとで部隊間の協調に値段が付いていないこと(`--credit marginal` はむしろ逆を向く)、行動空間が一部隊ずつの選択でしかないこと、探索が足りないことがある。**どれも測っていない。**
- **どの一点を選ぶか。** `concentrate` は全部隊を最も優先度の高い係争点へ送るだけの素朴な規則である。**優先度だけでなく守備の強さや距離を見る余地があり、それは学習が手書きの規則を上回れる余地そのものである。**
- **アリーナで身に付けた技能がフル試合へ乗るか。** この場が報いているのは地面を取ることと手放さないことであって、**地面を取らなければ勝てない試合でそれが良い打ち回しである保証はまだ無い。**
- **突撃が通らないのは何のせいか。** 守備側の値段ではない——半分にしても取れる disc は 76 本中 1 本から 3 本にしか動かない。**行軍の距離も、地平の長さも、採点の仕方も、動かして測っていない。**
- **一部隊の終端の二つの読み(`region` と `marginal`)のどちらが良いか。** 既定は `region` で、これまでのすべての測定はその下で取られている。**同じ盤面の上で二つを並べた実行は無い。**
- **直した二つの信号が数字を動かすのかどうか。** 作戦ポテンシャルをシェアから支配へ書き直したことと、開始ポテンシャルを打ち消すようにしたことである。**直す前と直した後を同じ種で並べた実行は無い。** 直した根拠は伸縮の算術だけである。
- **抽選に入れた二つの直しが数字を動かすのかどうか。** 対が自分自身と重なりうること、係争点が自陣の基地に届きうることの二つである。**基地に届く盤面の割合(約 4.8 パーセント)とそこでの上乗せ(+0.1 から +0.15)はマップと抽選の法則から見積もってあるが、直す前と後の自己対戦の平均を並べた実行は無い。**
- **梯子を上回った +0.047 を、同じ実行の 4 アームで測り直すこと。** いまあるのは別々の実行を盤面ごとに突き合わせた差であり、「二つの実行はアーム以外は同じだった」という仮定が残っている。

## 全体

- **凍結して交互に学習させる一巡。** 骨格が置いた学習の順序は、戦術を先に固めてから作戦を凍結した戦術に対して学習させる、である。**片方だけを動かす仕掛けは実装にあるが、一巡は回していない。**
- **網の大きさは、もう制約ではない。** 幅を絞った理由は毎秒 400 決定という要求であり、**その要求が当てていたのは GPU だった。** 実測では推論は 1 コアの数パーセントしか使わず、律速はシミュレーションである。**上げて良くなるという計測も無いので、これは「次に試すこと」ではなく「上を試すときに、幅を理由に諦めなくてよい」という但し書きである。**
