# 分かっていないことと、次に試すこと

**測ってあることは [03-tactics.md](03-tactics.md) と [04-operations.md](04-operations.md) にある。この文書は、そこから残った問いだけを書く。** 順序は好みではなく、測定から導く。

## 骨格の側でまだ決めていないこと

いずれも実装を止めるものではない。数値の初期値は [../system/03-script-policy.md](../system/03-script-policy.md) と [../system/04-learning.md](../system/04-learning.md) に置いてあり、計測で調整する。

- **打ち切り時の採点式の重み。** 経済差と軍事価値差と領域支配のどれをどれだけ効かせるか([../system/05-evaluation.md](../system/05-evaluation.md))。決着したエピソードが集まるまでは軍事価値差だけで採点する。
- **霧を有効にする時期。** 経路は最初から通すが、内容を切り替える判断は全知での足場ができてからになる。
- **報酬と最適化の各定数。** 網の形と算法は決まったが、報酬の重み、終端の比、アリーナの予算と戦力比は、いずれも根拠のある初期値であって計測で選ばれた値ではない。**例外が二つある。** 一つはアリーナの割引と trace の 1.0 で、これは好みでも計測でもなく、用務の長さと決定の頻度から出る算術で決まっている。**もう一つはエントロピー賞与で、構築作戦アリーナでは既定の 0.002 より 0.0002 のほうが良いという測定がある**——**ただしその測定は作戦層のこの場でしか取っておらず、既定を書き換えてはいない**([04-operations.md](04-operations.md))。

## 戦術層

- **手書きの層より強い方策が作れるのかどうか。** 選択に使っていない種の上では、模倣も、三つの設定も、それを二度延長したものも、歩幅を上げた鎖も、macOS で独立に学習した層も、梯子を上回っていない。**候補の点推定を 0 から外すには、いまのおよそ 4 倍の交戦が要る。** それを取るなら、候補選びにも確かめにも使っていない新しい種で取る。**上回った方策は無いが、下回った方策は初めて区間つきで出た**——既定の自己対戦で鍛えた層が -0.0402 ± 0.0214 で、原因は訓練相手だった([03-tactics.md](03-tactics.md))。
- **梯子と同水準で止まる理由。信号の到達ではない。** 延長実行の全 478 更新・決定 748,358 段を数えると、94.6 パーセントが終端の届く用務にあり、優位ちょうど 0 は 0.081 パーセントしか無い。**残る候補は、行動空間、特徴、そして交戦アリーナが与える盤面の幅である。どれも測っていない。**
- **不変性を情報と引き換えに買ったところは、買い戻して測ってある。残っているのは決闘だけである。** 目標への方位を地図の軸から脅威の重心へ移したことで符号化は点反射に対して不変になったが、**脅威の無い部隊——係争点へ行軍している部隊がまさにそれ——は方向を一切持たなくなった。** その符号化で鍛え直した層は梯子に対して -0.0398 ± 0.0228 と 0 を外して下回り、旧符号化の同条件(-0.0042 ± 0.0224)は互角だった([03-tactics.md](03-tactics.md))。**基準はいま自陣から外へ向かう向きにあり、下がりは戻った**(`target_ahead_of_home`・`target_abeam_of_home`)。**同じ設定で鍛え直した層は +0.0036 ± 0.0226 で 0 を含む。点反射が自陣と敵陣を入れ替えるので不変性は保たれ、撃たれていない部隊も方向を持ち、前後の項は「外へ送られたのか自陣へ戻されたのか」を言う。基準点は側ごとに置かなければならず、それは視界を組む側の責務である——交戦アリーナは各側の出撃地点を、作戦アリーナは各側の staging point を入れる。両側で共有すると不変性はその場で壊れ、それを含めて四つの試験で固定してある。** **残っている測定は決闘である**——凍結した層を、候補選びに使っていない種で梯子と測った実行が無い。上の +0.0036 は動いているパラメータの上の訓練中の成績である。**そして「符号化が差を作った」ことそのものは、三本になっても区間つきでは言えていない**——脅威基準と自陣基準の差は 0.0434、その区間は約 ±0.032 で、床の ±0.02 が別に乗る。**分けるには、同じ出発点から二つの符号化で鍛えた対を、決闘の基準線を引いて測る実行が要る。**
- **候補が一行の規則より上かどうか。** 4 アームの実行を一度走らせて「上に見えるが交戦 500 件では言えない」まで来た。**`withdraw` 固定がどこにいるかは三つの種で割れたままである。**
- **訓練済みの戦術層を盤面の片側だけに置く経路が無い。** 構築作戦アリーナの `--tactics` は層を両側の下に置くので side score が両側で反対称になって層の強さが打ち消し合い、**下の層を差し替えた 3 実行はどれも 0 を含んだ。成績で戦術層を測ることが、この場では構造で閉じている**([03-tactics.md](03-tactics.md))。**片側だけに置く経路を作れば side score で測れるが、それは `script` アームのプールした平均が 0 でなければならない理由——二つの側が交換可能であること——を手放すことでもある。** **代わりに何を関門にするのかを決めないまま作ってはならない。** 決闘のように相手側を手書きに固定した基準線アームを同じ実行で取る、という道はあるが、**設計も実装も無い。**
- **体力の読みでの幅。** この記録の天井の数字はほとんどが疎な読みの上のものである。体力の読みで測ったのは種 20260723 の一回だけ(hold が -0.0257、withdraw が -0.0145)で、**種による散らばりがその差と同じ程度ある。**
- **直した六つのどれが効いたのか。** 割引と trace、他インスタンスの軌跡の切断、開始ポテンシャルの混入、採点の読み、建設機の紛れ込み、健全度の分母。**六つとも直したが、前後を比べた決闘が一つも無い。** 歩幅を上げた三本はそのすべてを同時に動かしている。**いま動く方策が手に入ったので、一つずつ戻して同じ種で測ることができる。**
- **抽選で打つことの税を払わずに済ませられるかどうか。** 八つの測定が同じ符号に並び、**そのうち一つは初めて区間が 0 を外した**(自己対戦で鍛えた層で +0.0377 ± 0.0214)。取り得る道は三つで、**そのうち一つは走らせて閉じた。** エントロピーの重みを 0.002 から 0.0002 へ下げると、**分布はむしろ広がった**(最終エントロピーが 0.443 に対して 0.578)。**同じ下げ方は作戦層のアリーナでは成績を動かしたが、そちらでもエントロピー自体は下がっていないので、この一致は「重みは分布の広さを通じて効くのではない」ことの二つ目の例である**([04-operations.md](04-operations.md))。残るのは、温度を入れて運用時だけ締めるか、確率最大で打つことを運用の定義そのものにするかである。**三つ目は最も安いが、探索と運用が別物になるので、次の訓練が何を最大化しているのかを言い直す必要がある。**
- **歩幅そのもの。** 3e-4 では動かず、1e-3 と 5e-4 で動いたことは測ってあるが、**三つのうちどれが良いかを比べた実行は無い。** バッチを小さくするのか、更新の回数を増やすのかも並べていない。
- **交換のポテンシャルがアリーナでまだ要るのかどうかは、実行ではなく算術で閉じた。** 重みを 0.5 と最も重くした根拠は「終端が交戦の序盤に届かない」という算術であり、割引 1・trace 1 のアリーナではそれが成り立たない。**そのうえ同じ 1・1 では、決定の収益は「成績 − その決定で保持していたポテンシャル」ちょうどで、そのポテンシャルは逸脱が選ばれる前に読まれる。行動に依らない量は方策勾配に寄与しないので、確保・未消費・交換の三つとも方策には届かない。** 外して比べる実行は差を測れないので、**走らせない**([../system/04-learning.md](../system/04-learning.md))。
- **膠着が大半であることが直せるのかどうか。** 交戦のおよそ 3 分の 2(21,212 件中 13,733 件、64.7 パーセント、2 標準誤差 0.7 ポイント)が膠着打ち切りである。
- **「膠着打ち切りの交戦は 0 点だから信号が無い」という見立ては取り下げた。** ちょうど 0 点は 33 件(0.24 パーセント)、両軍とも無傷は 13 件(0.09 パーセント)しかなく、疎な読みの成績の絶対値は平均 0.316 ± 0.004(2 標準誤差)である([03-tactics.md](03-tactics.md))。
- **残っている問いは薄まりの方である。** 膠着打ち切りは件数の 64.7 パーセントを占めながら、疎な読みの絶対値の合計では 41.4 パーセントしか運んでいない。**「決着しない交戦が多いほど差が薄まる」という見立ては、少なくとも抽選を偏らせる形では当たらなかった。**
- **準備運動の回数。** 写した方策が最初の更新を生き延びるのに 5 回で足りるかは測っていない。
- **戦力の抽選の質。** 価格だけを見ており、相性も地形も見ていない。同じ予算で編成がどれだけ偏るかは測っていない。
- **死産が 0 でないこと。** 記録の残っている全実行、組んだ交戦 26,420 件のうち死産は 2 件、**0.008 パーセント(95 パーセント区間 0.0009 から 0.027 パーセント)**である。**「1 から 2 パーセント」という読みは取り下げた**([03-tactics.md](03-tactics.md))。**残った 2 件はどちらもエピソードの 1 件目で、同じ地点が生成を受け付けなかったものである。**
- **方策が弱いほど盤面が混むこと自体は測れるが、それが死産に届いた記録は無い。** `withdraw` 固定のアームは、同じ抽選で対にした基準線より交戦 1 件あたり立っているユニットが 0.633 ± 0.238 多く、膠着で終わる割合が 0.138 ± 0.044 高い(400 秒 80 対。240 秒 80 対でも 0.468 ± 0.356 と 0.104 ± 0.042 で同じ側)一方、固定と貪欲の 3 アームは交戦 7,073 件で死産 0(95 パーセント上限 0.042 パーセント)である。**記録の残っている実行に乱数から始めた層のものが無いので、最も弱い方策で劣化がどこまで行くかは測り直せていない。**
- **既定と違う条件のアリーナ。** 240 秒より長いエピソードと別のマップは、引き直すようにしたアリーナでは測っていない。

**GAE の trace を 1.0 から 0.95 へ落とす道は、走らせて外れた。** 予告した機構は働いた——批評家の誤差は 0.06 から 0.012 へ落ち、勝敗は 707 対 711 まで揃った——が、**確率最大の側は h3 と区別が付かない(-0.0015 ± 0.0218)。** エントロピーの二本と合わせて徴候が同じである:**学習は分布の質量を動かし、採点される argmax を動かしていない。** **どちらの差も測定の床の内側なので、言えるのは「動かなかった」だけである。**

## 作戦層

- **決定の頻度は、粗い側へ一度だけ掃いて外れた。** 作戦周期はエージェントの既定で 2000 ミリ秒、地平は 300 秒なので、**1 部隊は 1 エピソードに約 150 回決定するのに独立な結果は 1 つしか無い。** 周期はランナーの引数(`tools/macos/learn-run.sh --operational`、`tools/windows/Start-RwAgents.ps1 -OperationalMs`)なので掃引で選べる量であり、**10000 ミリ秒で 100 エピソード鍛えた実行(p2)が、梯子と区別の付かないところまで落ちた。** **その測定には交絡があって単独では読めない**——1 エピソードあたりの段数が 5 分の 1 になるため更新が 68 回にしかならず、比べている p1 の 142 回の半分である。**したがって残っている問いは「粗い周期そのものが悪いのか、同じエピソード予算で回すと勾配の一歩が半分になることが悪いのか」であり、それを分けるには粗い周期で更新数を揃えた実行が要る。走らせていない。** **細かい側(1000 ミリ秒以下)は一度も試していない**([04-operations.md](04-operations.md))。
- **凍結した戦術層と訓練の長さは分かれた。効いたのは凍結した戦術層である。ただしこの対照は傾いていた計器の上で取ってあり、取り直していない。** 梯子と集中をどちらも上回って見えた f2 は、それ以前の最良(p3・p4)から凍結と 50 から 150 エピソードへの長さを同時に変えていた。**手書き戦術層の下で他をすべて f2 と同じにして 150 エピソード鍛えた実行(f3)が落ち、そこでは集中アームが学習層を二つの測定種で区間つきで上回る**(`concentrate` − `learnt` = +0.0587 ± 0.0443(種 80001、49 盤面)と +0.0660 ± 0.0492(種 90001、52 盤面))。**同じ手書きの層の下で 50 エピソードだった p3・p4 は +0.0157 ± 0.0480 と +0.0045 ± 0.0402 で集中と区別が付かなかったので、手書きの層の下では長さはむしろ悪くしている。長さも訓練種も揃えた一対(50 エピソード・訓練種 51001)では、凍結の下の f1 が取りに行くべき 98 本のうち 22 本、手書きの下の p3 が 11 本である**([04-operations.md](04-operations.md))。**直した計器では学習層が集中アームと区別できないので、この対照の f2 側の読みは動いている。f3 を直した計器で取り直した実行は無い。**
- **なぜ手書きの層の下では長く鍛えるほど悪くなるのかは、分かっていない。** 取りに行くべき disc は 50 エピソードの 11 本と 10 本から、150 エピソードでは 98 本中 6 本・104 本中 10 本へ落ちる。**壊れる向きは分かっている。f3 の学習アームは最接近の中央値が 654 と 667 で、50 エピソードの 441 と 418 より遠く、実行器は二つの実行のどちらでも catchment 外の警告を出している。長く鍛えるほど採点される地面から離れていく**([04-operations.md](04-operations.md))。**その実行の census は澄んでいる(517,557 段が終端の届いた用務にあり、優位ちょうど 0 は 0 段、切断は 0 本)ので、信号の届き方ではない。**無いのは機序を当てた測定である。**** **凍結した層の下では同じ長さが逆に効くので、言えるのは「長く鍛えると壊れる」ではなく「下の層が何を返すかで長さの符号が変わる」までである。**
- **種 90001 の傾きの出所は決まった。凍結した戦術層であって、その種の抽選ではない。この問いは閉じた。** 同じ種の同じ 52 盤面で、`script` アームは手書きの戦術層の下では **-0.0058 ± 0.0183 で 0 を含んで関門を通り**、凍結した戦術層の下では **+0.0297 ± 0.0182 で通らない。盤面は種だけで決まるので、違うのは下で戦った層だけである。網は点反射に対して不変ではないというコードと文書の警告が、測定で裏づけられた**([04-operations.md](04-operations.md))。
- **「傾きはどれくらいの頻度で立つのか」は答が出て、残っているのは「構造でどう消すのか」だけである。頻度ではなかった——傾きは系統的である。** 凍結戦術層の下の `script` アームは五つの種で八つあり、**八つとも正、五つの種も五つとも正、八つの平均はおよそ +0.012 で、そのうち種 90001(+0.0297 ± 0.0182)と種 93001(+0.0267 ± 0.0193)が自分の区間を外して関門に落ちる。五つの種が五つとも正になるのは公平な硬貨なら 32 分の 1 である**([04-operations.md](04-operations.md))。**原因の一つは決まり、取り除かれた。欠陥は視界ではなく符号化で、58 個の戦術特徴のうち点反射で符号が変わるのは目標への単位方向ベクトルの 2 つだけだった。まず脅威の重心から見た目標の方位に置き換え、いまは各側の自陣から外へ向かう向きを基準にしてある**([03-tactics.md](03-tactics.md))。**三つの種で取り直すと偏りは小さくなり、そのときは消えていなかった**——+0.0107 が -0.0020(種 80001)、+0.0297 が +0.0047(90001)、+0.0267 が +0.0200(93001)で、平均は約 +0.022 から約 +0.008 へ落ちたが種 93001 は区間を外したままだった。**そして基準点を脅威の重心から各側の自陣へ移し、アリーナが側ごとの基準点を渡すようにして取り直すと、三つの種はどれも関門を通った**——**-0.0046 ± 0.0141(80001)・-0.0047 ± 0.0198(90001)・+0.0020 ± 0.0183(93001)で、二つが負、平均は約 -0.002 である**([04-operations.md](04-operations.md))。**この問いは、取り直した三つの種については閉じた。** **閉じていないものを同じ強さで書く。種は三つで、読みは種ごとに一つずつしか無い。旧符号化の系統性は五つの種の八つの読みの上のもので、種 91001・92001 はどちらの新しい符号化でも取っていない。三つの読みで五つの種の系統性を否定することはできない。** **そして残りの三つはそのまま残る。** 第一、**第二の候補を潰すこと**——出撃地点の反射が合同な行軍を与えないという説明である。**脅威基準の三点で並んでいた「より近くまで届いた側が正の側」は自陣基準では再現しなかったが、それは仮説を潰したのではない。行軍の非合同は基準点とは別のものだからである。分けるには、出撃地点の対を行軍距離で釣り合わせた抽選か、この欄を持つ実行を種の数だけ取ることが要る。** 第二、**主結果そのものの測り直し**——梯子と集中を上回った四つの数字は二世代前の計器の上で取られたままで、一つも取り直していない。**自陣基準の凍結層の下で作戦層を鍛え直して同じ 3 アームを回す実行が要る。走らせていない。いまはその計器の関門が三つの種とも通っているので、走らせる条件は揃っている。** 第三、**作戦の切り出しがまだ鏡像合同でないこと**(下記)。**そのあいだ、主結果に付く限界は書いたまま残る——盤面ごとに対にすることは両アームに共通する加法的な傾きを差の中から消すが、系統的な偏りはまさに二つのアームに違う効き方をしうる種類のものなので、対にしたことをもって足りているとは言えない。**
- **作戦の切り出しは、まだ鏡像合同ではない。戦術について閉じた問いが、この場について閉じたわけではない。** 領域と部隊の行は地図そのものの番号と大域の部隊スロットで並ぶので**合同な地面が二つの側で別のオフセットに座り**、領域行の接触記録は**裏返す相手の欄が通信形式に無いので裏返せない**——裏返した視界はこちらの霧の記録を自分の接触記録として読む。**前者は行を自陣中心に並べ替えれば直り、後者は通信形式に欄を足すか、アリーナが側ごとに作り直すか、裏返した視界が記録を組み直すかのどれかが要る。三つとも実装が無い。** **手書きの作戦梯子はこれを受けないので `script` アームの関門はこの欠陥を一度も通らない。通るのは `learnt` アームだけであり、そこが測られていない**([../system/04-learning.md](../system/04-learning.md))。
- **なぜ学習が「一点へ集める」を見つけないのか。この問いは半分だけ閉じた。** 三つ直したうえで凍結した戦術層の下で鍛えると、**学習層は集中アームに並んだ**——傾いていた計器では上回って見えたが(`concentrate` − `learnt` = -0.0508 ± 0.0378 と -0.0487 ± 0.0328)、**直した計器では -0.0186 ± 0.0540 と -0.0113 ± 0.0426 で 0 を含む。** 直したのは、終端の基準点(終端が部隊の行いではなく地面の立ち方を払っていたこと)、信用の届き方(再契約のたびに優位が恒等的に 0 になり、決定の 1.2 パーセントにしか終端が届いていなかったこと。census で確定)、そしてエントロピー賞与を既定の 10 分の 1 に置いたことの三つである。**奪取数も向きを決めない。取りに行くべき disc のうち、直した計器では学習層が 98 本中 20 本と 104 本中 18 本、集中が 17 本と 23 本で、種ごとに向きが割れる**([04-operations.md](04-operations.md))。
- **エントロピー賞与が何を通じて効いたのかが分かっていない。** 0.002 から 0.0002 へ下げた二本(p3・p4)は梯子を上回って集中アームに並んだが、**測ったエントロピーは下がっていない**——p1 の平均 1.696 に対して p3 が 1.544、p4 が 1.756 で、どれも 1.5 から 1.8 の同じ帯にいる。**「分布が尖ったから決まった」は成り立たない。** **凍結戦術層の下の二本は平均 1.438(f1)と 1.291(f2)とこれまでで最も低いが、賞与以外も変えているので機序についての測定ではない。** **中間の値も 0 も試していないので、この一桁がちょうど良いのか、下げれば下げるほど良いのかは分けられていない。** **賞与を下げた設定を、周期ごとの信用割当より前の信号(o1)に載せた実行も無いので、賞与が単独で効くのか密な信用と組んで初めて効くのかも分からない。**
- **長さは一度だけ伸ばし、その寄与は分かれた。50 エピソードから 150 エピソードである。** **凍結した戦術層の下では長さが効いて集中アームを越え、手書きの層の下では逆に悪くなる**([04-operations.md](04-operations.md))。**150 より長い実行は無く、凍結の下で長さを掃いた点も 50 と 150 の二つだけである。賞与を下げた設定を別の地図や別の地平で測り直した実行も無い。** 同じアームの実行間の揺れが side score で 0.016 ほどあることは、手書き戦術層の下の七つの実行で測ってある。
- **なぜ配置を決められないのか。方策はいまも決められておらず、そしてそれは成績を損ねていない。** 学習層の用務の長さは 20.7 から 22.5 決定、すなわち 41 から 45 ゲーム秒ごとに行き先を変えるところで、梯子(138.2 から 144.6)の 6 分の 1、集中(129.9 から 133.5)の 6 分の 1 である。**周期を 10000 ミリ秒に粗くしてもこの比は変わらない**(5.8 対 27.1)ので、決められないことは周期の関数ではなく方策の性質である。**そのうえで、同じ 22 決定前後で気を変える方策が梯子も集中も区間つきで上回った。したがって「学習層が集中に届かないのは配置を決められないからだ」という読みは取り下げたままである。** **残っているのは「決められるようにしたら上がるのか」であり、それを測るには用務の長さを直接押す仕掛け(契約の最短保持や引き直しの費用)が要る。実装も測定も無い。**
- **どの一点を選ぶか。** `concentrate` は全部隊を最も優先度の高い係争点へ送るだけの素朴な規則である。**優先度だけでなく守備の強さや距離を見る余地があり、それは学習が手書きの規則を上回れる余地そのものである。学習層はいまそこに並んでいる——直した計器では点数でも奪取数でも区別が付かない。傾いていた計器で「その上に出ている」と読んでいたのは取り下げた。** **残っているのは二つで、「何を見て選んでいるのか」を言う測定が無いことと、集中アームを実際に越えられるのかどうかである。**
- **アリーナで身に付けた技能がフル試合へ乗るか。** この場が報いているのは地面を取ることと手放さないことであって、**地面を取らなければ勝てない試合でそれが良い打ち回しである保証はまだ無い。** **フル試合で並べてあるのは梯子・模倣・旧い信号の強化までで、この場の最良の層をフル試合で測り直した実行は一つも無い。**
- **突撃が通らないのは何のせいか。** **学習層が突撃しなかった理由は終端の基準点と信用の届き方とエントロピー賞与であり、三つとも動かした。取りに行くべき 98 本のうち 4 本から 11 本まで来ている。** **梯子自身が 5 本から 7 本しか取れないことは変わっていない。** 守備側の値段は原因ではない——半分にしても取れる disc は 76 本中 1 本から 4 本にしか動かない。**決定の頻度は粗い側へ一度だけ動かして外れた。行軍の距離も、地平の長さも、採点の仕方も、まだ動かして測っていない。**
- **一部隊の終端の二つの読み(`region` と `marginal`)のどちらが良いか。** 既定は `region` で、これまでのすべての測定はその下で取られている。**同じ盤面の上で二つを並べた実行は無く、`--credit marginal` の実行は一本も無い。** 定義からの算術としては、`marginal` は一つの領域に乗った部隊が credit を分け合うので**この場では集中を罰する向き**である。それは測定ではない。
- **作戦ポテンシャルの二つの書き直しが数字を動かすのかどうか。** シェアから支配へ書き直したことと、開始ポテンシャルを打ち消すようにしたことである。**直す前と直した後を同じ種で並べた実行は無い。** 直した根拠は伸縮の算術だけである。**終端の基準点・周期ごとの信用割当・エントロピー賞与の三つとは分けて読む**——そちらは同じ 49 盤面に l3 / o1 / p1 / p2 / p3 / p4 として並べてある([04-operations.md](04-operations.md))。
- **凍結した戦術層の下のアリーナは別の計器であり、その計器は系統的に正へ傾いている。** 取り直した自己対戦ゼロは種 80001 の四つ(97 盤面で +0.0021 ± 0.0104、49 盤面で +0.0135 ± 0.0206・+0.0107 ± 0.0134・+0.0072 ± 0.0099)、種 90001 の 52 盤面で +0.0297 ± 0.0182、種 91001 の 53 盤面で +0.0047 ± 0.0132、種 92001 の 47 盤面で +0.0026 ± 0.0119、種 93001 の 49 盤面で +0.0267 ± 0.0193 である。**したがって「この経路は関門を通る」とは言えない。八つとも正で五つの種も五つとも正、区間を外すのは 90001 と 93001 の二つであり、これは通ったり通らなかったりする計器ではなく、この過程の打つ側へ寄っていて二つの種でその寄りが区間を超えた計器である。** **原因の一つは分かっており、消してある——下に置いた網が点反射に対して不変でないことであり、そうさせていた特徴 2 つを不変な対に置き換え、さらにその基準点を各側の自陣に置いてアリーナが側ごとに渡すようにした。三つの種で取り直すと、脅威基準では -0.0020 ± 0.0100・+0.0047 ± 0.0205・+0.0200 ± 0.0158(93001 だけ通らない)、自陣基準では -0.0046 ± 0.0141・-0.0047 ± 0.0198・+0.0020 ± 0.0183 で三つとも通る。残り二つの種(91001・92001)はどちらの符号化でも未着手であり、三つの読みで五つの種の系統性を否定することはできない**([04-operations.md](04-operations.md))。 地平や半径を変えた実行も無い。
- **抽選に入れた二つの直しが数字を動かすのかどうか。** 対が自分自身と重なりうること、係争点が自陣の基地に届きうることの二つである。**基地に届く盤面の割合(約 4.8 パーセント)とそこでの上乗せ(+0.1 から +0.15)はマップと抽選の法則から見積もってあるが、直す前と後の自己対戦の平均を並べた実行は無い。**
- **「梯子を上回った +0.047 を同じ実行の 4 アームで測り直すこと」は済んだ。** 同一実行・新しい種で `script` − `learnt` = -0.0414 ± 0.0261 と再現し、**その後 -0.0637 ± 0.0351 と -0.0682 ± 0.0370、さらに -0.1111 ± 0.0318 と -0.1122 ± 0.0409 に更新された。** **同じ測り直しが「集中は学習層の 2 倍以上」を取り下げさせ、続く二本が「集中は学習層の上にいる」ごと取り下げさせ、凍結戦術層の下の二本が向きを逆にした**([04-operations.md](04-operations.md))。

## 全体

- **凍結して交互に学習させる一巡は、一度だけ回った。そしてその順序が効いていることは、いまや仮定ではなく測定である。** 骨格が置いた学習の順序は、戦術を先に固めてから作戦を凍結した戦術に対して学習させる、である。**回したのは一巡だけで、その一巡がこの計画で最良の作戦層を出した。同じ設定・同じ長さを手書きの戦術層の下で回すと集中アームに区間つきで負けるので、その最良を作っているのは訓練の長さではなく下に凍結した層である**([04-operations.md](04-operations.md))。**二巡目——その作戦層を凍結して戦術層を鍛え直す向き——は、経路も実行も無い。** `ops_run` と `ops_train` の `--tactics` は戦術層を作戦の場の下に置く道であって、**学習中の戦術層の上に訓練済みの作戦層を置く道はどこにも書かれていない。** **そのうえ戦術層は交戦アリーナの中で学習しており、そこには作戦層が存在しない。二巡目を回すには、戦術の学習をどの場で行うかから決め直す必要がある。**
- **網の大きさは、もう制約ではない。** 幅を絞った理由は毎秒 400 決定という要求であり、**その要求が当てていたのは GPU だった。** 実測では推論は 1 コアの数パーセントしか使わず、律速はシミュレーションである。**上げて良くなるという計測も無いので、これは「次に試すこと」ではなく「上を試すときに、幅を理由に諦めなくてよい」という但し書きである。**
