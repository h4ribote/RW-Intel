# RW-Intel

Rusted Warfare を機械学習でプレイするシステム。生産、アップグレード、攻撃目標の選定といった大局的な判断を担うモデルと、個々のユニットの戦闘機動を担うモデルを分け、両者を実時間で協調させることを目指す。

## 現状

ゲームへの接続方式を決定し、ゲーム内部の解析と性能実測を終え、モデルの設計を決め、**観測と行動の経路、五層のスクリプト方策、指揮系統の外から命令する介入の経路とスクリプト乱入者、方策どうしを比べる評価の仕組み、そして学習環境までを実装した段階**である。戦術層を鍛える交戦アリーナと、作戦層を鍛える構築作戦アリーナが、どちらも実際に走って測定を出している。

**試合を打つ鎖は、いま学習したものが手書きの鎖を上回る。** 600 秒の試合(Lake、内蔵 AI 一体、乱入あり、各アーム 256 試合)で、学習した作戦層と戦略層を載せた鎖は -0.772、手書きの鎖は -0.824 であり、差は **+0.053、要る 70 試合に対して 256 打っている。二つ目の独立した実行で +0.056 として再現した。** **三つの層すべてで、学習した層が手書きの層を上回った。** **ただし三層すべてを載せた鎖と、戦術層だけ手書きにした鎖は、区別が付かない**(+0.011、要る 1,916 試合に対して 256)——**交戦アリーナで測れる戦術層の優位は、試合の鎖の中では見えない。** **その差をどの層が作っているかも、まだ分けられていない**——戦略層の寄与は -0.010(要 4,756 試合)、作戦層は別系統の世代を 300 秒の試合で分けて測って +0.029(要 471 対)で、どちらも 0 を含む。**鎖が上回ることと、その中のどの層が上回らせているかは別の測定である。** **そして鎖は依然として組み込み AI に大きく負けている**(-0.78)。

**この場が報いる技能はフル試合へ乗る——ただし乗ったのは手書きの集中アームであって、この場の最良の学習層ではない。** 構築作戦アリーナで手書きの梯子を上回る集中アームは、**フル試合でも梯子を +0.065 上回る**(96 試合ずつ、必要 91 対で分解)。経済成分も -0.369 から -0.315 へ動く——**地面を取ることは収入の上流である。** 同じ実行で、梯子と「何も選ばない固定配備」は区別が付かない(-0.004、必要 19,441 対)。**すなわち梯子の丁寧な選択が試合を動かしている証拠は無く、動かしているのは一点へ集めることである。** 構築した場が測ったものが試合で再現したという、この計画で初めての確認である。**そして同じ条件で学習層を測ると、順位が入れ替わる。** アリーナで梯子を -0.2041、集中アームを -0.0761 上回った 600 エピソードの世代を置くと、**梯子との差は +0.040(梯子が上、要 233 対)で分解せず、自分が鍛えられた戦術層だけの鎖と比べた作戦層だけの寄与は +0.029 で 0 を含み、六つの対のうち唯一分解したのは集中アームがその学習した鎖を +0.087 で上回る対である**(要 58 対に対し 96 対)。**アリーナで報われた技能が試合で罰される徴候は二つある**——契約の達成率が 0.12 と他の三本(0.31 から 0.42)の三分の一で、経済成分が -0.407 と四本の最下位である。**気を変え続ける層は契約を捨て続け、地面を取らないので経済まで落とす。**

**その機序を二つの形で測って、二つとも落ちた。** 一つ、**この場は地平の一瞬しか払っていなかった**ので、往復し続けても代価が 0 だった——同じ disc を毎周期読んで立っていた時間で重み付けた平均を足し、両方の読みを毎エピソード書くようにしたが、**六つの対のどれも順位を変えない**(学習層は `script` に対し -0.2046 と -0.1717、`concentrate` に対し -0.0988 と -0.0709)。二つ、**この場は採点される地面を優先度で名指していた**——実際の試合では `region.priority` が 0 になる領域は 27,000 行中 0.0 パーセントなのに、この場は 9 領域のうち 5 枚を 0 にしていた。反射が対にできる全領域へ重みを配って同じ盤面で対にすると、**学習層の成績は動かない**(-0.0061 ± 0.0620)。**動いたのは集中アームだけで、しかも密な引きのほうが良い**(-0.0524 ± 0.0351)——重みの付いた領域が増えると相手側の梯子が薄く広がるからである。**どちらの直しも残した。落ちたのは説明であって、直しではない。**

**直した場で測り直すと、この記録最大の優位はほとんど残らなかった。そしてそれが非転移の説明でもある。** 四つのアームを一つの盤面に並べた(種 130001、93 盤面ずつ、`tactics-close` 凍結、関門は地平で +0.0085 ± 0.0248、保持時間で +0.0104 ± 0.0197 とどちらも通る)。**梯子に対しては三本とも分解する**——`concentrate` が -0.0683 ± 0.0344、旧い場で鍛えた 150 エピソードが -0.0528 ± 0.0379、直した場で鍛えた 150 エピソードが -0.0574 ± 0.0375。**しかし三本どうしは一つも分解しない**(`m1` − `q1` は -0.0047、要 6,579 盤面)。**旧い引きの上では 600 エピソードの世代が梯子を -0.2041 で上回っていた。桁が違う。** **説明はひとつしかない**——旧い場の優位の大半は、**その場の欠陥が手書きの梯子を不利にしていたぶん**だった。梯子の部隊は半分が garrison と記録されて地面を取れという命令を出せず、姿勢は固定され、優先度は採点される地面を名指していた。**直すと梯子は強くなり、学習層の取り分は 0.20 から 0.06 へ落ち、一点へ送るだけのアームと並ぶ。** **アリーナの優位が試合へ乗らなかったのは、乗るべき技能がそこに無かったからである。** 限界:`q1` は 150 エピソードで、旧い場の最大は 600 エピソードだった——**直した場で長さが強さを買うかはまだ測っていない。**

**残っていた説明は代金であり、そしてそれは欠陥だった。** 部隊の代金は「この部隊を抜いたら円板はどう読めたか」で計っていたが、**シェアは 1 で飽和するので、守備が倒れた瞬間、集中した部隊は全員がちょうど 0 を受け取る。** 実測で、優先度 1 の disc へ 4 部隊が集中すると garrison が生きている間は各 +0.0500(side score +0.300)、**倒した瞬間に各 +0.0000**(side score +0.500)である。**削っている間だけ払われ、倒すと払われない。** side score は体力加重なので瀕死の守備はほとんど地面を争わず、**「倒さずに削り切って立っている」ことがこの場では最適に近い。試合では守備は生きている限り撃ち返す。** 代金はいま、**この側の配備がその円板を動かした分をそこに残している値打ちで按分する**形に直してある。

**三つの層の「選択の幅」を測り、幅が足りない層には幅を作った。** 戦術の逸脱は 7 つでは全体で 0.013 から 0.026 しか動かせず、**測定の床(±0.02)と同じだった**——**8 つ目の逸脱を行動空間に足すと帯は 0.125 になった。** 作戦は 0.065 から 0.095、戦略の姿勢は 300 秒の試合で 0.11 である。**「学習時間を伸ばせば強くなる」が成り立つかどうかは、この幅と、幅の中で手書き層がどこにいるかで決まっていた**——幅そのものが測定の床と同じなら、どれだけ鍛えても示せない。

**学習させる層は指揮の階梯の三段すべてである。** 戦術層と作戦層に加えて、**戦略層(10 秒に一度の姿勢)の学習経路も通した**——30 個の集計特徴、姿勢 5 つの頭、そして**試合の採点そのものを終端に受け取る**形である。設計上、試合の結果を見る層はここだけであり、**この層には構築した場が無い**:戦略層が決めているのは試合そのものの使い方なので、経済を取り除いた場を組むとその決定が残らない。**そして三つの層は、設計が定めた順序で一巡した**——戦術層を交戦アリーナで固め、それを凍結した下で作戦層を構築作戦アリーナで鍛え、その二つを凍結した下で戦略層を試合で鍛える、という順序である。**訓練済みの層を学習中の層の下に凍結して置く配線**(`--frozen tactics:<パス>,operations:<パス>`)がそれを運ぶ。**凍結が効いていることは仮定ではなく測定である**——同じ設定・同じ長さを手書きの戦術層の下で鍛えると、作戦層は集中アームに区間つきで負ける。

**その 30 個目は、この層が払われている当の量である。** 立っているもの全部どうしの比 `standing_edge` を、軍事力どうしの比 `military_edge` の直後に足した。**試合の採点も、毎周期の密な項として払うポテンシャル整形も、どちらもこの量でできているのに、29 個のどれもそれを持っていなかった**——批評家は、自分が予測すべき戻り値を入力のどこにも見ないまま当てはめられており、軍事力どうしの比がたまたま相関する部分しか合わせようがなかった。二つは冗長ではない:採取機と工場からなる経済は立っているもの全部の比を動かして軍事力の比を動かさず、それこそ姿勢が選び分けているものである。**同じ切り出しでもう一つ、窓の最古が 0 の周期では「立ち上がり中の急伸」と「完全な頭打ち」がどちらも 0.0 に潰れていた**——経済を建てている最中の全周期で、この層は頭打ちの読みを渡されていた。窓の分母はもともと 1 で床が引いてあるので、0 の周期に別扱いを与えていたことがそのまま欠陥であり、伴走する `income_started` のほうが「0 での頭打ち」と「動かす値打ちのある頭打ち」を分ける。**そしてこの層の学習実行は、いま相手一体でなければ拒む。** 試合の採点は「最強の相手一人」と比べるが、この層のポテンシャルは front report からしか読めず、**ワイヤのユニット行は敵味方の旗を持つだけで所有者を持たない**ので、試合の中から敵を一人ずつに分けることはできない。相手が一人なら二つは同じ数で密な項は終端と同じ方向を指すが、二人以上なら密な項は敵全部の総和を指し、試合の序盤は終端が払うのと別のことを教わることになる。**評価の実行は制限しない**——そこはポテンシャルを読まない。

**戦術層。新しい梯子から鍛え直した層が、確率最大でも抽選でも梯子を上回る。** 7 逸脱では決定を丸ごと取り上げても 0.013 から 0.026 しか落ちず、**動かせる幅そのものが測定の床と同じだった。8 つ目の逸脱 `close`(自軍の射程内まで歩み寄る)を足すと帯は 0.125 に広がり、そしてその手は梯子が使う条件では害だった**——梯子からその枝だけを取り上げると梯子自身が **+0.0675 ± 0.0254** 上がるので、基準線ごと引き直した。**その新しい梯子から模倣し直して 5,120 エピソード鍛えた層は、二つの種をまとめると確率最大で +0.0274 ± 0.0177、抽選で +0.0192 ± 0.0169 で梯子を上回る**——選択に使った種では確率最大 +0.0341 ± 0.0241 と抽選 +0.0247 ± 0.0234 でどちらも 0 を外し、**確認の種では +0.0196 ± 0.0260 と +0.0131 ± 0.0245 でどちらも 0 を含む。** **符号は二つの種で揃っているが、単独で言えるのは選択に使った種の上だけである。****そこへは訓練の長さで登る**(-0.0037 → +0.0018 → +0.0341、二つの対が 0 を外す)。**そして出発点が効く**——同じ長さでも旧い梯子から始めた系統には +0.0359 ± 0.0252 で勝つ。**そしていちばん強く言えるのは定数との差のほうである**——最良の定数(常に `hold`)は二つの種とも梯子を区間つきで下回り(まとめて -0.0382 ± 0.0185)、この層はその定数を確認の種で +0.0633 ± 0.0269 上回る。 **測定の床も測ってある**——同じ重みの複製を二つのアームとして同じ実行に入れても対にした差が ±0.02 出るので、単一の実行の数字で 0.02 未満の改善を主張してはならない。**符号化が地図そのものの枠を運んでいたことも見つけて取り除いた**——58 個の戦術特徴のうち盤面の点反射で符号が変わるのは目標への方位の 2 つだけで、いまは各側の自陣から外へ向かう向きを基準に取る。**不変性は情報と引き換えである**:脅威の重心を基準にした最初の直し方では、撃たれていない部隊——係争点へ行軍している部隊がまさにそれ——が方向を持たなくなり、その層は梯子に -0.0398 ± 0.0228 と 0 を外して負けた。

**作戦層。以下の段落は、場を直す前の計器の上で取った読みである**——直した場では梯子に対する取り分が 0.20 から 0.06 へ落ち、学習層は一点へ送るだけのアームと区別が付かなくなる(上記)。**数字は取り下げていないが、どれもその計器についての言明である。**

**フル試合では選択そのものが測れないが、経済を構成で取り除いた場では分解できる。** 相手・地図・長さ・難易度を六通り変えても、梯子・模倣・強化のどれもが互いに 0.02 の内側に並んだ——選択が試合を動かす幅は点推定でおよそ 0.04 あり、経済と内蔵 AI の数が作る散らばり(0.11 から 0.24)に埋もれる。**構築作戦アリーナの上では分解できる。訓練済みの戦術層を両側の下に凍結し、その下で鍛えた層が、同じ実行に立てた手書きの梯子を -0.1732 ± 0.0282 で上回り、全部隊を一点へ送る集中アームをも -0.0686 ± 0.0321 で上回る**(種 92001、148 盤面、`script` アームは +0.0020 ± 0.0116 で関門を通る)。**いまの最大は -0.2041 ± 0.0231(梯子に対して)と -0.0761 ± 0.0277(集中アームに対して)で、領域行に「この側の部隊が何隊そこへ契約しているか」を足した切り出しの上で 600 エピソード鍛えた世代である。これがこの計画で学習方策が手書き層を上回った最大の差であり、そして上に書いたとおりフル試合には乗らない差でもある。** **集中アームを上回ることは、二つの切り出しの六世代で再現している。** **訓練の長さも強さを買う。ただし 300 から先は単独では言えない**——どちらの切り出しでも形は同じで、150 対 300 と 150 対 600 の対が 0 を外し、300 対 600 は含む。**900 まで延ばした世代は 600 と区別が付かず(-0.0080 ± 0.0235)、別系統の 150 エピソードがその 900 に並ぶ(-0.0008 ± 0.0270)ので、この場で次に効くのは長さではなく、実行が何から始まるかである。****ただしこれらの数字は、下に凍結した戦術層に依存する。** 交戦アリーナで最も強い層を下に置くと、その層はこの場では決定の 95.6 パーセントを `hold` に使い(旧い層は 80.4 パーセントを `focus` に使っていた)、**同じ作戦層の優位は -0.1840 から -0.1217 へ縮み、訓練の長さの段は分解しなくなる。** **凍結した層はこの場の設定ではなく計器そのものであり、交戦アリーナで最強の層が最良の計器とは限らない。** **そして診断の指標はどれも世代の順位を作らない。** 用務の長さも、優先度のある地面を名指した割合(63 → 13 → 86 パーセントと乱高下しながら点数は単調に上がる)も、**配分の見える切り出しを足したときに作った「同じ側の他の部隊と領域を共有していた割合」も**——手書きの梯子が既に 87 パーセントで共有しており、三世代は 69 / 88 / 72 パーセントと上下する。**三世代の順位を再現する量は、取りに行くべき disc をいくつ取ったかだけである**(80 / 102 / 111)。

**そこへ至る道は、学習信号の欠陥を一つずつ塞ぐ道だった。** 終端が部隊の行いではなく地面の立ち方を払っていたこと、再契約のたびに優位が恒等的に 0 になって決定の 1.2 パーセントにしか終端が届いていなかったこと、そして最後に、部隊ごとの代金を契約の名指す領域から読んでいたために**負けているものから立ち去ることに金を払っていた**ことである。**最後の一つを塞ぐまでは、長く鍛えるほど弱くなることが三度出ていた。** 代金はいま契約を一切読まず、採点される全円板について、この側の配備がその円板を動かした分のうちその部隊の持ち分を払う。**四つ目は、その持ち分を「この部隊を抜いたら円板はどう読めたか」で計っていたことである**——シェアは 1 で飽和するので、守備を倒した瞬間、集中した部隊は全員がちょうど 0 を受け取っていた。この場が教えるための当の用務に、何も払っていなかった。

**計器の側も同じだけ直っている。** 作戦の切り出しを鏡像合同にし(領域行は自陣から外へ向かう並び、部隊行はその側が最初に受け取った部隊番号ぶんずらす並び、接敵の記録は両側同じ規則)、下に凍結する戦術層の符号化を鏡像不変にした。**直すたびに読みは動き、そのたびに前の読みを取り下げてきた**——「集中アームも上回った」は二度反転して、いまが三度目の上回りである。**そして不変性はここでも情報と引き換えだった**:地図の番号で並んだ領域行は、一つの固定マップの上では「どの場所か」を名指ししていた。

**この場と試合の食い違いも三つ塞いだ。どれも「層が一つの行動空間で鍛えられ、別の行動空間で測られていた」形である。** 一つ、**staged 部隊の半分が garrison と記録されていた**——継いだ記録法が部隊の最初のユニットからドクトリンを引き直し、戦車は GARRISON に落ちるので、**引かれた 4 部隊のうち VANGUARD の 2 部隊がどちらも DEFEND と ESCORT しか出されていなかった。地面を取れるかを測る場で、である。** 試合では編成層が戦う編成から先に組むので、同じ装甲が ATTACK を持つ。二つ、**姿勢が `ARM` に固定されていた**ので切り出しの姿勢 5 特徴は 4 つが常に 0 で、しかも `offensive` と許容総損害を姿勢と無関係に引いていたため**試合が出せない命令の組み合わせ**になっていた。三つ、**戦略層の接敵 7 特徴が全試合の全フレームで 0 だった**——鎖がその読みを渡していなかった。手書き規則の対空応答も同じ理由で一度も発火しえなかった。

**教師の側も一つ。作戦の教師は「盤面の採点が選んだ領域」を書いていて、規則が落ち着いた先(実際に出る契約)を書いていなかった。** その覆しは手書きの梯子の用務が 127 決定続く理由そのものなので、**決定の大多数でラベルが違っていた。** 刻印にその書き換えを歩かせたので、**それ以前に集めた作戦の教師はいま拒まれる。**

**この計画では、測定そのものの欠陥が結論を繰り返し書き換えている。** アリーナが方策とは別のものを測っていたことが八つ、学習信号を黙って失っていたことが四つ見つかり、いずれも直して測り直してある。**とくに、エピソードごとに同じ交戦を引き直していたために標本の数が 30 倍から 50 倍水増しされており、それより前に「アリーナが傾いている」と読んでいた測定は一つも成立していなかった。** 経緯と数字は [docs/record/](docs/record/) にある。

**刻印そのものにも穴があり、塞いだら六つとも動いた。** 記録したものが「どのコードで作られたか」を名乗る digest は、入口の関数から名前を辿って外へ歩く。**その走査が、入れ子の code object——内包表記・generator 式・lambda・入れ子 def——の中の名前を辿っていなかった。** この計画の算術はかなりの割合がそこに住んでいる:内包表記の中からしか読まれない定数は値ごと digest に入らず、**その数字を書き換えても退役するファイルは一つも無かった**(撃たれている隊員を数える generator 式の中でしか読まれない `RECENT_HIT_MS` がまさにそれである)。**走査を再帰にすると、それだけで六つとも動く**——これまで一度も digest に入っていなかった値が入るからである。そこへ戦術と戦略の切り出しの直しと、鎖が戦術層へ全滅を渡すようになった変更が重なって、**六つの digest——三層の符号化と三層の規則——はいま、符号化が戦術 `03b6b4de8f2232f8`・戦略 `cf7701a2d9fb6001`・作戦 `2bf345d9ebb34bbb`、規則が tactics `0ca9cef9b68e7a2d`・operations `9c92b0e780638340`・strategy `79b451cf433fe00e` である。****したがって、これまでに書いた `local/*.pt` と教師データはすべて拒まれる。** 設計どおりの退役であり、旧い digest を名乗るファイルは `avow` でも救えない——人の言い分は足せるだけで、当てはめが残した記録の上書きはできない。**取り直しになる。**

**そして「名前は動かないまま中身が動いた切り出し」が、まさにこの刻印で捕まる形になった。** 戦術の露出 2 特徴——こちらが撃てる敵の数と、敵に撃たれうる自軍の数——は部隊中心からの距離で測っていた。後者は**自軍各員から自軍中心までの距離を敵の最長射程と比べており、敵が盤面のどこにいても値が動かなかった**:名前は露出を約束しながら、切り出しが既に `spread` として持っている自軍の散らばりを測っていたのであり、それで選ばれた逸脱は違う問いに答えていた。いまは両方ともユニット対ユニットで、射手ごとの射程で、しかも手書き層と同じ空地の別で判定する。**特徴数は 58 のまま、パラメータ 8,521 も同じで、名前の並びは一字も動かない**——動くのは digest だけである。いまの三層の形は、戦術 58 特徴・8,521 パラメータ、作戦 448 特徴(部隊の one-hot 8 枠を足して網の入力は 456)・130,783 パラメータ、戦略 30 特徴・6,534 パラメータ(入力 30、隠れ 64 が 2 層、出力は姿勢 5 と価値 1)である。

**学習信号の側も一連の穴を塞いだ。そしてこれらはまだ一度も測り直していない。** 試合の作戦報酬は契約が変わるたびに台帳を引き直していたので、**上がったところで引き直せば下げ幅を払わずに済む経路があった**(構築作戦アリーナの台帳は最初からそう書かれていない)。戦術層の終端は「清算待ちの決定が無い周期」に発火したとき軌跡へ届かず溶けていた——契約の地面を取って保った部隊は交戦していないので決定が無く、**完了の終端はまさにこの経路で失われていた。** 決定を待たせずに消えた部隊の軌跡と台帳は残り、同じ番号を次に受け取った部隊がそれを引き継いでいた。自己対戦では両側の層が同じ番号と同じバッファを共有するので、先に閉じた側が、まだ閉じていない相手側の生きた軌跡を切っていた。部隊番号は 8 個の枠を回るので、あるエピソードの乱入の印が、まだ濾していない前のエピソードの無傷な決定まで落としていた。**そして設計が数えている四つの終端のうち、全滅は試合で一度も発火していなかった**——編成層は最後のユニットが死んだその周期に部隊を退役させるので、戦術層は「在籍が空の部隊」を一度も見られない。いまは編成層が破壊されて退役した部隊を書き、鎖がそれを戦術層へ渡す。

**上に書いた学習側の測定は、どれもこれらの直しより前に取られている。** 試験は 255 件通る(ゲームを起動せず 10 秒ほど)が、**試験は測定ではない。**

決定した方式は、ゲーム本体のプロセスに `-javaagent` で入り込み、エンジンの内部状態を直接読んでコマンドを直接発行するというものである。ネットワークプロトコルを解析して独自クライアントを作る案は、マルチプレイが決定論的ロックステップであり状態が一切通信されないため、シミュレーションの完全な再実装を伴うことになり退けた。判断の詳細は [docs/record/01-approach.md](docs/record/01-approach.md) にある。

プロセス内から次を行えることを実行時に確認済みである。

- ユニットの識別子、座標、体力、所属、種別、およびプレイヤーの資金と戦績の読み取り
- 登録済みの全ユニット種別の一覧と、その価格・技術レベル・移動タイプの読み取り
- ユニットへの命令の発行。移動を命じて実際に移動することを確認した
- システム命令によるユニットの生成。二つのアリーナがこれに依存する
- スキルミッシュの自動開始、勝敗の検出、次のエピソードへのリセット
- 内蔵 AI 同士を戦わせ、多数のエピソードの結果を集めること
- 実時間の 10 倍速での進行。8 並列で合計 80 倍。学習の実負荷では 12 並列で毎実時間秒 309 決定(Windows)から 363 決定(macOS)まで測ってある
- 五層(戦略・作戦・戦術・内政・編成)を契約で結んだスクリプト方策の実行
- 方策を交互に走らせた比較と、必要エピソード数の算出
- 指揮系統の外から部隊を取り上げ、契約を書き換え、編成を組み替えること。人間の行入力とスクリプト乱入者が同じ経路を通り、記録先を指定すれば介入はそのとき見ていた盤面と対にして残る
- 二つのゲームプロセスを一つのロックステップ試合に入れること。その中でシステム命令により 18 体を生成しても、両者のチェックサムは一致し desync も出なかった
- **交戦アリーナ。** こちらが生成した以外に動くもののない盤面に両軍を生成し、戦わせ、掃討して次の交戦を組む。部屋の内蔵 AI は停止させ、相手側も制御プロセスだけが動かす
- **構築作戦アリーナ。** 経済を構成で取り除いた盤面に、一つの中心について点反射で対称な配置を組み、両側へ鏡像で等しい部隊と守備を配り、地平まで両側の作戦→戦術の鎖を回して、各交戦点まわりの固定半径の体力加重 catchment から領域支配を反対称に採る
- **どちらのアリーナも、両側を手書き層にした自己対戦の平均が 0 であることを関門にしている。** 交戦アリーナは既定の設定で +0.0194 ± 0.031、構築作戦アリーナは Hills で -0.0034 ± 0.0049(種 70001 の 51 盤面)であり、種 80001 の 49 盤面を回した七つの実行でも -0.0127 から -0.0034 の間に収まって毎回 0 を含む。**下で戦う戦術層を訓練済みの網に差し替えた実行は別の計器なので関門を取り直す。旧符号化で取り直した八つの読みは五つの種にまたがり、六つが通って種 90001(+0.0297 ± 0.0182)と種 93001(+0.0267 ± 0.0193)が通らない。八つとも正で五つの種も五つとも正なので、この計器は系統的に正へ傾いていた。同じ種を手書きの戦術層の下で回すと -0.0058 ± 0.0183 で通るので、傾きを作っていたのは下に置いた網である。符号化を鏡像不変に直して鍛え直した層で三つの種を取り直すと、-0.0020 ± 0.0100(80001)・+0.0047 ± 0.0205(90001)・+0.0200 ± 0.0158(93001)で偏りは小さくなり、さらに方位の基準を各側の自陣へ移した層では -0.0046 ± 0.0141・-0.0047 ± 0.0198・+0.0020 ± 0.0183 と三つとも通る。主結果を取り直した実行の `script` アームも +0.0004 ± 0.0119(80001)と -0.0025 ± 0.0108(90001)で通り、この記録で最も強い作戦層を出した実行では +0.0020 ± 0.0116(92001、148 盤面)で通っている**
- **学習した層を、同じ盤面の上で何世代でも並べること。** 「長く鍛えたほうが強いのか」は二世代の対であり、別々の実行で測るとこの場の散らばりを二度払う。**アームは読んだファイルの語幹で名乗り、正体はパラメータの digest で記録される**ので、一つのアーム名の下に二つの方策が混ざった比較は拒否される
- **訓練済みの層を、学習中の層の下に凍結して置くこと。** 設計は最初から他層の凍結を要求していたが、試合の中でそれを行う口が無かった
- **複数のアームを 1 回の実行に入れ、同じ交戦・同じ盤面の上で交互に回して対にした差を読むこと。** 抽選の散らばりが消えるので区間は半分になる。**別々の実行で取った生値を引き算する読み方は、実際に三度誤った読みを生んだ**
- **交戦アリーナで、二つのアームに文字どおり同じ交戦を引かせること。** 場所を選ぶ抽選を、交戦を引く抽選から分けた第二の乱数列に移してある。置き場所の候補は「立っているものから最も離れた地点」の中から選ぶので候補数は盤面に依存し、盤面は方策が残した生存者そのものであり、`random.choice` は候補数によって消費する乱数量が変わる。**分ける前は、同じ種の二つのアームがエピソードの途中で乱数列を分岐させ、以後は別々の交戦を引いていた。対にした引き算は、それを同じ引きとして続けていた。** 分けた後は、k 番目の交戦の引き——二つの予算、どちらが強いか、角度、二つの戦力——がどのアームでも同じである。**対にできないものは残る**:置かれる場所そのものは盤面の事実であり、盤面は方策が作ったものだから、二つのアームの間に残るのは「同じ戦力・同じ偏り・違いうる地面」であって、違う戦力ではない
- 交戦を二通りに採点し、どちらの読みでも全アームと全対差を報告すること。生き残りを値段まるごとで数える読みと、残り体力の割合で割り引いて数える読みである
- 手書き層の決定を教師として集め、網に写して、そこから強化学習を始めること

robocopy "<ゲームのインストール先>" local\rw /E /XD jvm cache /XF "hs_err_pid*.log" lastrun.log crashes.txt preferences.ini

## 動かす

制御プロセスを先に起動し、そこへゲームを接続する。エージェントは接続できるまで待つ。

```powershell
.\agent\build.ps1
python -m rwintel.control --instances 2 --episodes 2 --map Lake --max-seconds 300
.\tools\windows\Start-RwAgents.ps1 -Count 2 -Speed 10
```

macOS では、コンテナがホストを別ホストとして見るので、制御プロセスは `127.0.0.1` ではなく `0.0.0.0` で待ち受けさせる。コンテナ側は `host.docker.internal` でホストへ達する。以降の `python -m rwintel.control` と `python -m rwintel.learn` のすべての例で `--host 0.0.0.0` を足し、`Start-RwAgents.ps1` を `tools/macos/start-agents.sh` に読み替える。

```bash
agent/build.sh
python -m rwintel.control --host 0.0.0.0 --instances 2 --episodes 2 --map Lake --max-seconds 300
tools/macos/start-agents.sh -Count 2 -Speed 10
```

エピソードごとに勝敗と、決着しなかった場合の軍事価値差が報告される。詳細は [docs/system/02-interface.md](docs/system/02-interface.md) と [docs/system/06-runtime.md](docs/system/06-runtime.md) にある。

二つの方策を比べるときは評価の側を使う。方策はインスタンスの中で交互に走り、差とそれを主張するのに必要なエピソード数が出る。

```powershell
python -m rwintel.eval --instances 4 --episodes 3 --arm script --arm arm --map Lake --max-seconds 300
.\tools\windows\Start-RwAgents.ps1 -Count 4 -Speed 10
```

手順の根拠は [docs/system/05-evaluation.md](docs/system/05-evaluation.md) にある。

試合の最中に人間が指揮を引き取るには、介入コンソールを開く。打った操作は指揮系統が出すのと同一形式の契約になり、`--interventions` を付けるとそのときの盤面と対にして書き出される。`--intrude` はスクリプト乱入者を入れる指定で、設計の頻度で干渉する相手を入れたまま計測するためのものである。

```powershell
python -m rwintel.control --instances 1 --map Lake --max-seconds 900 --console --interventions local\interventions.jsonl
python -m rwintel.control --instances 4 --episodes 4 --map Lake --max-seconds 300 --intrude
```

二つのゲームプロセスを一つのロックステップ試合に入れるには `--paired` を使う。どちらがホストでどちらが参加するかは制御プロセスが決める。`--spawn-probe` は試合中に生成を投入する回数で、エピソードの終わりにチェックサムの照合回数と一致の有無が報告される。

```powershell
python -m rwintel.control --instances 2 --paired --opponents 0 --map Lake --max-seconds 180 --spawn-probe 6
.\tools\windows\Start-RwPairedMatch.ps1 -Speed 10
```

学習の実行である。`python -m rwintel.learn` は最初の語で実行の種類を選び、`tactics` `operations` `strategy` `collect` `clone` `choices` `duel` `avow` の八つがある。**三層すべてが学習できる。** 戦術層は試合を回さず交戦アリーナの中で学習させ、作戦層と戦略層は通常のスキルミッシュで乱入者を入れて回す。`collect` は決定器を渡さずに走らせて、スクリプトの決定を教師データとして書き出す。**`choices` と `clone` と `avow` はゲームに触れない。** `choices` は、書き出された盤面の上で複数のパラメータに確率最大で答えさせ、どの行動をどれだけ選ぶかを教師の分布と並べて出す——**成績は「実行が動いたか」を言い、これは「方策が動いたか」を言う。二つは別の問いである。** `avow` は、名乗るべきものを名乗っていないパラメータの一式に、どの符号化に当てたものかという人間の言い分を理由の文ごと書き込む——刻印の無い古いファイルを使う唯一の道であり、以後どの読み込み口も「これは当てはめの記録ではなく人の言葉である」と毎回言う。**足せるだけで、上書きはできない**(だから旧い digest を名乗るファイルはこれでも救えない)。**そして `strategy` の学習実行だけは、相手が一体でなければ拒む**——理由は上に書いた。設計の順序どおり、その下には訓練済みの戦術層と作戦層を `--frozen` で凍結して置く。

```powershell
python -m rwintel.learn tactics --instances 4 --save local\tactics.pt
python -m rwintel.learn operations --instances 4 --episodes 6 --map Lake --max-seconds 300 --intruder --save local\operations.pt
python -m rwintel.learn strategy --instances 8 --episodes 6 --map Lake --max-seconds 300 --intruder --frozen tactics:local\tactics.pt,operations:local\operations.pt --save local\strategy.pt
python -m rwintel.learn collect --layer tactics --instances 4 --record local\teacher.jsonl
.\tools\windows\Start-RwAgents.ps1 -Count 4 -Speed 10
```

macOS では、ホストの学習コマンドとコンテナのゲームを同時に生かして寿命を結ぶ `tools/macos/learn-run.sh` を使う。`--` の後にホストのコマンドをそのまま与えると、それを起動し、コンテナをその相手として立ち上げ、エピソードが終われば取り残さずコンテナを止める。

```bash
tools/macos/learn-run.sh --count 4 --speed 10 -- \
    python -m rwintel.learn tactics --host 0.0.0.0 --instances 4 --save local/tactics.pt
```

**アリーナの実行に `--max-seconds` を渡す必要はない。** 省略時の既定はアリーナの 240 秒(`operations` と `strategy` は 300 秒)であり、**これを伸ばすのは throughput のつまみではなく測定を壊す操作である**。交戦は片付けられないので、1 本のエピソードの中の交戦は生き残りが溜まっていく同じ盤面を共有し、**件数のわりに標本が痩せる**。交戦を増やしたいなら `--episodes` を増やす。

`clone` は書き出した教師データに網を当てはめて、乱数ではなくスクリプトの真似から強化学習を始められるようにする。**ゲームに触れない三つのうちの一つ**なので、制御プロセスもゲームも起動しない。写した重みから学習を始めるときは `--warmup` を付けて、乱数のままの価値ヘッドを先に合わせ、模倣の狭さを溶かさないよう `--entropy` を小さいまま使う(既定がその値である)。

```powershell
python -m rwintel.learn clone --layer tactics --teacher local\teacher.jsonl --save local\tactics-bc.pt
python -m rwintel.learn tactics --instances 8 --load local\tactics-bc.pt --warmup 5 --save local\tactics.pt
python -m rwintel.learn choices --layer tactics --teacher local\teacher.jsonl --load local\tactics-bc.pt,local\tactics.pt
```

`duel` は学習せずに測る実行で、こちら側に読み込んだ網、相手側にスクリプト戦術層を置いて交戦の成績を取る。**`--load` を渡した決闘は、両側スクリプトの基準線アームを既定で同時に取る。** 二つのアームは同じ交戦を戦うので、報告は交戦ごとに対にした差も出す。**成績は反対称なので基準線の平均は 0 でなければならず、0 から離れていればアリーナがその乱数種で盤面の片側に有利ということになる。** アリーナがどちらへ傾くかは種の性質なので、**同じ種の基準線を引かずに方策の生値を読んではならない。**

```powershell
python -m rwintel.learn duel --load local\tactics.pt --instances 8 --episodes 4
python -m rwintel.learn duel --instances 8 --episodes 4
.\tools\windows\Start-RwAgents.ps1 -Count 8 -Speed 10
```

**構築作戦アリーナの実行は、`rwintel.learn` のサブコマンドではなく独立した三つのモジュールである。** 場を測る `ops_run`、その上で作戦層を学習させる `ops_train`、書かれた journal を盤面ごとに突き合わせる `ops_compare` である。**前の二つは他の実行と同じく先に起動してからゲームを繋ぎ、三つ目はゲームを起動しない。** `ops_run --our` は繰り返せる指定で、渡した数だけアームが立ち、**盤面は全アームが打ち終わるまで進まないので、1 回の実行がそのまま対にした比較になる。**

`ops_run` と `ops_train` の `--tactics` は、訓練済みの戦術層を**盤面の両側の下に凍結して置く**指定である。層は確率最大の行動で読まれ、rollout を渡さないので何も記録しない。**これがアーキテクチャの学習順序の後半、すなわち戦術層を先に定めて凍結し、作戦層だけを動かす一巡であり、この場の最良の作戦層はその下で鍛えたものである。その順序が効いていることは、同じ設定を同じ長さだけ手書きの戦術層の下で鍛えた対照で確かめてある。** 渡さなければ両側とも手書きの戦術層で、何も変わらない。**渡した実行は別の計器であり、episode 記録に置いた層の名前(パラメータ本体の SHA-256)が入るので、`ops_compare` は異なる戦術層どうしを対にしない。両側なのは、片側だけを訓練済みにすると二つの側が交換可能でなくなり、`script` アームの平均が 0 でなければならない理由そのものが消えるからである。その代わり、この経路で戦術層どうしを成績で比べることはできない。**

```powershell
python -m rwintel.learn.ops_run --instances 8 --episodes 10 --map Hills --our script --our pin --our concentrate
python -m rwintel.learn.ops_train --instances 8 --episodes 40 --map Hills --load local\operations-bc.pt --warmup 5 --save local\ops-arena.pt
python -m rwintel.learn.ops_train --instances 8 --episodes 40 --map Hills --tactics local\tactics.pt --load local\operations-bc.pt --warmup 5 --save local\ops-under-tactics.pt
python -m rwintel.learn.ops_compare local\ops-eval-learnt.jsonl local\ops-eval-pin.jsonl
```

主な引数である。数値を省略した場合は [docs/system/04-learning.md](docs/system/04-learning.md) の定数表の値がそのまま使われ、模倣の実行についてはそれが最初の行に出る。

| 引数 | 実行 | 意味 |
| --- | --- | --- |
| `--instances` / `--episodes` | `tactics` `operations` `strategy` `collect` `duel` | 接続するゲームの数と、1 インスタンスあたりのエピソード数。**`clone` `choices` `avow` はゲームに触れないので取らない** |
| `--opponents` | ゲームを起動する実行 | 部屋に置く内蔵 AI の数。既定は 1。**`strategy` の学習実行は 1 以外を拒む**——試合の採点は最強の相手一人と比べるのに、この層のポテンシャルは front report からしか読めず、ワイヤのユニット行は敵味方の旗を持つだけで所有者を持たないので、相手が二人以上いると密な項と終端が別の量になる。**評価の実行(`rwintel.eval`)は制限しない**——そこはポテンシャルを読まない |
| `--load` | `tactics` `operations` `strategy` `clone` `choices` `duel` `avow` | 開始時に読むパラメータ。**`duel` と `choices` は読み先が無ければ異常終了する**。学習の実行は新しい方策から始める。**`duel` `choices` `avow` はコンマで並べれば複数を一度に扱う。** どの読み込み口も、名乗る特徴の並びと、その並びを埋めたコードの digest が今のものでないファイルを拒む——**六つの digest がすべて動いたので、これまでに書いたパラメータと教師はすべてここで拒まれる**(上の刻印の段) |
| `--save` | `tactics` `operations` `strategy` `clone` | 終了時に書くパラメータ |
| `--frozen` | `operations` `strategy` | 訓練済みの層を、学習中の層の**下に凍結して置く**。`tactics:local\tactics.pt,operations:local\operations.pt` のように層と道を書き、コンマで並べる。確率最大で読まれ、rollout を渡さないので何も記録しない。**幅はファイルから読む**ので、既定以外の幅で鍛えた網も載る。**渡した実行は別の計器であり、名乗るのは道ではなくパラメータ本体の SHA-256 である**——道は次の学習実行が上書きする綽名にすぎない。学習中の層自身を凍結する指定と、同じ層を二度書く指定は拒む |
| `--warmup` | `tactics` `operations` `strategy` `ops_train` | 最初の何回の更新で価値ヘッドだけを合わせるか(その間は幹も方策も止める)。**言えばその通りに従う(0 を含む)。言わなければ、`--load` があるときだけ短く温め、新しい方策から始めるときは温めない**——写した重みには批評家が付いてこないので、乱数のままの批評家に対して方策勾配を取ると、何も言わないまま実行を失う |
| `--layer` | `collect` `clone` `choices` `avow` | どの層を記録するか、写すか、読むか、言い分を書き込むか。**`avow` だけは既定を持たず、言わなければ拒む**——既定があれば、黙っているだけで違う層の特徴の並びが書き込まれうる |
| `--because` | `avow` | それだと信じる理由。**必須である。** その一文が、書き込まれた言い分を信じてよい唯一の証拠だからである |
| `--teacher` | `clone` `choices` | 教師データ。`choices` はそこに書かれた盤面を、方策どうしを比べる共通の物差しとして使う |
| `--smoothing` / `--epochs` / `--patience` / `--keep-tainted` | `clone` | 教師データの当てはめ方 |
| `--script` / `--script-opponent` | `tactics` | アリーナの両側をスクリプトにする / 相手だけをスクリプトに固定する |
| `--greedy` | `duel` | 方策 1 本につき「確率最大の行動で打つアーム」を**足す**。抽選のアームは運用時と同じものなので消えない。二つは同じ交戦を戦うので、抽選が課している税だけを切り出せる |
| `--intruder` | `operations` `strategy` | スクリプト乱入者を注入する。設計が学習と評価の両方で要求している |
| `--record` / `--record-episodes` | `tactics` `operations` `strategy` `collect` `duel` | エピソード記録の書き出し先。`collect` だけは `--record` が決定列を指し、エピソード記録は `--record-episodes` に出る |
| `--device` | `collect` `avow` 以外 | torch のデバイス。既定は CPU で、この大きさの網ではカードより 3 倍から 7 倍速い |
| `--width` | `tactics` `strategy` `clone` `choices` `duel` | 戦術網および戦略網の 1 層あたりの隠れユニット数。**既定以外の幅で鍛えた網も、そのまま `--frozen` にも `rwintel.eval` のアームにも `ops_run` / `ops_train` の `--tactics` にも載る**——三層とも最初が特徴から幅への線形写像なので、ファイル自身が自分の幅を名乗る |
| `--pin` | `duel` | 逸脱を一つに固定したアームを足す。コンマで並べれば並べただけ立つ。**帯——決定が動かせる幅——はこれでしか読めない** |
| `--without` | `duel` | 手書きの梯子からその枝を取り上げたアームを足す。**固定とは別の問いで、「その逸脱を定数として使うといくらか」ではなく「梯子の中でその逸脱がいくらか」を訊く。** 受け付けるのは**梯子が実際に枝で答えうる六つ**(`withdraw` `withdraw_far` `spread` `kite` `focus` `focus_threat`)だけで、残る二つは拒む——`hold` は梯子の落ち先であって枝ではなく、`close` は測って梯子から取り除かれ行動空間にだけ残っている手なので、どちらを取り上げても決定は一つも変わらず、**基準線を基準線と比べた 0 を「その逸脱の寄与」として報告することになる。** どちらも `--pin` では測れる |
| `--separation` / `--stall-seconds` / `--imbalance-floor` | アリーナを使う実行 | 交戦の抽選の三つの設定。**コンマで並べればアームとして走り、それぞれが自分の基準線を持つ。** 学習の実行は最初の一つだけを使う——アームごとに違えば、一つの方策を二つのアリーナで訓練して一つの数字を報告することになる |
| `--entropy` / `--learning-rate` | `tactics` `operations` `strategy` `ops_train` | 方策をどれだけ一様さへ押すか、と最適化器の学習率。**構築作戦アリーナの層はどれも `--entropy 0.0002`、すなわち既定の 10 分の 1 で、凍結した戦術層の下で鍛えてある。訓練の長さは 150・300・600 エピソードで単調に効く** |
| `--outcome-weight` | `tactics` | アリーナで交戦の成績を終端としてどれだけの重みで払うか |
| `--score` | アリーナを使う実行 | 交戦の成績のどちらの読みを終端として払うか(`health` / `kills`)。既定は `health`。**決めるのは払う側だけで、報告はどちらの設定でも両方の読みで出る** |
| `--discount` / `--trace` | `tactics` `strategy` | 1 決定あたりどれだけ先を割り引くか、と GAE がどれだけバイアスと分散を交換するか。**どちらの層も既定は 1.0 と 1.0** である——交戦 1 件も試合 1 本も、終端のある有界な用務 1 件なので割り引かない。`operations` は 0.99 と 0.95 に固定である。**この 1 つの数が収益の割引とポテンシャルの伸縮の両方に入る**ので、二つが離れることはない |
| `--batch` | `tactics` `operations` `strategy` `clone` | 1 回の勾配の一歩に載せる行数。**既定は `tactics` と `operations` が 1,024、`strategy` は 256** である——戦略層は 1 側 10 ゲーム秒に 1 決定しか出さず、8 インスタンス・5 分の試合・10 倍速で毎実時間分およそ 240 決定にしかならないので、1,024 では 1 バッチが 4 分かかり、1 時間の実行が 15 歩で終わる |
| `--tactics` | `ops_run` `ops_train` | 訓練済み戦術層を盤面の**両側の下**に凍結して置く。**渡した実行は別の計器であり、journal がその層を名乗る** |
| `--opening` | `ops_train` | 終端をどこから読むか。**`region` の読みだけがこれを見る。** 1(既定)が送られた disc の開始所有、0 が中立の半分。**`marginal` と `board` は自分の起点——この側の staged 部隊を一つも入れずに読んだ円板——を持つので、この引数から何も取らない** |
| `--credit` | `ops_train` | 一部隊の終端の読み。**`board`(既定)は契約を一切読まず、採点される全円板について、この側の配備がその円板を動かした分のうちその部隊の持ち分を払う。** 残る二つは契約の名指した領域を読む——`region` はその領域の支配まるごと、`marginal` はその持ち分だけである。**契約を読む二つは、負けている地面から立ち去ることに金を払う**([docs/record/04-operations.md](docs/record/04-operations.md)) |
| `--tenure` | `ops_train` | 地面を**いつ**読むか。`horizon`(既定)は地平の一枚だけを読むので、**最後にどこに立っているかが目的のすべてになり、係争点の間を往復し続けても代価は 0 である。** `tenure` は毎周期の読みを立っていた時間で重み付けた平均を払う——**試合における地面は収入の上流なので、早く取ることは遅く取ることより価値があり、気を変えることは行軍のぶんだけ高くつく。** 尺度も反対称性も同じで、**どちらを払う実行でも両方の読みが journal に書かれる** |
| `--reading` | `ops_compare` | 対の差をどちらの読みで取るか(`side_score` / `side_tenure`)。`ops_run` は両方を自分で報告する |

torch を要求するのは学習側だけであり、スクリプト方策だけを走らせる実行はその費用を払わない。環境の設計と定数は [docs/system/04-learning.md](docs/system/04-learning.md)、これまでに取った測定は [docs/record/03-tactics.md](docs/record/03-tactics.md) と [docs/record/04-operations.md](docs/record/04-operations.md) にある。**手書きの戦術層は上回ってある**——8 つ目の逸脱を外した梯子から模倣し直して 5,120 エピソード鍛えた層が、二つの種をまとめて確率最大で +0.0274 ± 0.0177、抽選で +0.0192 ± 0.0169 である。**それでも主張する価値のある改善は数百分の数であり、それを見るには片側で数千交戦が要る。****そのうえ、同じ重みを二度測っても ±0.02 出る**([測定の床](docs/record/03-tactics.md))。**そしてその重みは、いまどの読み込み口でも拒まれる**——刻印が動いたので、上の数字を出した層も、それが鍛えられた教師も、すべて取り直しである(上の刻印の段)。数字は取り下げていないが、どれもその計器とその層についての言明である。
